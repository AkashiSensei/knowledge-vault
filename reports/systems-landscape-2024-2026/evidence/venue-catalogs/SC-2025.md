## 热门问题与方法

- 数值算法/算子/图计算是最大方向（27 篇），AI/ML 系统与算法、编程编译软件栈、可靠性性能运维均达 20 篇；稀疏/矩阵/张量核心 kernel 仍是 SC 的主轴。
- 热门问题包括大模型训练和 serving 的并行与内存瓶颈、GPU/异构加速器的算子映射、通信避免与 collective、有损压缩、故障发现与生产性能诊断。
- 常见方法是软硬件协同设计、分层分区/调度、通信与计算重叠、根据输入结构自适应选策略，以及基于 trace/遥测的经验模型。

## 论文条目

- [PerfDojo: Automated ML Library Generation for Heterogeneous Architectures](https://dl.acm.org/doi/10.1145/3712285.3759900)
  - ETH Zürich；Andrei Ivanov、Siyuan Shen、Gioele Gottardo、Marcin Chrapek、Afif Boudaoud、Timo Schneider、Luca Benini、Torsten Hoefler
  - 该工作面向 x86、Arm、RISC-V 和 GPU 之间机器学习 kernel 难以便携调优的问题。PerfLLM 把候选代码变换放进 PerfDojo，用人可读、数学化且语义可校验的表示把优化建模为 RL 游戏，再由 LLM/RL 搜索不同指令集、稀疏性与量化条件下的实现。摘要报告其在多类 CPU/GPU 架构上均能取得显著性能收益，但未给出统一数值。
  - 传统自动调优往往依赖架构专用启发式或难解释的中间表示；PerfDojo 用可验语义变换空间同时服务人类分析与 RL 训练，使搜索不必先编码目标硬件知识。
  - 编程、编译与系统软件、LLM for Systems、编译/自动调优、Auto-Tuning, Compilation, and Code Generation、HPC 系统、官方摘要预读

- [Automatic Generation of Mappings for Distributed Fourier Operations](https://dl.acm.org/doi/10.1145/3712285.3759869)
  - Lawrence Livermore National Laboratory (LLNL)、Ohio State University；Doru Thom Popovici、Botao Wu、John Shalf、Martin Kong
  - 傅里叶变换是一种在多种科学应用中普遍使用的数学运算；在这项工作中，作者引入了一种新的自动方法来生成多维傅里叶运算的分布式映射，为该问题提供了解决方案；该工作的方法决定如何将计算分解、映射和调度为更小、更低维的并行操作；作者设计并实现了一种新颖的非线性迭代公式，可以优化傅里叶和线性代数运算；该工作的方案利用 Z3 SMT 求解器来最大限度地减少关键 MPI 集合之间的通信步骤数，同时选择网格形状；评估了新方案的有效性，并证明其速度比耦合的 heFFTe 和 COSMA 解决方案提高了 2 倍至 31 倍。
  - 既有分布式 FFT 库的映射较僵化；该方法联合决定分解、映射与调度，用非线性迭代式跨 FFT/线性代数优化，并由 Z3 同时选进程网格、最小化 MPI collective 步数。
  - 编程、编译与系统软件、分布式/并行执行、映射与数据布局、FFT/傅里叶运算、编译/自动调优、Auto-Tuning, Compilation, and Code Generation

- [A Sample-Free Compilation Framework for Efficient Dynamic Tensor Computation](https://dl.acm.org/doi/10.1145/3712285.3759779)
  - Tencent、Shanghai Jiao Tong University、RIKEN Center for Computational Science (R-CCS)、Shenzhen Institute of Advanced Technology, Chinese Academy of Sciences、Taichi Graphics、National University of Singapore；Yangjie Zhou、Honglin Zhu、Qian Qiu、Weihao Cui、Zihan Liu、Peng Chen、Mohamed Wahib、Cong Guo、Siyuan Feng、Jintao Meng、Haidong Lan、Jingwen Leng、Yun Lin、Jin Song Dong、Wenxi Zhu、Minwen Deng
  - 由于输入维度可变，动态形状张量计算对特定形状的编译提出了挑战；作者提出了 Helix，这是一种动态张量框架，具有无样本和架构引导的编译功能，可提高编译效率和形状通用性能；为了避免形状采样，Helix 通过跨架构层分解计算来构建与形状无关的编译；双向策略结合了自上而下的抽象、将张量计算与体系结构层次结构对齐以及自下而上的内核构建，从可重用的、与体系结构一致的微内核构建高效的执行策略；混合分析器通过在较低架构级别进行分析来确保准确性，并通过在较高级别和运行时进行基于架构的建模来实现可扩展性；这种分层设计消除了特定于形状的调整，并实现了形状自适应执行；对 x86 CPU、ARM CPU 和 NVIDIA GPU 的评估表明，与现有编译器相比，Helix 将编译时间缩短了 174 倍，并分别比供应商库和动态形状编译器提供了 2.26 倍和 3.29 倍的加速。
  - 既有动态形状编译依赖样本、遇到未见形状会退化；Helix 以架构层次分解实现无样本编译，再结合自顶向下张量映射、自底向上微内核和混合分析器做形状自适应执行。
  - 编程、编译与系统软件、矩阵/张量算子、编译/自动调优、Auto-Tuning, Compilation, and Code Generation、HPC 系统、官方摘要预读

- [Constraint-Driven Auto-Tuning of GEMM-Like Operators for MT-3000 Many-Core Processors](https://dl.acm.org/doi/10.1145/3712285.3759898)
  - National University of Defense Technology (NUDT)、ShaanXi Normal University；Xinxin Qi、Jianbin Fang、Peng Zhang、Yonggang Che、Jie Ren
  - DynaChain 面向 MT-3000 异构众核处理器上的深度学习 GEMM-like 算子：它先解耦计算与数据搬运，用约束依赖链在搜索中及时剔除不可行调度，再用 ILP 分解不规则矩阵尺寸以避免 padding，最后生成适配 VLIW+SIMD 的寄存器分配与指令流水微内核。在代表性算子上，自动生成代码可达到与专家调优库相当的性能。
  - 核心创新是把可行性约束的依赖传播直接放进 schedule 搜索，并把不规则形状分解与 MT-3000 微内核生成统一优化；这比穷举大量无效配置或靠 padding 迁就规则尺寸更能保留硬件利用率。
  - 编程、编译与系统软件、矩阵/张量算子、编译/自动调优、GEMM、MT-3000、Auto-Tuning, Compilation, and Code Generation

- [Plexus: Taming Billion-Edge Graphs with 3D Parallel Full-Graph GNN Training](https://dl.acm.org/doi/10.1145/3712285.3759890)
  - University of Maryland；Aditya K. Ranjan、Siddharth Singh、Cunyang Wei、Abhinav Bhatele
  - Plexus 针对超出单 GPU 内存的十亿边图做无采样的全图 GNN 训练。它将 GPU 排成三维虚拟网格，在不同平面分片邻接矩阵、特征与权重，用各维 all-gather/all-reduce 完成 SpMM 和 GEMM；双重置换平衡稀疏非零元，性能模型则直接选择三维网格形状。它扩展到 Perlmutter 的 2,048 张 GPU 和 Frontier 的 1,024 张 GPU，较既有方法加速 2.3–12.5 倍。
  - Plexus 首次把三维并行矩阵乘系统地改造为稀疏与稠密计算混合的端到端 GNN 训练，并对所有矩阵都做分布而不靠边界采样或陈旧特征换取可扩展性；这是其能扩展到数千 GPU 的关键。
  - AI/ML 系统与算法、分布式训练、图计算/GNN、网络/集合通信、分布式/并行执行、GNN

- [PGT-I: Scaling Spatiotemporal GNNs with Memory-Efficient Distributed Training](https://dl.acm.org/doi/10.1145/3712285.3759880)
  - University of Wisconsin-Madison、Argonne National Laboratory (ANL)、Arizona State University、Sandia National Laboratories；Seth Ockerman、Amal Gueroudji、Tanwi Mallick、Yixuan He、Line Pouchard、Robert Ross、Shivaram Venkataraman
  - PGT-I 面向大规模时空 GNN：索引批处理不再预先物化大量高度重叠的时间快照，而是保留底层时空数据并在运行时按索引组装训练样本；分布式索引批处理再将样本分给 DDP 工作者，各自在本地构造快照、只对梯度做 all-reduce。它无需分割图即可训练完整 PeMS，峰值内存最多降低 89%，128 GPU 上较标准 DDP 加速 11.78 倍。
  - 该工作把时空窗口的重叠性变成了可复用的索引表示，并让这一表示贯穿预处理和多 GPU 训练；相较复制快照或先分区再训练，它同时去掉数据膨胀和周期性 CPU–GPU/工作者间搬运。
  - AI/ML 系统与算法、分布式训练、图计算/GNN、网络/集合通信、分布式/并行执行、内存层次/Cache

- [TaGNN: An Efficient Topology-Aware Accelerator for High-Performance Dynamic Graph Neural Networks](https://dl.acm.org/doi/10.1145/3712285.3759818)
  - Huazhong University of Science and Technology、School of Computer Science and Technology, Huazhong University of Science and Technology、University of Warwick；Hui Yu、Yu Zhang、Ligang He、Bing Peng、Jin Zhao、Zixiao Wang、Hao Qi、Hai Jin
  - TaGNN 是针对动态 GNN 多时间快照推理的 FPGA 加速器。它从图更新找到受影响顶点及其邻域，让多个快照并发计算这些子图，而未受影响顶点在每层只读取和计算一次；O-CSR 按时间与拓扑重叠压缩数据，相似度感知的 cell skipping 还会在连续快照特征足够接近时复用上一次 RNN 结果。在 Alveo U280 上，它较三种专用 DGNN 加速器平均加速 6.5–13.5 倍。
  - 核心创新是不再逐快照重做整图，而是在硬件中把“拓扑变化部分”与“时间上不变部分”分开，同时结合无损的不变顶点复用和可控精度损失的 RNN 跳过，从而真正打开多快照并行性。
  - AI/ML 系统与算法、分布式训练、GPU/异构加速、图计算/GNN、网络/集合通信、性能建模与评测

- [Moment: Co-Optimizing Physical Communication Topology and Data Placement for Multi-GPU Out-of-Core GNN Training](https://sc25.conference-program.com/?post_type=page&p=14&id=pap212&sess=sess282)
  - Zhejiang University；Zuocheng Shi、Jie Sun、Ziyu Song、Mo Sun、Yang Xiao、Fei Wu、Zeke Wang
  - Moment 面向单机多 GPU、多 NVMe SSD 上的 TB 级图 mini-batch GNN 训练。它离线读取 CPU、GPU、SSD 及 PCIe/QPI/NVLink 的实际连接与带宽，去除对称的硬件布局后将数据通路建模为容量受限最大流，再用数据分布感知背包算法把顶点 embedding 分配到 GPU/CPU 内存和 SSD；运行时由每张 GPU 直接发起磁盘 I/O，流水执行采样、特征提取和训练。其性能较核外系统最多提高 6.51 倍、较四机分布式基线提高 3.02 倍，成本约为后者一半。
  - Moment 的新意是把通常被当作固定条件的硬件物理放置，与图数据在多级存储中的放置一起求解；最大流显式刻画共享链路争用，背包模型再吸收图访问偏斜，避免了“先定机器、再单独摆数据”的局部优化。
  - AI/ML 系统与算法、分布式训练、GPU/异构加速、图计算/GNN、网络/集合通信、映射与数据布局

- [mLR: Scalable Laminography Reconstruction Based on Memoization](https://dl.acm.org/doi/10.1145/3712285.3759805)
  - University of California, Merced、Argonne National Laboratory (ANL)；Bin Ma、Victor Nikitin、Xi Wang、Tekin Bicer、Dong Li
  - mLR 用于加速层析成像的 ADMM-FFT 迭代重建：它利用相邻迭代中同一图像 chunk 的 FFT 输入/结果高度相似，先用代数等价的 FFT 消除与融合把三步变换缩为两步，再以每个 chunk 一项的私有 memoization cache 命中近期结果，只在 miss 时批量查询远程记忆库。变量卸载和跨节点 GPU 扩展使其处理 2K×2K×2K 问题，较原 ADMM-FFT 平均快 52.8%、最高快 65.4%。
  - 这项工作的核心不是再优化一个 FFT kernel，而是证明数值迭代内部存在可安全复用的近似计算，并用变换融合、分块私有缓存和批量远程查询把 memoization 开销降到比重算更低。
  - 可靠性、性能分析与运维、性能建模与评测、Performance: Benchmarks and Optimization、HPC 系统、官方摘要预读

- [Scaling the Memory Wall Using Mixed-Precision — HPG-MxP on an Exascale Machine](https://dl.acm.org/doi/10.1145/3712285.3759877)
  - Oak Ridge National Laboratory (ORNL)；Aditya Kashi、Nicholson Koukpaizan、Hao Lu、Michael Matheson、Sarp Oral、Feiyi Wang
  - 该工作用 HPG-MxP 检验混合精度是否也能加速受内存带宽限制的稀疏科学求解，而不只是稠密 AI 矩阵乘。实现以 FP64 外层保证 GMRES 迭代改进的精度，将大量内层操作改为 FP32，同时用 ELLPACK/多着色 Gauss–Seidel、双 GPU 流覆盖 halo 通信、融合 SpMV–restriction 和混合精度 kernel 减少内存流量与主机往返。在 Frontier 9,408 节点全机规模上，双/单精度组合相对全 FP64 实现加速 1.6 倍。
  - 其核心贡献是把 GMRES-IR 的精度分工与稀疏格式、kernel 融合及通信覆盖协同到全机系统，并用收敛惩罚和全规模验证确认加速不是降低解的有用性换来的；这是对“低精度只利好计算密集工作负载”的关键突破。
  - 可靠性、性能分析与运维、性能建模与评测、内存层次/Cache、低精度与量化、HPG、Performance: Benchmarks and Optimization

- [CPU- and GPU-Initiated Communication Strategies for Conjugate Gradient Methods on Large GPU Clusters](https://dl.acm.org/doi/10.1145/3712285.3759774)
  - Simula Research Laboratory、Koç University, Turkey、University of Oslo；James D. Trotter、Sinan Ekmekcibasi、Doğan Sağbili、Johannes Langguth、Xing Cai、Didem Unat
  - 该工作在 NVIDIA 与 AMD 集群上同时实现标准 CG 和流水 CG，系统比较 GPU-aware MPI、NCCL/RCCL 与 NVSHMEM 三类通信路径。CPU 发起版用 GPU 流减少通信同步；更激进的版本则把整个 CG 循环放进一个驻留 GPU kernel，由 NVSHMEM 在设备端发起单边不规则通信，完全去掉 CPU 参与。消除不必要的 CPU–GPU 搬运与同步后，单 GPU 提速 8%–14%，超过 1,000 GPU 的强扩展测试中优于现有方法 5%–15%。
  - 最关键的新意是把“由谁发起通信”提升为 CG 整个执行模式的设计变量：单体驻留 kernel 让迭代、收敛判定和点对点交换都停留在 GPU，不只是把 MPI 换成另一个通信库。
  - 可靠性、性能分析与运维、GPU/异构加速、网络/集合通信、性能建模与评测、CPU、Performance: Benchmarks and Optimization

- [Zero-Value Code Specialization via Profile-Guided Control Data Flow Analysis](https://sc25.conference-program.com/?post_type=page&p=14&id=pap535&sess=sess184)
  - Beihang University、Independent Researcher；Shaokang Du、Kelun Lei、Xin You、Hailong Yang、Yufan Xu、Zhongzhi Luan、Yi Liu、Depei Qian
  - ZeroSpec 处理运行时频繁出现零、但静态编译器无法确定的冗余计算。它用 profile 记录零值，再通过静态控制—数据流分析沿依赖链推导零传播会消除哪些指令，根据细粒度收益/代码膨胀成本选定区域，生成带运行时零检查的专用快路径与通用慢路径。在 SPEC CPU2017、NPB 和实际应用中，最高加速 1.31 倍。
  - 相较只对某个操作数做局部常量传播，ZeroSpec 用控制与数据流的联合分析自动确定“以哪个零值为守卫、克隆多大区域”，并用指令级成本模型筛掉不偿失的专用化，将原本依赖人工选区的优化变成全自动流程。
  - 可靠性、性能分析与运维、性能建模与评测、Performance: Benchmarks and Optimization、HPC 系统、官方摘要预读

- [C.A.T.S.: Memory and Control Flow Tracing for Whole-Program Performance Analysis](https://sc25.conference-program.com/?post_type=page&p=14&id=pap270&sess=sess342)
