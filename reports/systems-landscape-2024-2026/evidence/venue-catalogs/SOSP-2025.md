# SOSP 2025 论文列表

官方 Proceedings 共收录 66 篇论文。以下标题均链接至对应的 ACM DOI 页面；每篇依次列出机构与主要作者、研究场景和系统机制、相较既有方法的核心创新，以及细粒度方向。当前能从官方预印本、作者主页或机构仓储合法直接获取的 PDF 已保存在 `reference/SOSP/2025/`；没有合法直链的论文保留官方页面和摘要证据，不使用非授权镜像。

- [Rearchitecting the Thread Model of In-Memory Key-Value Stores with μTPS](https://doi.org/10.1145/3731569.3764794)
  - Tsinghua University、Shanghai Jiao Tong University；Youmin Chen、Jiwu Shu、Yanyan Shen、Linpeng Huang、Hong Mei
  - μTPS 面向每秒数千万请求的内存 KV Store，把传统 run-to-completion 请求处理拆成两类 stage：cache-resident、低冲突阶段由一组 core/cache way 执行，memory-resident、易争用阶段由另一线程池处理；reconfigurable RPC、可调 cache 和 autotuner 再按负载改变 stage 资源。这样可分别优化 locality 与 synchronization，而不让一条长函数的不同瓶颈互相牵制。
  - 相较所有请求线程从收包到查表完整执行，核心创新是按缓存驻留性和冲突性质重新解释 thread-per-stage，并为各 stage 配置独立硬件资源与可运行时重组的数据通路。
  - 内存 KV Store、Thread-per-stage、Cache Partitioning、争用隔离、自动调优

- [Device-Assisted Live Migration of RDMA Devices](https://doi.org/10.1145/3731569.3764795)
  - NVIDIA；Artem Y. Polyakov、Gal Shalom、Asaf Schwartz、Aviad Yehezkel 等
  - 该工作让使用 ConnectX RDMA passthrough 的 HPC/AI VM 在不中断远端 peer 连接的情况下 live migration。统一 device-hypervisor interface 让 NIC 暂停、导出并在目标恢复 queue、key 和连接状态；迁移协议同时 quiesce 通过 PCIe 等 memory fabric 发生的设备间直接通信，确保设备集合状态一致后切换。正常运行和迁移后均无额外数据路径开销，停机低于一秒。
  - 相较只迁移 CPU/内存或要求 guest/peer 重新建立 RDMA 连接，核心创新是让设备参与状态截获与 quiescence，把一组相互直连的 passthrough device 当作一致迁移单元。
  - RDMA 虚拟化、Device Passthrough、Live Migration、设备状态迁移、HPC/AI 云化

- [Prove It to the Kernel: Precise Extension Analysis via Proof-Guided Abstraction Refinement](https://doi.org/10.1145/3731569.3764796)
  - ETH Zurich；Hao Sun、Zhendong Su
  - 当 Linux eBPF verifier 因抽象不精确而无法判断程序安全时，该方案不直接拒绝，而是把需要更精确证明的路径和状态交给用户态 solver；用户态生成 refinement 及 formal proof，内核只在线性时间内检查 proof，再把新抽象纳入继续分析。实验让 512 个此前误拒的真实 eBPF 程序中 403 个通过，同时不把复杂求解器放进可信内核。
  - 相较不断扩充内核 verifier 的 abstract domain，核心创新是以 proof-carrying refinement 分离“昂贵推理”和“小型可信检查”，同时提高精度并控制 TCB 与最坏复杂度。
  - eBPF Verifier、Proof-guided Abstraction Refinement、Kernel Extension、Proof Checking、静态分析

- [eBPF Misbehavior Detection: Fuzzing with a Specification-Based Oracle](https://doi.org/10.1145/3731569.3764797)
  - EPFL、University of Waterloo；Tao Lyu、Kumar Kartikeya Dwivedi、Thomas Bourgeat、Mathias Payer 等
  - Veritas 生成带依赖关系的 eBPF program，SpecCheck 则把指令语义、寄存器/内存状态和 safety property 编码成可满足性约束，对具体程序做无抽象的“应接受还是应拒绝”判定；该结果与 Linux verifier 比较，既发现接受不安全程序的 security bug，也发现误拒安全程序的 usability bug，并能给出产生分歧的约束。共发现 13 个 verifier 缺陷。
  - 相较等到已接受程序运行崩溃才把它视为 fuzzing oracle，核心创新是建立独立的 specification-level ground truth，直接检查 verifier 的 accept/reject 决策及根因。
  - eBPF Fuzzing、Specification Oracle、Verifier Correctness、Privilege Escalation、可用性缺陷

- [Mercury: Unlocking Multi-GPU Operator Optimization for LLMs via Remote Memory Scheduling](https://doi.org/10.1145/3731569.3764798)
  - UC San Diego、Rice University、Meta、OpenAI；Yue Guan、Xinwei Qiang、Zaifeng Pan、Daniels Johnson 等
  - Mercury 编译跨多 GPU 的 LLM operator，在 loop-based CommIR 中把其他 GPU 的 HBM 显式表示为本地内存层次的延伸。编译器可联合搜索 tensor tile 放在哪张卡、何时经互连读取/写入远端 buffer、计算循环和通信怎样流水，而不是先定并行算法再插 collective；它能自动复现 RingAttention、Ulysses，并发现手工策略未覆盖的 schedule。
  - 相较 compiler 只优化单 GPU kernel、跨卡通信由固定 collective template 决定，核心创新是把 remote GPU memory placement 和 communication schedule 纳入同一个 operator-level loop optimization space。
  - 多 GPU LLM 算子、Compiler IR、Remote HBM、通信调度、自动并行

- [Pesto: Cooking up High Performance BFT Queries](https://doi.org/10.1145/3731569.3764799)
  - Cornell University、UC Berkeley、UC San Diego；Florian Suri-Payer、Neil Giridharan、Liam Arzola、Shir Cohen 等
  - Pesto 是兼容完整 SQL 的 Byzantine-fault-tolerant database，但不让所有 replica 先通过 state-machine replication 排成同一事务序列。各副本可暂时执行出不同状态，只在并发 transaction 可能影响 serializability 或返回 query result 时按需同步并交叉验证；leaderless 路径减少故障切换影响。TPC-C 吞吐接近无复制数据库，并比经典 SMR BFT 提升约 2.3 倍。
  - 相较每个事务都先做全局 total order，核心创新是允许受控副本分歧，把昂贵一致化推迟到查询语义真正要求的位置，同时仍在恶意节点下保持 serializability。
  - BFT 数据库、SQL、On-demand Synchronization、Serializability、Leaderless Replication

- [How to Copy Memory? Coordinated Asynchronous Copy as a First-Class OS Service](https://doi.org/10.1145/3731569.3764800)
  - Shanghai Jiao Tong University、Huawei；Jingkai He、Yunpeng Dong、Dong Du、Mo Zou 等
  - Copier 把内存复制提升为供 syscall、IPC、network stack 和应用共享的 OS service。调用者提交 asynchronous copy 后继续计算，service 根据大小、地址和当前负载选择 CPU、DMA 等 copy engine，并凭全局队列合并、排序和并发多个复制；配套工具链将现有同步 memcpy 路径改造成可重叠调用。Redis、Protobuf、proxy 等获得最高 1.8 倍加速，并集成到 HarmonyOS 5.0。
  - 相较各子系统分别实现 zero-copy 或硬件 memcpy，核心创新是提供统一异步语义和全局协调器，让跨应用 copy 能共享硬件并与原计算重叠。
  - OS Memory Copy、异步数据移动、DMA Offload、系统级调度、HarmonyOS

- [Demeter: A Scalable and Elastic Tiered Memory Solution for Virtualized Cloud via Guest Delegation](https://doi.org/10.1145/3731569.3764801)
  - The Chinese University of Hong Kong、National Yang Ming Chiao Tung University；Junliang Hu、Zhisheng Hu、Chun-Feng Wu、Ming-Chang Yang
  - Demeter 将 VM 的 DRAM+PMEM/CXL.mem 页面冷热跟踪和迁移委托给 guest：guest 可直接使用 Processor Event-Based Sampling 观察虚拟地址访问，并在 range 粒度保留 locality；避免 hypervisor 在二阶段地址转换下扫描页表和频繁 TLB flush。双 balloon 机制分别控制 guest 可用内存与快层配额，让云平台仍可弹性收缩并实施租户 QoS。
  - 相较 hypervisor 统一推断 VM 内页面热度，核心创新是把最需要应用地址语义的决策下放 guest，同时用双 balloon 保留 provider 对容量和快层的控制权。
  - 虚拟化分层内存、CXL.mem、Guest Delegation、PEBS、Memory Ballooning

- [Moirai: Optimizing Placement of Data and Compute in Hybrid Clouds](https://doi.org/10.1145/3731569.3764802)
  - Carnegie Mellon University、Uber；Ziyue Qiu、Hojin Park、Jing Zhao、Yu-Kai Wang 等
  - Moirai 为 on-prem 与公有云之间的 Spark/Presto analytics 同时决定 dataset 是否复制、放在哪侧，以及每个 recurring job 在哪执行。它从历史 query 建出 job-data dependency 和未来访问预测，排除长期未访问数据以缩小搜索，再把数据位置和 egress cost 提供给 scheduler；Uber 四个月、6670 万 query trace 上将 egress、复制和本地网络容量共同压低，总成本相对既有 partitioning 下降 97% 以上。
  - 相较先分数据再独立调度 compute，核心创新是利用 recurring analytics 的访问稳定性联合优化两种位置，使移动任务和复制数据成为同一成本选择。
  - Hybrid Cloud、数据/计算联合放置、Egress Cost、Analytics Scheduling、生产 Trace

- [Unlocking True Elasticity for the Cloud-Native Era with Dandelion](https://doi.org/10.1145/3731569.3764803)
  - ETH Zurich、MPI-SWS；Tom Kuchler、Pinghe Li、Yazhuo Zhang、Lazar Cvetković 等
  - Dandelion 让 cloud-native 应用声明为 pure compute function 与 HTTP/远程服务 communication function 组成的 DAG，不再给每次调用启动带 guest OS、POSIX network 和本地环境的 microVM。纯计算函数可进入极小、强隔离 sandbox，按请求在数百微秒内冷启动，communication function 统一访问 storage/database/AI service；Azure Functions trace 上因此无需维持大量 warm sandbox，平均 committed memory 降低 96%。
  - 相较继续优化 POSIX-compatible VM snapshot，核心创新是改变 cloud application interface，用更高层远程服务语义换掉每实例 OS 与网络配置成本，从而真正按请求分配隔离环境。
  - Cloud-native Runtime、Serverless 弹性、Declarative DAG、微秒级 Sandbox、接口—系统协同设计

- [Sleeping with One Eye Open: Fast, Sustainable Storage with Sandman](https://doi.org/10.1145/3731569.3764804)
  - UC San Diego、Samsung Semiconductor、Shanghai Jiao Tong University；Yanbo Zhou、Erci Xu、Anisa Su、Jim Harris 等
  - Sandman 管理 all-flash server 中为低延迟而常驻 busy-poll 的 CPU/SSD software stack：持续监测 queue 和设备状态，识别即将到来的 I/O burst，快速唤醒或扩展 polling resource；平稳期则让线程/资源进入低功耗状态。它把 resource scaling latency 纳入 burst detection，平均功率最高降低 39.38%、能耗降低 33.36%，大多数场景性能接近始终 busy-poll。
  - 相较固定 polling 保性能或固定 interrupt/power state 省能，核心创新是围绕存储 burst 的短时间尺度联动监测、预测和快速扩缩，保留峰值响应能力。
  - 存储节能、All-flash Server、I/O Burst Detection、Busy Polling、资源弹性

- [Spirit: Fair Allocation of Interdependent Resources in Remote Memory Systems](https://doi.org/10.1145/3731569.3764805)
  - UC Berkeley、Yale University；Seung-seob Lee、Jachym Putta、Ziming Mao、Anurag Khandelwal
  - Spirit 为共享 far-memory service 的多应用同时分配本地 cache 容量与 network bandwidth。两种资源可互相替代：更大 cache 减少网络 fetch，更宽带宽又允许小 cache 保持吞吐；系统在线学习每个应用的等效组合，Symbiosis 算法以微观经济学“交易”资源，使租户在各自性能曲线上取得可证明公平的分配，且相对独立配额最高提升 21.6% 性能。
  - 相较分别对内存和带宽做 max-min fairness，核心创新是在联合效用曲线上定义公平，允许租户交换两类互依资源而不强迫它们采用同一比例。
  - Remote Memory、多资源公平、Cache/Bandwidth 联合分配、在线资源交易、性能隔离

- [HedraRAG: Co-Optimizing Generation and Retrieval for Heterogeneous RAG Workflows](https://doi.org/10.1145/3731569.3764806)
  - UC San Diego、Rice University、RegAilator；Zhengding Hu、Vibha Murthy、Zaifeng Pan、Wanlu Li 等
  - HedraRAG 把包含 query processing、retrieval、reranking 和 generation 的异构 RAG workflow 表示为 RAGraph。Runtime 对并发请求的 wavefront 动态做 node splitting/reordering、增加或改接 edge：把可并行 stage 分开执行，合并请求内相似工作，并针对请求间长短偏斜重排 CPU–GPU pipeline。不同 RAG 图无需手写专用调度，端到端加速 1.5–5 倍。
  - 相较把 retriever 和 LLM 各自作为固定 service 调度，核心创新是用可变换 workflow graph 同时暴露跨 stage、请求内和请求间三种优化机会。
  - RAG Serving、Workflow Graph、CPU-GPU Pipeline、跨阶段调度、LLM Infra

- [Scalable Address Spaces using Concurrent Interval Skiplist](https://doi.org/10.1145/3731569.3764807)
  - KAIST、FuriosaAI；Tae Woo Kim、Youngjin Kwon、Jeehoon Kang
  - 该工作替换 Linux 由全局 mmap_lock 串行保护的 VMA 管理。Concurrent interval skiplist 将虚拟地址区间索引和每段 locking 元数据放进同一结构，让不重叠的 mmap/munmap/page-fault 路径并行，并逐项消除 TLB、allocator 和辅助元数据的扩展瓶颈；Linux 6.8 原型在 48 core 上把 mmap microbenchmark 提升 13.1 倍，并改善 LevelDB/Apache 等应用。
  - 相较在 VMA tree 外叠加更细锁，核心创新是让区间查找、插入和同步由一个支持并发重叠判定的数据结构原生完成，避免索引与锁状态二次协调。
  - 虚拟地址空间、Concurrent Interval Skiplist、mmap Scalability、内核锁、Memory Management

- [Characterizing Mobile SoC for Accelerating Heterogeneous LLM Inference](https://doi.org/10.1145/3731569.3764808)
  - Shanghai Jiao Tong University、Tsinghua University、SenseTime；Le Chen、Dahu Feng、Erhu Feng、Yingrui Wang 等
  - HeteroInfer 先测量手机 GPU、NPU 的算力、算子支持、共享内存带宽和对其他 app 的干扰，再按 operator/layer 将 LLM 同时放到 GPU 与 NPU；统一内存使两侧共享 tensor，快速同步机制减少 heterogeneous pipeline barrier。不同模型和手机上相对单一 GPU/NPU engine 提升 1.34–6.02 倍，并保持较低前台干扰。
  - 相较把整模型固定映射到某一种移动加速器，核心创新是以实测 SoC bandwidth 和 operator affinity 构建真正并行的 GPU–NPU 执行，而不是简单 fallback。
  - 端侧 LLM 推理、Mobile SoC、GPU-NPU 异构并行、Unified Memory、性能表征

- [μFork: Supporting POSIX fork Within a Single-Address-Space OS](https://doi.org/10.1145/3731569.3764809)
  - University of Manchester、University of British Columbia；John Alistair Kressel、Hugo Lefeuvre、Pierre Olivier
  - μFork 在 kernel 与应用共享一个 address space 的 Unikraft 上兼容未修改 POSIX fork：child memory 被复制到同一地址空间的另一区域，CHERI memory tag 帮助识别并重定位其中仍指向 parent 的 absolute pointer，bounded capability 隔离 parent、child 与 kernel，并配套 copy-on-write。Redis snapshot、Nginx worker 和 FaaS Zygote 可直接运行，fork 约 54 μs。
  - 相较为 fork 引入第二页表/VM、破坏 SASOS 轻量性，核心创新是用 capability tag 同时解决单地址空间内的指针重定位和安全域隔离。
  - Single-address-space OS、POSIX fork、CHERI、Capability Isolation、Copy-on-write

- [DiffKV: Differentiated Memory Management for Large Language Models with Parallel KV Compaction](https://doi.org/10.1145/3731569.3764810)
  - Shanghai Jiao Tong University、Huawei、CUHK；Yanqi Zhang、Yuwei Hu、Runyuan Zhao、John C. S. Lui、Haibo Chen
  - DiffKV 不再统一量化/裁剪 K 和 V：它分别考虑 key 与 value 对 attention 的作用、token 重要性，以及各 attention head 随输入变化的 sparse pattern，为不同 head/request 保留不同数量和精度的 KV。由此产生的不规则 hole 交给 on-GPU manager 并行 compact free-list 和移动 block，把逻辑稀疏真正变成连续可分配显存；复杂 reasoning/长生成 workload 上压缩 2.7–5.7 倍并提升吞吐 1.9–5.4 倍。
  - 相较所有 head、token、K/V 使用同一 compression rule，核心创新是三级差异化压缩与 GPU 并行内存整理共同设计，避免更细粒度策略被 fragmentation 抵消。
  - LLM KV Cache、差异化压缩、Attention Head 稀疏、GPU Memory Compaction、长推理

- [Proto: A Guided Journey through Modern OS Construction](https://doi.org/10.1145/3731569.3764811)
  - University of Virginia；Wonkyo Choe、Rongxiang Wang、Afsara Benazir、Felix Xiaozhu Lin
  - Proto 是运行在通用便携硬件上的教学 OS，把 address space、thread、commodity filesystem、USB、DMA、multicore、self-hosted debugger 和 window manager 拆成一系列可独立运行的增量 prototype。每一步由一个 2D/3D game、音视频播放器或 blockchain miner 的真实需求驱动，只引入让该 app 工作的最小机制，学生最终拼出完整系统。
  - 相较从 terminal 和抽象 subsystem 依序实现传统教学内核，核心创新是以可见应用为依赖图组织 OS 构造，让现代设备机制和复杂应用成为渐进课程的一部分。
  - 操作系统教育、Instructional OS、增量原型、Commodity Hardware、Application-driven Learning

- [Oasis: Pooling PCIe Devices Over CXL to Boost Utilization](https://doi.org/10.1145/3731569.3764812)
  - Columbia University、Microsoft Azure/Research、MIT CSAIL、UIUC、University of Washington；Yuhong Zhong、Daniel S. Berger、Pantea Zardoshti 等
  - Oasis 利用数据中心已部署的 CXL memory pool 作为 host 与远端 PCIe device 间的数据通道。Control plane 把某台机器的 device queue/doorbell 映射到 pool，按设备类型加载 engine 转发 descriptor、completion 和 DMA data，使多 host 共享 NIC/SSD 而无需昂贵 PCIe switch；NIC 原型将利用率提高约 2 倍，failover 中断 38 ms。
  - 相较为设备池另建专用 PCIe fabric，核心创新是复用 CXL shared-memory reachability 承载跨主机 PCIe 协议，并把设备类别差异封装为可插拔 engine。
  - CXL、PCIe Device Pooling、NIC 共享、资源利用率、设备 Failover

- [PhoenixOS: Concurrent OS-level GPU Checkpoint and Restore with Validated Speculation](https://doi.org/10.1145/3731569.3764813)
  - Shanghai Jiao Tong University、National University of Singapore；Xingda Wei、Zhuobin Huang、Tianle Sun、Yingyi Hao 等
  - PhoenixOS 在 GPU process 继续执行时 checkpoint/restore。由于 GPU 没有 CPU dirty bit/COW 路径，系统先从 kernel launch argument 推测本 kernel 会读写哪些 memory region，再以 binary instrumentation 在运行中验证；据此实现 software COW、recopy 和 on-demand restore，并协调 checkpoint transfer 与 execution-context pool。迁移、故障恢复和 serverless 冷启动均不必暂停整个 GPU process。
  - 相较 stop-the-world GPU checkpoint，核心创新是用“推测访问集合 + 低成本运行验证”补出 GPU 缺失的内存观察机制，从而安全并发复制状态。
  - GPU Checkpoint/Restore、Validated Speculation、Software COW、进程迁移、Serverless GPU

- [Pie: A Programmable Serving System for Emerging LLM Applications](https://doi.org/10.1145/3731569.3764814)
  - Yale University；In Gim、Zhiyao Ma、Seung-seob Lee、Lin Zhong
  - Pie 把 serving engine 固定的 token-generation loop 拆成 sampling、KV 操作、model step、I/O 等细粒度 handler，并允许应用提交 WebAssembly sandbox 中的 inferlet 控制调用顺序。Agent workflow、custom decoding 或外部工具等待因此可自行插入 KV policy、跨请求复用和计算/I/O overlap，而不修改 serving backend；标准生成只增加 3%–12% 延迟，agentic workflow 吞吐/延迟可改善 1.3–3.4 倍。
  - 相较 serving system 只接受 prompt 并完整生成，核心创新是把 generation control plane 安全开放给应用程序，使新推理/Agent 逻辑能直接参与底层状态和调度。
  - Agent Infra、可编程 LLM Serving、Inferlet、WebAssembly Sandbox、Tool/IO Workflow

- [Aegaeon: Effective GPU Pooling for Concurrent LLM Serving on the Market](https://doi.org/10.1145/3731569.3764815)
