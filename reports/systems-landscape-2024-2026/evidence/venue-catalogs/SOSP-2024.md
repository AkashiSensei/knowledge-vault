# SOSP 2024 论文列表

官方 Proceedings 共收录 43 篇论文。以下标题均链接至对应的 ACM DOI 页面；每篇依次列出机构与主要作者、可以在不阅读全文时理解研究对象和技术路径的核心工作、相较既有方法的核心创新，以及细粒度研究方向。当前能从官方预印本、作者主页或机构仓储合法直接获取的 PDF 已保存在 `reference/SOSP/2024/`，其余论文保留官方页面，未使用非授权镜像。

- [Aceso: Achieving Efficient Fault Tolerance in Memory-Disaggregated Key-Value Stores](https://doi.org/10.1145/3694715.3695951)
  - Huawei Cloud、The Chinese University of Hong Kong；Zhisheng Hu、Pengfei Zuo、Yizou Chen、Chao Wang 等
  - Aceso 面向计算节点通过网络访问共享内存池的 KV Store，把故障保护按数据结构拆开：索引用差分 checkpoint，KV 数据用 erasure coding；版本号补回 checkpoint 期间尚未落盘的索引更新，delta reclamation 回收旧版本，分层恢复先恢复关键元数据、再后台恢复其余数据。它在避免双/三副本高内存占用的同时，相对复制型系统最高提升 2.7 倍吞吐、降低 54% 尾延迟并节省 44% 内存。
  - 相较把索引和数据统一复制，核心创新是根据二者访问与恢复特征组合 checkpoint 和纠删码，并把 checkpoint 干扰、编码数据回收和故障恢复共同纳入一条可在线运行的容错路径。
  - 内存解耦 KV Store、混合容错、差分 Checkpoint、Erasure Coding、故障恢复

- [Apparate: Rethinking Early Exits to Tame Latency-Throughput Tensions in ML Serving](https://doi.org/10.1145/3694715.3695963)
  - Princeton University、Georgia Tech；Yinwei Dai、Rui Pan、Anand Iyer、Kai Li、Ravi Netravali
  - Apparate 为视觉、NLP 分类和自回归生成模型自动插入并在线管理 early exit：容易样本可在中间层提前返回，系统同时让所有出口继续计算少量 shadow result，以持续估计各出口的准确率和额外计算开销，再按请求分布动态调整出口位置与置信阈值。这样降低单请求中位延迟和生成 token 时间，同时不牺牲原有吞吐并满足给定准确率约束。
  - 相较离线训练后固定 early-exit 结构和阈值，核心创新是把出口本身变成持续反馈信号，使 serving runtime 能在输入分布变化时闭环控制退出策略。
  - DNN/LLM Serving、Early Exit、逐输入计算自适应、在线准确率约束、推理延迟

- [Autobahn: Seamless high speed BFT](https://doi.org/10.1145/3694715.3695942)
  - Cornell University、UC Berkeley、Intel Labs；Neil Giridharan、Florian Suri-Payer、Ittai Abraham、Lorenzo Alvisi、Natacha Crooks
  - Autobahn 面向网络会短暂异步、节点可能作恶的 BFT 状态机复制，将交易数据在多条独立 lane 中异步并行传播，再由低延迟的部分同步 consensus 只对已传播的数据引用排序。数据面无需等待共识轮次，因此网络恢复后不会累积传统 view-based 协议的 hangover；同时共识路径比 DAG BFT 更短，达到相近吞吐而将其延迟约减半。
  - 相较分别偏向稳定期低延迟或故障后平滑恢复的两类协议，核心创新是把无阻塞数据传播与简短的部分同步排序解耦，在同一协议中同时取得两种性质。
  - Byzantine Fault Tolerance、部分同步共识、异步数据传播、状态机复制、故障恢复

- [BIZA: Design of Self-Governing Block-Interface ZNS AFA for Endurance and Performance](https://doi.org/10.1145/3694715.3695953)
  - Arizona State University、KAIST、Peking University、CUHK 等；Shushu Yi、Shaocong Sun、Li Peng、Yingbo Sun 等
  - BIZA 是对上仍暴露普通 block interface、对下主动管理 ZNS SSD 的全闪存阵列。它把频繁更新的热块暂存到容量有限的 Zone Random Write Area，使用 ghost cache 识别真正值得占用 ZRWA 的数据；再以 guess-and-verify 探测 zone 与内部 I/O 资源的映射，让定制调度器把主机写和垃圾回收等内部任务分发到不同资源并行执行。
  - 相较要求上层软件改用 ZNS 接口或让传统阵列完全看不到 zone，核心创新是让阵列在保持 block 兼容性的同时推断并利用 ZNS 内部拓扑，自主管理热更新与后台任务。
  - ZNS SSD、全闪存阵列、Block Interface 兼容、写放大、存储 I/O 调度

- [CHIME: A Cache-Efficient and High-Performance Hybrid Index on Disaggregated Memory](https://doi.org/10.1145/3694715.3695959)
  - The Chinese University of Hong Kong、Fudan University、Huawei Cloud、Duke Kunshan University；Xuchuan Luo、Jiacheng Shen、Pengfei Zuo 等
  - CHIME 为远程内存上的范围查询把 B+ tree 的有序导航与 hopscotch hash 的快速定位结合：计算节点只缓存较少的上层索引，远端桶用三层不同粒度的 optimistic synchronization 支持并发读写；元数据通过复制和 piggyback 与数据一次取回，系统还根据 key 热度推测应预读的邻近桶，减少一次查询的 RDMA 读取次数。
  - 相较纯 B+ tree 依赖大量本地缓存、纯哈希又产生远端读放大，核心创新是在一个可并发索引中联合两种结构，并围绕网络往返重新设计同步、元数据和投机读取。
  - 内存解耦、远程范围索引、B+ Tree/Hash 混合、RDMA 访问、缓存效率

- [Caribou: Fine-Grained Geospatial Shifting of Serverless Applications for Sustainability](https://doi.org/10.1145/3694715.3695954)
  - University of British Columbia、ETH Zurich；Viktor Urban Gsteiger、Pin Hong Long、Yiran Sun、Parshan Javanrood、Mohammad Shahrad
  - Caribou 在多区域云上以 serverless workflow 的单个函数为迁移粒度，结合各区域实时电力碳强度、函数执行与跨区传输成本、端到端延迟以及数据驻留约束，搜索每个阶段应部署在哪个区域。系统自动重部署函数并把请求重定向到新 endpoint，无需修改应用逻辑或云提供商平台；部分阶段必须留在指定地区时，仍可移动其余阶段来减排。
  - 相较把整个应用一次性迁往低碳区域，核心创新是把 workflow 拆到函数级并同时满足位置、性能和成本约束，使局部合规限制不再阻止其余计算做碳感知迁移。
  - Serverless Workflow、碳感知调度、跨区域部署、函数级迁移、可持续云计算

- [Cookie Monster: Efficient On-Device Budgeting for Differentially-Private Ad-Measurement Systems](https://doi.org/10.1145/3694715.3695965)
  - Columbia University、Meta、University of British Columbia；Pierre Tholoniat、Kelly Kostopoulou、Peter McNeely 等
  - Cookie Monster 面向浏览器在移除第三方 cookie 后的广告转化统计，在用户设备上记录并消耗 differential privacy budget。它把“一个人对多个 measurement query 的贡献”建模为 individual DP，而非对所有可能用户采用同一最坏情况预算，从而允许浏览器针对实际参与查询更精确地核算隐私损耗；Chrome 原型在相同隐私保证下支持更多可用统计查询。
  - 相较现有广告 API 使用传统全局 DP 预算而过早耗尽额度，核心创新是把预算单位落到个人实际贡献，并将可证明的预算执行直接置于客户端可信边界内。
  - 隐私广告测量、On-device Privacy Budget、Individual Differential Privacy、浏览器系统

- [DNS Congestion Control in Adversarial Settings](https://doi.org/10.1145/3694715.3695982)
  - ETH Zürich；Huayi Duan、Jihye Kim、Marc Wyss、Adrian Perrig
  - 该工作研究攻击者用少量恶意 DNS 查询持续占满递归解析器与权威服务器之间的通道、进而让大量正常客户端失去解析能力的 adversarial congestion。DCC 在 DNS 服务器内部以优化的 fair queue 隔离不同来源/目标的消息，并通过异常检测和拥塞信号限制制造阻塞的流量，保持正常请求的公平通行；其部署不要求改变 DNS 协议或客户端。
  - 相较只按查询速率检测 DDoS，核心创新是把攻击抽象为 DNS 服务器间通道的拥塞控制问题，以公平排队提供行为无关的最低服务，再用信号机制减少误伤。
  - DNS 安全、对抗性拥塞、Fair Queuing、DoS 防御、Internet Infrastructure

- [Dirigent: Lightweight Serverless Orchestration](https://doi.org/10.1145/3694715.3695966)
  - ETH Zurich、IBM Research Europe；Lazar Cvetković、François Costa、Mihajlo Djokic、Michal Friedman、Ana Klimovic
  - Dirigent 是为高 sandbox churn 的 FaaS 集群重写的编排器：压平 Kubernetes 式多层对象与 controller，函数调用关键路径只维护即时内存状态而不做持久化更新，并把控制面和数据面放进同一进程以消除内部 RPC。它利用 FaaS 不向用户暴露 sandbox 具体位置的语义，允许故障后重建“等价容量”而非逐项恢复旧映射，因而可每秒启动约 2500 个 sandbox 并降低 P99 调度延迟。
  - 相较在通用容器编排器上叠加函数层，核心创新是利用 FaaS 的位置透明性放松精确状态恢复要求，从根源缩短状态机和调用链。
  - Serverless/FaaS 编排、Sandbox Churn、轻量控制面、关键路径状态管理、冷启动

- [Efficient Reproduction of Fault-Induced Failures in Distributed Systems with Feedback-Driven Fault Injection](https://doi.org/10.1145/3694715.3695979)
  - Johns Hopkins University、University of Michigan、Microsoft Research；Jia Pan、Haoze Wu、Tanakorn Leesatapornwongsa、Suman Nath、Peng Huang
  - Anduril 用于重现“已知生产故障”，而不是盲目找新 bug：它先从失败症状和分布式程序的因果依赖中筛出可能相关的故障位置与类型，再运行系统、比较当前执行与目标失败状态的距离，并用反馈引导下一轮选择故障注入时机和组合。对 22 个真实 failure 的实验均能重现，中位搜索时间约 8 分钟。
  - 相较枚举节点宕机、网络丢包和时序组合，核心创新是把静态因果范围与运行反馈组成面向指定症状的搜索闭环，只探索更可能抵达目标失败状态的执行。
  - 分布式系统调试、故障注入、Failure Reproduction、反馈引导搜索、因果分析

- [Efficient file-lifetime redundancy management for cluster file systems](https://doi.org/10.1145/3694715.3695981)
  - Carnegie Mellon University、Google；Timothy Kim、Sanjith Athlur、Saurabh Kadekodi、Francisco Maturana 等
  - Morph 管理集群文件从新写入、高热到冷数据阶段的冗余转换：新文件不再先写三副本，而是写“一份副本加一条纠删码 stripe”，转冷时删除副本即可免费变成 EC；以后需要换成更宽、更节省容量的 EC 配置时，使用 convertible codes 只读取必要的数据块，并配套 placement 让可转换块位于合适节点。Google trace 分析显示可减少 95% 以上转码 I/O。
  - 相较把每次 replica-to-EC 或 EC-to-EC 变化都当成完整重编码，核心创新是让前一阶段的编码布局预先包含后一阶段需要的信息，使文件生命周期中的冗余变化可增量完成。
  - 集群文件系统、冗余生命周期、Convertible Codes、Erasure Coding、存储转码 I/O

- [Enabling Parallelism Hot Switching for Efficient Training of Large Language Models](https://doi.org/10.1145/3694715.3695969)
  - Peking University、Purdue University；Hao Ge、Fangcheng Fu、Haoyang Li、Xuanyu Wang 等
  - HotSPa 解决同一 LLM 训练 mini-batch 内序列长度差异导致静态 data/tensor/pipeline parallelism 低效的问题。系统先按长度把样本分组并为各组选择不同并行策略，编译器生成多张共享同一份参数存储的执行图；组间切换时，hot-switch planner 只传输新策略改变 ownership 的参数、梯度和 optimizer state，并安排通信与计算重叠。
  - 相较整次训练固定一种并行配置或切换时重新构建模型状态，核心创新是让多套并行执行图共享底层张量，并把状态重分片变成可在 batch 边界快速执行的运行时操作。
  - LLM 训练系统、动态混合并行、序列长度异构、执行图切换、训练状态重分片

- [FBDetect: Catching Tiny Performance Regressions at Hyperscale through In-Production Monitoring](https://doi.org/10.1145/3694715.3695977)
  - Meta、The Ohio State University；Dong Young Yoon、Yang Wang、Miao Yu、Elvis Huang 等
  - FBDetect 在 Meta 数百万服务器上监测约 80 万条吞吐、延迟、CPU 和内存时间序列，以发现最低约 0.005% 的代码/配置性能回退。它在全 fleet 采集 stack trace，把候选版本细化到 subroutine 级差异；随后过滤负载波动等伪回退、合并由同一变更造成的相关告警，并把指标、调用栈和变更关联成根因。系统已持续生产运行七年。
  - 相较只对 benchmark 或少量 canary 做版本对比，核心创新是将极小效应的统计检测与 fleet-wide 程序上下文结合，使海量噪声下的微小回退仍可定位到具体代码路径。
  - 生产性能回退、Hyperscale Monitoring、调用栈归因、时间序列异常检测、AIOps（非 LLM）

- [Fast & Safe IO Memory Protection](https://doi.org/10.1145/3694715.3695943)
  - Cornell University、UIUC；Benny Rubin、Saksham Agarwal、Qizhe Cai、Rachit Agarwal
  - 该工作保持 IOMMU 对设备 DMA 的严格地址隔离，但将优化目标从“提高 IOTLB 命中率”转为“降低每次 miss 的处理成本”：为 DMA buffer 分配连续 IOVA 以缩短页表遍历，避免映射更新时不必要的 page-table-cache invalidation，并批量执行 DMA unmap，减少设备与 IOMMU 同步。无需修改设备或主机硬件即可把生产场景中隔离引入的吞吐和尾延迟开销压到接近零。
  - 相较通过大页、缓存扩容或弱化隔离减少 miss，核心创新是系统性重构 miss 后的软件映射生命周期，即使工作集远大于 IOTLB 也维持完整保护和低开销。
  - IOMMU、DMA 内存保护、IOTLB Miss、IOVA 管理、设备隔离

- [Fast Core Scheduling with Userspace Process Abstraction](https://doi.org/10.1145/3694715.3695976)
  - Tsinghua University；Jiazhen Lin、Youmin Chen、Shiwei Gao、Youyou Lu
  - uProcess 在同一 Linux 进程内建立可隔离的用户态“进程”：MPK 划分普通应用与特权调度运行时的内存权限，user interrupt 让运行时不陷入内核即可抢占当前 uProcess。基于它构建的 Vessel 以亚微秒级把 CPU core 在 latency-critical 与 best-effort 应用间切换，在保障前者尾延迟时利用空闲 core 执行后者。
  - 相较内核线程/进程切换或只能协作让出的用户态 fiber，核心创新是组合 Uintr 与 MPK，在用户态同时获得异步抢占和受保护的调度控制权。
  - 用户态调度、Core Scheduling、User Interrupt、Memory Protection Keys、LC/BE Colocation

- [Fast, Flexible, and Practical Kernel Extensions](https://doi.org/10.1145/3694715.3695950)
  - EPFL、UC Berkeley；Kumar Kartikeya Dwivedi、Rishabh Iyer、Sanidhya Kashyap
  - KFlex 把安全内核扩展分成两个问题：静态 verifier 只证明扩展遵守内核暴露的接口契约，运行时则用 software fault isolation、独立 heap 和可取消执行保证扩展不会越界访问或无限占用 CPU。两层共同设计后，扩展可使用动态分配和复杂数据结构，不必让 eBPF 式 verifier 在加载时证明全部控制流性质；典型应用约增加 7% 延迟或降低 30% 吞吐。
  - 相较 eBPF 将安全性和可验证性都压进受限字节码与单个 verifier，核心创新是把“接口正确性”与“扩展自身内存/终止安全”分治，使功能表达力和运行开销可独立取舍。
  - 内核可扩展性、eBPF 替代、Software Fault Isolation、静态验证、运行时隔离

- [Icarus: Trustworthy Just-In-Time Compilers with Symbolic Meta-Execution](https://doi.org/10.1145/3694715.3695949)
  - UC San Diego、The University of Texas at Austin、Carnegie Mellon University；Naomi Smith、Abhishek Sharma、John Renner、David Thien 等
  - Icarus 让开发者用受控 DSL 编写 JavaScript JIT，然后通过 symbolic meta-execution 把 JIT 对任意输入可能生成的所有 machine-code program 编码为一个 Boogie meta-program，由 SMT solver 一次证明这些输出都满足内存安全等性质，最后生成可链接进浏览器的 C++。Firefox JIT 组件实验既能发现真实漏洞，也能生成与手写实现相当的代码。
  - 相较逐个验证运行时生成的程序或人工证明 JIT compiler，核心创新是用一次符号化元执行概括无限输出空间，把“所有未来生成代码的安全性”转化为静态可解的单一验证任务。
  - JIT Compiler、Symbolic Meta-execution、程序验证、浏览器安全、SMT

- [If At First You Don’t Succeed, Try, Try, Again...? Insights and LLM-informed Tooling for Detecting Retry Bugs in Software Systems](https://doi.org/10.1145/3694715.3695971)
  - Microsoft Research、University of Chicago；Bogdan Alexandru Stoica、Utsav Sethi、Yiming Su、Cyrus Zhou 等
  - 该工作先从真实系统归纳 retry 的遗漏重试、错误条件、状态未清理和无界重试等 bug，再用 LLM 从非统一的函数名、异常处理和控制流语义中识别“这段代码是否实现 retry”及其边界；随后复用项目已有 unit test，在重试点注入失败并检查多次执行后的状态与返回结果。LLM 负责发现传统规则难统一表达的候选代码，动态测试负责以真实执行确认问题。
  - 相较要求开发者使用统一 retry library 或仅靠静态模式匹配，核心创新是让 LLM 补足 ad-hoc 实现的语义识别，再把已有测试转化为针对 retry 时序和状态清理的故障注入 oracle。
  - LLM for Systems、Retry Bug 检测、程序语义识别、故障注入、软件测试

- [Improving DNN Inference Throughput Using Practical, Per-Input Compute Adaptation](https://doi.org/10.1145/3694715.3695978)
  - Princeton University、Georgia Tech、Stanford University；Anand Padmanabha Iyer、Mingyu Guan、Yinwei Dai、Rui Pan 等
  - E3 部署带 early exit 的视觉、NLP 及自回归 LLM：不同请求在不同层退出会让后续 GPU batch 越来越小，E3 因此把连续层切成 block，并复制部分 block 到多台设备，让仍需深入执行的请求重新组成固定大小 batch；放置器联合决定 block 切分、复制数、设备位置和通信，在准确率阈值下最大化 goodput 或降低成本。
  - 相较让退出后的 batch 自然收缩、导致 GPU utilization 下降，核心创新是通过 layer-block replication 主动重整请求，使逐输入计算量变化不再破坏批处理效率。
  - DNN/LLM Serving、Early-exit 部署、逐请求计算自适应、Layer Block Replication、Goodput

  - 相较分别依赖 Lambda 和 Kubernetes 两套平台，核心创新是从 cloud-native 应用只需 CPU、内存和远程服务这一假设出发，设计同时具备快速启动、长期状态和安全通信的单一 proc 抽象。
  - Cloud OS、Serverless/Microservice 统一、轻量隔离、快速启动、租户网络

- [VPRI: Optimized I/O Page Fault in Public IaaS](https://doi.org/10.1145/3694715.3695957)
  - Alibaba Cloud、Shanghai Jiao Tong University；Kaijie Guo、Dingji Li、Ben Luo、Yibin Shen 等
  - VPRI 让使用 device passthrough 的云 VM 不必为 DMA 永久 pin 住全部 guest memory。设备遇到未驻留页面时，经虚拟化 Page Request Interface 向 host 发起 I/O page fault，软件—硬件协作完成页面调入、映射更新和请求恢复；设计避开特定 IOMMU 的 ATS/PRI 依赖和设备自带地址转换复杂度，并限制 fault 对租户 I/O SLO 的影响，已在 Alibaba Cloud 大规模部署。
  - 相较标准 PRI 成本高且平台绑定、或设备各自实现 IOMMU，核心创新是提供可虚拟化、平台无关的统一缺页路径，使 passthrough 性能与内存按需分配可以共存。
  - 云虚拟化、Device Passthrough、I/O Page Fault、IOMMU、内存超分

- [Verus: A Practical Foundation for Systems Verification](https://doi.org/10.1145/3694715.3695952)
  - Carnegie Mellon University、Microsoft Research、ETH Zurich、UW-Madison 等；Andrea Lattuada、Travis Hance、Jay Bosamiya、Matthias Brun 等
  - Verus 在 Rust 语法和类型系统上加入 specification、proof 和 ghost state，统一支持顺序/并发数据结构、page table、NUMA replication、crash-safe storage 与 allocator 等系统证明。它整合 SMT 自动化、linear reasoning、ownership 和并发 invariant，并针对 proof checking 编译与求解流程优化；六类案例共 6.1K 行实现、31K 行证明，验证速度较已有工具快 3–61 倍。
  - 相较每个系统领域定制逻辑或为自动化牺牲表达能力，核心创新是把多种已验证有效的证明机制统一到生产可用 Rust 语言和一个高性能验证管线中。
  - Rust 系统验证、SMT、并发不变量、Crash Safety、形式化方法平台

- [vSoC: Efficient Virtual System-on-Chip on Heterogeneous Hardware](https://doi.org/10.1145/3694715.3695946)
  - Tsinghua University、UIUC、University of Southern California；Jiaxing Qiu、Zijie Zhou、Yang Li、Zhenhua Li 等
  - vSoC 加速在 PC/服务器上模拟带 camera、codec、image processor 等设备的移动 SoC。它在 guest 中提供统一 shared virtual memory，而 host 端把分散在 CPU 和各设备显存的数据映射进同一虚拟地址空间；prefetch engine 根据设备 pipeline 提前搬运和同步将被下一阶段访问的数据，隐藏 coherence 开销。热门应用帧率提升 12%–49%，AR/VR 等新应用提升 1.8–9 倍，并被 Huawei DevEco Studio 采用。
  - 相较逐设备 copy buffer、为每种 host accelerator 编写专用通路，核心创新是用虚拟 SoC 级 SVM 消除 guest/host memory architecture 不匹配，再以 pipeline-aware prefetch 保持一致性而不阻塞帧处理。
  - 移动系统虚拟化、System-on-Chip、Shared Virtual Memory、异构设备、模拟器性能
