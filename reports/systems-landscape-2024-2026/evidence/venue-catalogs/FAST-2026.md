# FAST 2026 论文列表

FAST 2026 正式技术议程共收录 44 篇论文。以下标题链接至 USENIX 官方页面；每篇依次列出作者与机构、研究场景和系统机制、相较既有方法的核心创新，以及细粒度方向。44 份官方 PDF 均已保存至 `reference/FAST/2026/`。

- [Here, There and Everywhere: The Past, the Present and the Future of Local Storage in Cloud](https://www.usenix.org/conference/fast26/presentation/yang)
  - Leping Yang, Shanghai Jiao Tong University; Yanbo Zhou, Gong Zeng, Li Zhang, Saisai Zhang, Ruilin Wu, Chaoyang Sun, Shiyi Luo, Wenrui Li, Keqiang Niu, Xiaolu Zhang, Junping Wu, Jiaji Zhu, and Jiesheng Wu, Alibaba Group; Mariusz Barczak and Wayne Gao, Solidigm; Ruiming Lu, Erci Xu, and Guangtao Xue, Shanghai Jiao Tong University Awarded Best Paper! Deployed-Systems Paper
  - 该经验论文回顾 Alibaba Cloud local storage 从 host userspace stack 到硬件 offload 的多代架构，按 workload、性能隔离、故障域、运维和成本分析各方案为何演进；进一步提出 local NVMe 与 EBS 组合的 hybrid path，在正常期保 near-physical 性能、故障/容量不足时借远端块存储补 availability/elasticity。
  - 相较只展示某一代 local-disk service，核心贡献是把软件栈、offload 和 local–remote hybrid 的长期生产取舍放到统一演进框架。
  - Cloud Local Storage、Architecture Evolution、Hardware Offload、EBS Hybrid、Alibaba Cloud

- [Cost-efficient Archive Cloud Storage with Tape: Design and Deployment](https://www.usenix.org/conference/fast26/presentation/wang)
  - Qing Wang, Tsinghua University; Fan Yang, Qiang Liu, and Geng Xiao, Huawei Cloud; Yongpeng Chen and Hao Lan, Tsinghua University; Leiming Chen, Bangzhu Chen, Chenrui Liu, Pingchang Bai, Bin Huang, Zigan Luo, Mingyu Xie, and Yu Wang, Huawei Cloud; Youyou Lu, Tsinghua University; Huatao Wu, Huawei Cloud; Jiwu Shu, Tsinghua University and Minjiang University Deployed-Systems Paper
  - TapeOBS 是 Huawei Cloud 百 PB 级 archive service：所有 tape mount/read/write/EC job 都进入 fully asynchronous pool，按 tape/drive locality 和批量大小调度，以适配 library drive 数少、seek/mount 昂贵；library 内用 tape-tailored local engine 和 dedicated drive 隔离关键工作，并批量做 erasure coding。
  - 相较把 tape 当慢 disk 同步服务 request，核心创新是把整条数据路径改成大批异步任务系统，让 coding、调度与有限机械 drive 共同优化。
  - Tape Storage、Cloud Archive、Asynchronous Scheduling、Erasure Coding、Huawei Cloud

- [Towards Condensed and Efficient Read-Only File System via Sort-Enhanced Compression](https://www.usenix.org/conference/fast26/presentation/huang)
  - Hao Huang, Yifeng Zhang, Yanqi Pan, Wen Xia, Xiangyu Zou, and Darong Yang, Harbin Institute of Technology, Shenzhen; Jubin Zhong and Hua Liao, Huawei Technologies Co., Ltd
  - RubikFS 构建只读 IoT/container image 前，把 file chunk 建 similarity graph 并做 subgraph partition，将相似内容聚到同一 compression block，避免 block 内数据混杂；hotness grouper 又让常读 chunk 同组，读取时少解压无关冷数据。压缩率最高增 42.6%、无用读取少 70.7%。
  - 相较按原文件顺序固定大小压缩，核心创新是允许重排只读数据，并用 similarity 与 hotness 两种图/分组同时优化空间和 read amplification。
  - Read-only File System、Compression、Similarity Graph、Container Image、Read Amplification

- [ACOS: Apple’s Geo-Distributed Object Store at Exabyte Scale](https://www.usenix.org/conference/fast26/presentation/baron)
  - Benjamin Baron, Aline Bousquet, Eric Metens, Swapnil Pimpale, Nick Puz, Marc de Saint Sauveur, Varsha Muzumdar, and Vinay Ari, Apple Deployed-Systems Paper
  - ACOS 是 Apple 运行十余年的 exabyte object store，面向备份、照片/视频、音乐、直播等异质访问。系统组合 local 与 regional replication，在不同故障域按 durability/latency/cost 放置对象；论文给出从硬件故障到 data-center outage 的生产恢复与每天数十亿请求的规模数据。
  - 相较 clean-slate object-store prototype，核心贡献是展示 exabyte、多业务、跨地域系统如何分层复制并在十年演进中维持成本、可用性和耐久性。
  - Geo-distributed Object Store、Exabyte Scale、Replication、Durability、Apple Production

- [SolidAttention: Low-Latency SSD-based Serving on Memory-Constrained PCs](https://www.usenix.org/conference/fast26/presentation/zheng)
  - Xinrui Zheng, Dongliang Wei, Jianxiang Gao, Yixin Song, Zeyu Mi, and Haibo Chen, Shanghai Jiao Tong University
  - SolidAttention 在内存有限 AIPC 本地跑 128K-context LLM，将大部分 KV 放 SSD。动态 sparse-attention 只需少量历史 token；系统把相关 KV 合成粗 block 以吃满 SSD bandwidth，依据时间局部性 speculative prefetch，并在 attention synchronization point 重叠 compute/I/O，内存占用降 98%、推理快最高 3.1 倍。
  - 相较简单 KV offload 产生细碎随机 I/O，核心创新是联合改变 attention sparsity、KV block layout 和预取时机，让算法需要的数据形状与 SSD 访问粒度一致。
  - Local LLM Inference、SSD KV Cache、Sparse Attention、Speculative Prefetch、AIPC

- [CacheSlide: Unlocking Cross Position-Aware KV Cache Reuse for Accelerating LLM Serving](https://www.usenix.org/conference/fast26/presentation/liu-yang)
  - Yang Liu and Yunfei Gu, Shanghai Jiao Tong University; Liqiang Zhang, Jinan Inspur Data Technology Co., Ltd; Chentao Wu, Guangtao Xue, Jie Li, and Minyi Guo, Shanghai Jiao Tong University; Junhao Hu, Peking University; Jie Meng, Huawei Cloud
  - CacheSlide 针对 Agent prompt 中固定 instruction/tool/schema 片段绝对位置会随动态 history 移动、但相对顺序不变的 RPDC。它调整固定段 positional encoding，只重算受 position drift 影响的少量 token，再以 learned weight 校正/融合 cached KV，并按 layer/spill 管理 vLLM cache，agent benchmark 延迟降 3.11–4.3 倍。
  - 相较 PDC 要求绝对位置相同、PIC 全面校正代价高，核心创新是识别 agent workflow 的相对位置不变量，并为这一中间语义设计最小重算。
  - Agent Infra、Agent Prompt、KV Cache Reuse、Relative Position、LLM Serving

- [Bidaw: Enhancing Key-Value Caching for Interactive LLM Serving via Bidirectional Computation–Storage Awareness](https://www.usenix.org/conference/fast26/presentation/hu-shipeng)
  - Shipeng Hu and Guangyan Zhang, Tsinghua University; Yuqi Zhou, China University of Geosciences Beijing; Yaya Wei and Ziyan Zhong, China Telecom Omni-channel Operation Center; Jike Chen, Tsinghua University
  - Bidaw 管 multi-round conversation 的 host-DRAM+SSD KV。compute scheduler 按 KV 所在 tier 分组 request、再按加载量重排，避免大 SSD read 阻塞小内存命中；storage eviction 从 LLM 已生成 response 预测用户下一轮会访问哪些会话，并只缓存 storage-efficient history tensor，延迟降最高 3.58 倍。
  - 相较 serving scheduler 不知道 cache I/O、storage policy 又不知道对话语义，核心创新是双向暴露 request computation 与 conversation-derived access signal，联合排队和淘汰。
  - Interactive LLM Serving、Two-tier KV Cache、Storage-aware Scheduling、Conversation Prediction、SSD

- [Accelerating Model Loading in LLM Inference by Programmable Page Cache](https://www.usenix.org/conference/fast26/presentation/liu-yubo)
  - Yubo Liu, Hongbo Li, Xiaojia Huang, Yongfeng Wang, Hanjun Guo, Hui Chen, Yuxin Ren, and Ning Jia, Huawei Technologies Co., Ltd.
  - PPC 在 Linux kernel page cache 提供非侵入、可编程 policy hook；其 MAIO policy 为 LLM model load 学习/记录 I/O template，按 XPU affinity 和 tensor/data locality 做 prefetch/eviction并形成足够并发 SSD request。无需修改模型格式或 inference framework，startup latency 最多降 79%。
  - 相较绕过文件系统的专用 loader 快但兼容性差，核心创新是把 model-aware loading policy 注入通用 page cache，保留 POSIX/框架路径。
  - LLM Model Loading、Programmable Page Cache、I/O Template、XPU Affinity、Elastic Inference

- [OdinANN: Direct Insert for Consistently Stable Performance in Billion-Scale Graph-Based Vector Search](https://www.usenix.org/conference/fast26/presentation/guo)
  - Hao Guo and Youyou Lu, Tsinghua University
  - OdinANN 在 billion-scale on-disk graph ANNS 中把新 vector 直接渐进插入主 graph，而非内存积累后大批 merge。更新工作均匀分散、限制每次修改邻接关系，使 frontend search 不再遭周期性 merge stall，在固定 insert rate 下维持稳定 latency/QPS。
  - 相较 buffer-and-merge 获得高写吞吐却产生明显 search performance cliff，核心创新是把 direct insert 设计为可持续小扰动，优先稳定在线服务。
  - Vector Search、Graph ANNS、Direct Insert、Performance Stability、Billion-scale Index

- [DMTree: Towards Efficient Tree Indexing on Disaggregated Memory via Compute-side Collaborative Design](https://www.usenix.org/conference/fast26/presentation/wei)
  - Guoli Wei, University of Science and Technology of China; Yongkun Li, University of Science and Technology of China and Anhui Provincial Key Laboratory of High Performance Computing, USTC; Haoze Song, The University of Hong Kong; Tao Li and Lulu Yao, University of Science and Technology of China; Yinlong Xu, University of Science and Technology of China and Anhui Provincial Key Laboratory of High Performance Computing, USTC; Heming Cui, The University of Hong Kong Distinguished Artifact Award Winner
  - DMTree 让多个 compute server 不再各自维护私有 cache、共同轰击 memory server RDMA IOPS。compute 节点协作承担 tree node locating 与 locking，并通过 compute↔compute RDMA 共享/转移 cached state，memory server 主要保存数据；利用原本闲置的横向带宽缓解集中瓶颈，支持 point/range operation。
  - 相较所有 disaggregated index 优化 memory-side one-sided access，核心创新是引入 compute-side collaborative plane，把 cache coherence/lock traffic 从 memory fabric 横移。
  - Disaggregated Memory、Tree Index、Collaborative Cache、RDMA、Range Query

- [An Efficient Cloud Storage Model with Compacted Metadata Management for Performance Monitoring Timeseries Systems](https://www.usenix.org/conference/fast26/presentation/zhang-kai)
  - Kai Zhang, The Chinese University of Hong Kong; Tianyu Wang, Shenzhen University; Zili Shao, The Chinese University of Hong Kong
  - CloudTS 为 performance-monitoring time series 将 global tag/string 存入单一 dictionary，用二维 bitmap 表示 series↔tag mapping，避免每 series 重复 metadata并快速执行 tag filter；压缩 data chunk 按 series group 放 S3 object，保持 time-partition query model。生产数据查询平均比 Cortex 快 1.37 倍。
  - 相较通用 Parquet/JSON 或每租户重复 tag index，核心创新是将 monitoring 查询语义编码进全局压缩 metadata，再配合 object layout。
  - Time-series Storage、Cloud Object Storage、Metadata Compaction、Tag Query、Performance Monitoring

- ["Range as a Key" is the Key! Fast and Compact Cloud Block Store Index with RASK](https://www.usenix.org/conference/fast26/presentation/zhao)
  - Haoru Zhao, Mingkai Dong, and Erci Xu, Shanghai Jiao Tong University; Zhongyu Wang, Alibaba Group; Haibo Chen, Shanghai Jiao Tong University
  - RASK 根据 cloud block trace 中 write 常覆盖连续 LBA range 的现象，直接以 range 为 tree key，而非每 block 一个 mapping。log-structured leaf 高效吸收 overlap，range-tailored search/GC 解析最新覆盖；range-aware split/merge 防 update 后碎片化，内存最高少 98.9%、吞吐高 31 倍。
  - 相较压缩 per-block index 仍忽略连续性，核心创新是从索引语义层把连续区间变成原生 key，并为重叠/碎片重设 tree maintenance。
  - Cloud Block Storage、Range Index、Log-structured Leaf、Metadata Memory、Production Trace

- [Holistic and Automated Task Scheduling for Distributed LSM-tree-based Storage](https://www.usenix.org/conference/fast26/presentation/ren)
  - Yuanming Ren, Siyuan Sheng, and Zhang Cao, The Chinese University of Hong Kong; Yongkun Li, University of Science and Technology of China; Patrick P. C. Lee, The Chinese University of Hong Kong
  - HATS 在 Cassandra 同时调 foreground read 与必要但会干扰的 compaction。coarse replica selector 先按 node load 分配，fine selector 再避开当前 compaction/data hotspot；compaction rate controller 依据 read latency/load 自适应加减速，兼顾未来 read amplification 与当前 tail latency。
  - 相较 read load balancing 与 compaction throttling 两套 controller 独立、相互制造波动，核心创新是把 replica choice 与 background rate 放入同一反馈调度框架。
  - Distributed LSM-tree、Cassandra、Read Scheduling、Compaction Control、Tail Latency

- [Preparation Meets Opportunity: Enhancing Data Preprocessing for ML Training With Seneca](https://www.usenix.org/conference/fast26/presentation/desai)
  - Omkar Desai, Syracuse University; Ziyang Jiao, Huaibei Normal University; Shuyi Pei, Samsung Semiconductor; Janki Bhimani, Florida International University; Bryan S. Kim, Syracuse University
  - Seneca 为并发 ML training job 的 data pipeline 将 cache 在 encoded、decoded、augmented 三种形态间按 performance model 分区；random batch sampling 时在不破坏统计需求的范围内优先选择其他 job 已缓存 sample，让工作共享解码/增强结果。PyTorch makespan 降 45.23%、处理吞吐最高增 3.45 倍。
  - 相较只缓存原图或每 job 独立随机采样，核心创新是把数据处理阶段和跨作业缓存机会共同纳入 sample selection/cache allocation。
  - ML Data Pipeline、Data Loader、Multi-form Cache、Opportunistic Sampling、Concurrent Training

- [GPU Checkpoint/Restore Made Fast and Lightweight](https://www.usenix.org/conference/fast26/presentation/zeng)
  - Shaoxun Zeng, Tingxu Ren, Jiwu Shu, and Youyou Lu, Tsinghua University Distinguished Artifact Award Winner
  - GCR 为任意 GPU application 做系统级透明 checkpoint/restore。control/data separation 只在 checkpoint 时捕获必要 GPU control state，大 buffer 走高效数据路径；CPU shadow execution 重放轻量 instruction/control，生成 fine-grained dirty template 找出真正变化的 GPU buffer，实现 incremental checkpoint，正常执行开销低于 1%。
  - 相较全量扫描 GPU memory 或持续 dirty tracking，核心创新是用 CPU 影子执行预测写集合，将昂贵追踪从 GPU normal path 移出。
  - GPU Checkpoint/Restore、Shadow Execution、Incremental Checkpoint、Dirty Template、Elastic GPU

- [Fast Cloud Storage for AI Jobs via Grouped I/O API with Transparent Read/Write Optimizations](https://www.usenix.org/conference/fast26/presentation/hao)
  - Yingyi Hao, Shanghai Jiao Tong University; Ting Yao, Huawei Cloud; Xingda Wei, Dingyan Zhang, and Tianle Sun, Shanghai Jiao Tong University; Yiwen Zhang, Zhiyong Fu, and Huatao Wu, Huawei Cloud; Rong Chen, Shanghai Jiao Tong University
  - AITURBO 为 AI checkpoint/KV 读写暴露 grouped I/O API，让应用只声明一组相关对象/范围和语义，storage layer 看到全局后自动生成并发、聚合、placement 和 read/write plan；还借 accelerator 间高带宽 compute fabric 转发 storage traffic，突破单 host storage link，无需 Megatron/Mooncake 大量定制代码。
  - 相较每个 AI framework 自己手写 I/O 优化、storage 只见碎片请求，核心创新是以 grouped I/O 作为应用意图与存储全局调度之间的窄接口。
  - AI Cloud Storage、Grouped I/O、Checkpoint、KV Cache、Compute Fabric

- [AdaCheck: An Adaptive Checkpointing System for Efficient LLM Training with Redundancy Utilization](https://www.usenix.org/conference/fast26/presentation/liu-weijie)
  - Weijie Liu, Shengwei Li, Zhiquan Lai, and Keshi Ge, National University of Defense Technology; Qiaoling Chen, Nanyang Technological University; Peng Sun, Shanghai AI Laboratory; Dongsheng Li and Kai Lu, National University of Defense Technology
  - AdaCheck 用 tensor redundancy 抽象描述 DP/TP/PP、dense/MoE 和不规则自动并行中哪些 model/optimizer state 是副本或可重建。hash consistency check+ring communication 自动检测冗余，offline 只保存最小代表集合；online 又利用相邻 iteration 未变/可推导状态，checkpoint size 少 6–896 倍。
  - 相较 checkpoint 方案绑定特定 parallelism 并保存所有 state，核心创新是统一、可检测的 tensor-level redundancy model，覆盖架构和时间两个维度。
  - LLM Training、Adaptive Checkpoint、Tensor Redundancy、Parallelism-agnostic、State Deduplication

- [Sharpen the Spec, Cut the Code: A Case for Generative File System with SYSSPEC](https://www.usenix.org/conference/fast26/presentation/liu-qingyuan)
  - Qingyuan Liu, Mo Zou, Hengbin Zhang, Dong Du, Yubin Xia, and Haibo Chen, Shanghai Jiao Tong University Awarded Best Paper! Distinguished Artifact Award Winner
  - SYSSPEC 用 functionality 的 Hoare pre/post/invariant、module 的 rely-guarantee、concurrency 的 lock/order 组成多部分规范。SpecCompiler Agent 两阶段生成逻辑和并发 C 代码，SpecValidator Agent 对照规范/回归测试检查并把错误反馈给生成器重试；DAG spec patch 传播新 feature 后再生成，构建可演化 concurrent SPECFS。
  - 相较一次性让 LLM 从自然语言/整个代码库写文件系统，核心创新是把规格作为 Agent 可执行蓝图和验证 oracle，形成 generation–validation–feedback 闭环，并让演化发生在 spec 层。
  - Agent for Systems、Generative File System、Specification-guided Coding、Multi-agent Validation、Feedback Loop

- [Cylon: Fast and Accurate Full-System Emulation of CXL-SSDs](https://www.usenix.org/conference/fast26/presentation/yoon)
  - Dongha Yoon, Hansen Idden, Jinshu Liu, Berkay Inceisci, Sam H. Noh, and Huaicheng Li, Virginia Tech
  - Cylon 在 FEMU 上模拟 CXL-SSD 的 memory-like cache hit 与落 NAND miss。hybrid execution 让常见 sub-μs hit 避开昂贵 hypervisor trap，复杂 miss 才进入完整设备模型；cache policy 可替换，application 原样运行。以真实 prototype 校准后重现 latency distribution且接近 bare-metal speed。
  - 相较 closed hardware 难实验、纯软件逐访问 trap 太慢，核心创新是按 CXL-SSD fast/slow path 分裂模拟精度与执行方式，兼得 full-system fidelity 和速度。
  - CXL-SSD、Full-system Emulation、Hybrid Execution、Cache Policy、Hardware-Software Co-design

- [Xerxes: Extensive Exploration of Scalable Hardware Systems with CXL-Based Simulation Framework](https://www.usenix.org/conference/fast26/presentation/an)
  - Yuda An and Shushu Yi, Peking University; Bo Mao, Xiamen University; Qiao Li, Mohamed bin Zayed University of Artificial Intelligence; Mingzhe Zhang, Institute of Information Engineering, Chinese Academy of Sciences; Diyu Zhou, Peking University; Ke Zhou, Huazhong University of Science and Technology (HUST); Nong Xiao, Sun Yat-sen University; Guangyu Sun, Yingwei Luo, and Jie Zhang, Peking University
  - Xerxes 从 interconnect layer 起完整模拟最新 CXL 的 port-based routing、device-managed coherence、PCIe 6.0 与 CPU/accelerator/memory device 拓扑。研究者可组合 switch/port/device component，实验不同 topology、coherence owner 和 link characteristic 对 scalability/peer-to-peer 的影响。
  - 相较旧 simulator 只把 CXL 当低延迟 memory link，核心创新是显式建模新协议的路由与 device coherence component，支持尚无硬件的体系探索。
  - CXL Simulation、Device-managed Coherence、Port Routing、PCIe 6.0、Heterogeneous System

- [Characterizing and Emulating FDP SSDs with WARP](https://www.usenix.org/conference/fast26/presentation/song)
  - Inho Song and Shoaib Asif Qazi, Virginia Tech; Javier González, Samsung Electronics; Matias Bjørling, Western Digital; Sam H. Noh and Huaicheng Li, Virginia Tech
  - WARP 对多款 FDP SSD 和 workload 系统测量 RUH placement：对象 lifetime 分类准确时 WAF 接近 1，misclassification、RUH 互扰或 adversarial invalidation 时优势消失。开源 emulator 重现硬件 WAF并暴露不可见的 per-RUH state，可替换 firmware policy继续探索。
  - 相较依据单设备/单 trace 宣称 FDP 有效，核心贡献是同时给出跨设备边界条件与透明 emulator，把经验现象提升为可重复的 policy 研究平台。
  - FDP SSD、Write Amplification、Reclaim Unit Handle、Storage Emulation、Workload Characterization

- [ScaleSwap: A Scalable OS Swap System for All-Flash Swap Arrays](https://www.usenix.org/conference/fast26/presentation/ahn)
  - Taehwan Ahn, Chanhyeong Yu, Sangjin Lee, and Yongseok Son, Chung-Ang University
  - ScaleSwap 在 128-core、8 NVMe all-flash swap array 上让每个 core 独占 swap slot/metadata和 I/O queue，避免全局锁；本核忙时可把 metadata access 委托其他 core opportunistic assist；page/LRU 也保持 core affinity。相对 Linux swap throughput 高 3.4 倍、平均 latency 低 11.5 倍。
  - 相较只增加更多 SSD queue、上层 swap metadata/LRU 仍串行，核心创新是端到端 one-core–one-swap-resource ownership，并以协助机制处理不均衡。
  - Linux Swap、All-flash Array、Per-core Resource、LRU Contention、Scalability

- [DPAS: A Prompt, Accurate and Safe I/O Completion Method for SSDs](https://www.usenix.org/conference/fast26/presentation/seo)
  - Dongjoo Seo, University of California, Irvine; Jihyeon Jung and Yeohwan Yoon, Kookmin University; Ping-Xiang Chen, University of California, Irvine; Yongsoo Joo and Sung-Soo Lim, Kookmin University; Nikil Dutt, University of California, Irvine
  - DPAS 在 SSD I/O completion 时动态选择纯 polling、interrupt 或 PAS hybrid。PAS 用最近两次 I/O latency 快速估本次完成时间、睡到临近后 poll；DPAS 再根据 CPU contention 与 I/O interference 判断预测是否值得，避免固定 hybrid sleep 对延迟突变不适应，也减少 context switch。
  - 相较在所有负载固定 polling/interrupt 或用长历史平均 hybrid polling，核心创新是两点即时延迟追踪加机制级动态切换，同时控制响应和 CPU。
  - SSD I/O Completion、Dynamic Polling、Interrupt、Latency Prediction、CPU Contention

- [How Soon is Now? Preloading Images for Virtual Disks with ThinkAhead](https://www.usenix.org/conference/fast26/presentation/chen)
  - Xinqi Chen, Shanghai Jiao Tong University; Yu Zhang, Alibaba Group; Erci Xu, Shanghai Jiao Tong University; Changhong Wang, Jifei Yi, Qiuping Wang, Shizhuo Sun, and Zhongyu Wang, Alibaba Group; Haonan Wu, Shanghai Jiao Tong University; Junping Wu, Hailin Peng, Rong Liu, Yinhu Wang, Jiaji Zhu, and Jiesheng Wu, Alibaba Group; Guangtao Xue, Shanghai Jiao Tong University; Shanghai Key Laboratory of Trusted Data Circulation, Governance and Web3; Patrick P.
