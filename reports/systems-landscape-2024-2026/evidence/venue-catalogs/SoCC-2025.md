# SoCC 2025 论文列表

ACM SoCC 2025 正式 Proceedings（DOI 前缀 `10.1145/3772052`）共收录 67 篇论文。标题链接指向 DOI 官方文章页；已找到的 18 份合法公开 PDF 保存在 `reference/SoCC/2025/`。

- [Funky: Cloud-Native FPGA Virtualization and Orchestration](https://doi.org/10.1145/3772052.3772226)
  - Technical University of Munich, Munich, Germany；Atsushi Koshiba、Charalampos Mainas、Pramod Bhatotia
  - Funky 面向需要在 Kubernetes 中运行 FPGA 加速任务的云原生集群：它把 FPGA 封装为带 hypervisor 隔离的轻量 sandbox，保存设备状态以支持抢占与 checkpoint，并按 CRI/OCI 接口把分布式 FPGA 纳入容器编排。系统以任务需求和设备可用性做调度，在仅约 7.4% 原生性能开销下提供隔离、迁移、容错与弹性。
  - 相较只能把 FPGA 作为独占外设直通给容器、缺少抢占和故障恢复的做法，核心创新是同时补齐 FPGA 虚拟化、可恢复状态管理和云原生编排这一整条控制路径。
  - Cloud-native FPGA、设备虚拟化、抢占与检查点、Kubernetes 调度、异构加速器

- [Scalable and Fault-Tolerant Storage and File System Services with Non-Blocking Synchronization for Private Clouds](https://doi.org/10.1145/3772052.3772235)
  - Virginia Tech, Blacksburg, VA, USA；The Pennsylvania State University, University Park, PA, USA；Mincheol Sung、Ruslan Nikolaev、Binoy Ravindran
  - 该工作为私有云中跨 VM 共享文件设计 storage service 与 file-system service：两者以 Xen unikernel 运行，应用 VM 通过无锁并发 ring buffer 传输请求，文件路径尽量避免数据复制，存储服务还可复用 NetBSD 驱动并在崩溃后透明恢复状态。原型在保持可扩展和容错的同时达到接近 Linux 的 I/O 性能。
  - 相较把存储驱动、文件系统和恢复逻辑留在单个 VM 内，核心创新是用非阻塞 inter-VM 通道把它们服务化，并让同一无锁结构同时支撑正常数据面与有状态故障恢复。
  - Private Cloud Storage、Unikernel、Cross-VM File Sharing、Lock-free IPC、Fault Recovery

- [Towards a Lightweight Sidecar-based Service Mesh for Serverless](https://doi.org/10.1145/3772052.3772210)
  - ETH Zurich, Zurich, Switzerland；Lazar Cvetković、Ana Klimovic
  - 该研究测量 Istio、Linkerd 在高调用率、短生命周期函数下的 sidecar 和网络策略更新开销：生产轨迹中 Istio 可令 p95 端到端时间上升 38.3 倍、节点 p95 CPU 上升 3.9 倍。作者定位控制面策略 churn 与 sidecar churn 的瓶颈，并据此提出面向 serverless 的轻量 sidecar 重构方向。
  - 相较沿用面向长驻微服务的 service mesh 设计，核心贡献是用 serverless 特有的函数/策略高 churn 负载揭示失效机制，并把轻量、快速重配置的 sidecar 明确为新的设计对象。
  - Serverless Service Mesh、Sidecar Churn、Network Policy、Tail Latency、性能测量

- [Orcas: A DAG-based Consensus Approach with Linear Communication Overhead](https://doi.org/10.1145/3772052.3772238)
  - Tianjin University, Tianjin, China；Department of Computer Science, North Carolina State University, Raleigh, NC, USA, Raleigh, USA；Peking University, Beijing, China；Yi Hua、Xiulong Liu、Hao Xu、Chenyu Zhang、Gaowei Shi、Keqiu Li、Muhammad Shahzad、Guyue (Grace) Liu
  - Orcas 面向异步 DAG 区块链共识，把交易传播和投票分别重构：delay-aware 冗余 DHT 根据链路时延与带宽选择 r 个存储副本，Votable Broadcast 由 leader 聚合并分发投票证书，再用三轮异步提交给出可预测确认延迟。它把单副本端到端通信从二次量级降为线性，并在跨四洲部署中提高吞吐、降低时延与消息量。
  - 相较只优化 DAG 数据传播或投票中的一个环节，核心创新是同时使交易分发和共识投票线性化，从而得到端到端每副本 O(N) 的 DAG 共识。
  - DAG Consensus、Asynchronous BFT、Redundant DHT、Vote Aggregation、Blockchain Networking

- [Water Footprint of Datacenter Applications: Methodological Implications of Manufacturing, Operational, and Decommissioning Phases](https://doi.org/10.1145/3772052.3772216)
  - University of Utah, Salt Lake City, UT, USA；Northeastern University, Boston, Massachusetts, USA；Amit Samanta、Yankai Jiang、Ryan Stutsman、Rohan Basu Roy
  - 该工作比较数据中心应用全生命周期的耗水核算口径，不只计冷却和发电的运营用水，还纳入服务器制造与退役，并分析区域水资源差异如何改变工作负载放置结论。结果表明水感知调度必须同时考虑地域、时段和生命周期边界，否则不同方法会给出不一致甚至相反的优化信号。
  - 相较只用实时 WUE 或运营期用水给任务排序，核心创新是揭示制造—运行—退役边界选择对调度决策的系统性影响，并提出标准化全生命周期核算需求。
  - Datacenter Water Footprint、Lifecycle Accounting、Water-aware Scheduling、Sustainable Cloud

- [PowerTrip: Exploiting Federated Heterogeneous Datacenter Power for Distributed ML Training](https://doi.org/10.1145/3772052.3772228)
  - UMassAmherst, Amherst, USA；Pacific Northwest National Laboratory, Richland, Washington, USA；University of Massachusetts Amherst, Amherst, Massachusetts, USA；Talha Mehboob、Luanzheng Guo、Nathan R. Tallent、Michael Zink、David Irwin
  - PowerTrip 服务于受区域电网功率上限约束、跨多个地理站点的大模型分布式训练。系统持续读取各站点可用功率和站点间网络时延，以“高功率/低通信成本”启发式选择参与站点，再按新增站点带来的单位时间精度增益决定何时停止扩张；在 Google 功率轨迹下最多缩短 50% time-to-accuracy。
  - 相较假设各数据中心供电恒定、只压缩通信或静态选择站点的跨地域训练，核心创新是把动态异构供电与 WAN 通信的边际收益放进同一在线站点选择回路。
  - Distributed Model Training、Geo-distributed Datacenters、Power-aware Scheduling、Site Selection、Time-to-accuracy

- [Balancing Fairness and Performance in Multi-User Spark Workloads with Dynamic Scheduling](https://doi.org/10.1145/3772052.3772214)
  - Delft University of Technology, Delft, Netherlands；ASML, Veldhoven, Netherlands；Dāvis Kažemaks、Laurens Versluis、Burcu Kulahcioglu Ozkan、Jérémie Decouchant
  - UWFQ 面向多人共享的长期 Spark 应用，以用户而非作业作为公平主体：它模拟虚拟公平队列，根据各作业在有界公平模型下的预计完成时刻选取下一作业，并按预计 task 时长动态细分 partition，减轻 skew 和优先级反转。生产式轨迹中小作业平均响应时间最多下降 74%。
  - 相较按 job 数量分配资源、使提交更多作业的用户占优的公平调度，核心创新是把用户级虚拟完成时间与运行时任务重分区结合，在一个调度器中同时控制公平和短作业时延。
  - Apache Spark、Multi-user Fairness、Virtual Fair Queuing、Runtime Partitioning、Job Scheduling

- [Accelerating Distributed Filesystem Metadata Service via Decoupling Directory Semantics from Metadata Indexing](https://doi.org/10.1145/3772052.3772237)
  - Tsinghua University, Beijing Shi, China；Wenhao Lv、Hao Guo、Qing Wang、Youyou Lu、Jiwu Shu
  - HMFS 面向持久内存和高速网络下的分布式文件系统 metadata service，把目录语义从有序元数据索引中拆开：对象用无序索引快速定位，目录顺序/遍历关系由对象间直接链接保存；轻量事务保证两套结构崩溃一致，并并行执行目录枚举。系统在数百亿文件规模仍可保持千万级 metadata ops/s。
  - 相较为了支持 readdir 而让所有 metadata 操作都经过高开销有序索引，核心创新是以独立链接维护目录语义，使查找索引可以无序化而不牺牲 POSIX 目录行为和崩溃一致性。
  - Distributed File-system Metadata、Persistent Memory、Index Decoupling、Crash Consistency、Parallel Directory Listing

- [DuoAdmit: Dual-Layer Cache Admission for Load-Balancing Hybrid-Redundancy Block Storage](https://doi.org/10.1145/3772052.3772223)
  - Huazhong University of Science an Technology, Wuhan, China；Tencent Technology Co., Ltd., Shenzhen, China；Xiaojun Guo、Guangjie Xing、Hua Wang、Ke Zhou、Ming Xie、Fenqiang Yang、Min Fu、Bin Xu、Jianying Hu、Guangchao Yang
  - DuoAdmit 用于复制缓存加纠删码底层的混合冗余云块存储。上层根据各存储节点实时负载和故障状态自适应设定每节点 admission ratio，下层在 I/O 路径按 cache value 决定具体 block 是否进入复制缓存，使比例真正落地并抑制跨网流量放大；多节点故障时吞吐最多提高 51.2%。
  - 相较所有节点使用固定缓存准入规则，核心创新是把跨节点负载平衡和节点内对象价值做成相互约束的双层 admission，而非在故障后再被动迁移数据。
  - Cloud Block Storage、Hybrid Redundancy、Cache Admission、Failure-aware Load Balancing、I/O Amplification

- [Understanding GPU Resource Interference One Level Deeper](https://doi.org/10.1145/3772052.3772270)
  - ETH Zurich, Zurich, Switzerland；University of Toronto, Toronto, Canada；Paul Elvinger、Foteini Strati、Natalie Enright Jerger、Ana Klimovic
  - 该工作把 GPU 共置干扰细分到 block scheduler、计算单元、L1/L2 cache 和显存带宽等微结构资源，并通过受控压力负载分别量化每个应用对各类争用的敏感度。得到的 interference profile 可供调度器判断哪些 kernel 能安全同置并为租户提供性能下界，而不是只依据平均 GPU utilization。
  - 相较把 GPU 当成单一算力/显存二维资源，核心创新是给出可分离、可测量的细粒度干扰敏感性方法，为带严格性能保证的 kernel 共置建立资源模型。
  - GPU Colocation、Microarchitectural Interference、Resource Sensitivity、Performance Isolation、GPU Scheduling

- [Snap & Replay: A new way to analyze uarch-scale performance bottlenecks for ML accelerators](https://doi.org/10.1145/3772052.3772233)
  - Columbia University, New York, USA；University of California, San Diego, San Diego, USA；University of Washington, Seattle, USA；Google, Sunnyvale, USA；Ioannis Zarkadas、Amanda Tomlinson、Asaf Cidon、Baris Kasikci、Ofir Weisse
  - Snap & Replay 从生产 TPU 部署截取机器码级执行 trace，在硬件设计阶段使用的微架构 simulator 中重放，不改硬件、模型或编译流程即可定位 LLM kernel、通信 collective 和 memory pipeline 的低层瓶颈。其诊断促成 collective 最多 15% 优化，并把生产 LLM token 生成时延降低最多 4.1%。
  - 相较只能看到 op/kernel 聚合指标的 profiler，核心创新是反向利用硬件微架构模拟器，把真实生产 trace 映射到可行动的指令级软件优化建议。
  - ML Accelerator Profiling、Trace Replay、TPU Microarchitecture、LLM Inference Diagnosis、Hardware-software Co-design

- [Offloading Cloud-Native Infrastructure with XpuPod](https://doi.org/10.1145/3772052.3772211)
  - Institute of Parallel and Distributed Systems, Shanghai Jiao Tong University, Shanghai, China；Bicheng Yang、Jingkai He、Dong Du、Yubin Xia、Haibo Chen
  - XpuPod 把 service mesh、监控 agent 等基础设施容器从主机 CPU 卸载到 DPU，同时让应用进程无需修改。它提供跨 CPU/DPU 的统一透明网络抽象，并用弹性通信机制避免固定 pin 内存/核的成本；基于该抽象的 XpuK8s 决定哪些组合式基础设施容器适合卸载，在 BlueField-2 上降低端到端时延并提高集群扩展性。
  - 相较为每种基础设施服务单独重写 DPU datapath，核心创新是建立可承载普通进程和容器的通用 cross-XPU Pod/网络抽象，使控制面能够组合、放置并隔离未修改的云原生组件。
  - DPU Offloading、Cloud-native Infrastructure、Cross-XPU Networking、Kubernetes、Resource Isolation

- [Valet: Efficient Data Placement on Modern SSDs](https://doi.org/10.1145/3772052.3772256)
  - University of California, Santa Cruz, Santa Cruz, CA, USA；Emory University, Atlanta, GA, USA and Cloudflare, San Francisco, CA, USA；Pure Storage, Santa Clara, CA, USA and University of California, Santa Cruz, Santa Cruz, CA, USA；Devashish R. Purandare、Peter Alvaro、Avani Wildani、Darrell D. E. Long、Ethan L. Miller
  - Valet 以用户态 shim 观察 RocksDB、MongoDB、CacheLib 等日志结构应用的数据生命周期，动态生成 placement hint 并把不同寿命/更新模式的数据映射到现代 SSD 的合适区域。它不修改应用、文件系统或内核即可获得应用定制放置的收益，写吞吐提高 2–4 倍并降低尾延迟。
  - 相较要求应用适配 open-channel/stream SSD 接口的方案，核心创新是在稳定存储栈之外透明推断和注入 placement hint，使同一策略可跨设备接口和多租户应用复用。
  - SSD Data Placement、Userspace Shim、Placement Hints、Log-structured Workloads、Storage Tail Latency

- [ParaLog: Consistent Host-side Logging for Parallel Checkpoints](https://doi.org/10.1145/3772052.3772212)
  - University of Edinburgh, Edinburgh, United Kingdom；RIKEN R-CCS, Kobe, Japan；KTH Royal Institute of Technology, Stockholm, Sweden；Steven W. D. Chien、Kento Sato、Artur Podobas、Niclas Jansson、Stefano Markidis、Michio Honda
  - ParaLog 面向云中远端存储带宽不足的 MPI 科学应用，在各计算主机把并行 checkpoint 先写入分布式 host-side log，再按应用同步点和持久化语义协调回写。它对未修改 MPI 应用透明，同时保持 crash consistency，在 cloud/HPC/hybrid 环境将端到端执行时间降低 13%–26%。
  - 相较通用 block/file cache 无法理解并行 checkpoint 的跨进程一致性，核心创新是用面向 MPI 输出阶段的协调日志协议，把本地带宽聚合和全局崩溃一致性同时纳入缓存路径。
  - MPI Checkpointing、Host-side Logging、Cloud HPC、Crash Consistency、I/O Acceleration

- [DyOrc: Efficient Serving of Dynamic Machine Learning Workflows](https://doi.org/10.1145/3772052.3772218)
  - The University of Hong Kong, Hong Kong, Hong Kong；Alibaba Group, Beijing, China；Shiwei Zhang、Lansong Diao、Zisheng Meng、Siyu Wang、Wei Lin、Chuan Wu
  - DyOrc 服务由基础模型和工具组件条件组合而成的动态 AI 工作流，粒度是单个请求 DAG 中按中间结果才决定是否执行的 model stage。它把共享模型拆成可独立扩缩的服务，依据运行统计推测后续分支并提前排队/批处理，用同进程与专用 tensor 通道传递异构消息，并主动加载可能调用的大模型以隐藏冷启动；覆盖多模态 chatbot、ensemble、图像流水线和 multi-agent debate。
  - 相较 Ray Serve/Triton 把工作流当通用 DAG、只能在分支真正触发后调度，核心创新是用分支预测联动跨工作流动态 batching、模型预加载和 GPU tensor 通信，使条件执行仍能形成有效批次。
  - Agent Infra、Compound AI Workflow Serving、Conditional DAG、Speculative Scheduling、Cross-workflow Batching、Model Cold Start

- [DRAM Failure Prediction with Correctable Error Spatial Patterns: A Hybrid Learning Approach](https://doi.org/10.1145/3772052.3772234)
  - Inspur Cloud Information Technology Co., Ltd., Jinan, China；JINAN THERMAL POWER GROUP CO. LTD, Jinan, China；Lei Liu、Yinling Zhang
  - 该工作把 DIMM 的 correctable error 地址重排为三维空间特征图，经 3D CWT-PCA 提取空间模式，再将人工统计特征与 ResNet、KAN 的表征做混合学习，预测云服务器后续 DRAM failure。SHAP 用于解释关键错误模式，并用公开大规模数据和真实云中心数据检查跨环境泛化。
  - 相较只统计 CE 次数或时间序列，核心创新是显式保留 bank/row/column 等错误空间结构，并把可解释人工特征与深度网络表征融合用于故障预警。
  - DRAM Failure Prediction、Correctable Error Pattern、3D CWT-PCA、Hybrid Learning、Cloud Reliability

- [CIS: Checkpointed Inference for Data Drift-Resilient Model Serving at Edge Servers](https://doi.org/10.1145/3772052.3772261)
  - University of Virginia, Charlottesville, USA；Microsoft, Redmond, USA；Sudipta Saha Shubha、Haiying Shen、Ganesh Ananthanarayanan
  - CIS 面向边缘服务器上因数据漂移需要持续重训练的小模型，在 inference 与 retraining 争抢有限 GPU 时，把新训练过程的中间 checkpoint 持续切换为在线服务模型。调度器联合安排 checkpoint 放置、样本重排和临时 GPU 空间回收，以减少切换和请求排队；在不降低 SLO 命中率下最高提高 25.1% 准确率。
  - 相较等一轮重训练完成才整体替换模型，核心创新是把训练中间状态变成可立即服务的版本，并围绕频繁版本切换联合优化显存、样本顺序与推理排队。
  - Edge Model Serving、Continual Learning、Data Drift、Checkpointed Inference、GPU Co-scheduling

- [CPU-Limits kill Performance: Time to rethink Resource Control](https://doi.org/10.1145/3772052.3772219)
  - University of Illinois Urbana-Champaign, Urbana-Champaign, Illinois, USA；IBM Research, Yorktown Heights, New York, USA；Chirag C. Shetty、Sarthak Chakraborty、Hubertus Franke、Larisa Shwartz、Chandra Narayanaswami、Indranil Gupta、Saurabh Jha
  - 该测量研究检验 Kubernetes CPU limit 对 latency-sensitive container 的实际作用，发现 CFS quota throttling 即使在节点有空闲 CPU 时也会制造尾延迟和额外成本。作者区分前台服务与 background job 等场景，论证前者通常应取消 limit，并指出 autoscaling、rightsizing 与计费若继续把 limit 当必要前提会得到错误策略。
  - 相较只在既定 CPU limit 下优化额度大小，核心贡献是挑战该机制本身的必要性，并用实证划清“完全取消”与“仍适合限制”的工作负载边界。
  - Container CPU Control、CFS Quota、Tail Latency、Kubernetes Rightsizing、Cloud Billing

- [Serverless Elasticsearch: the Architecture Transformation from Stateful to Stateless](https://doi.org/10.1145/3772052.3772245)
  - Elastic, Athens, Greece；Elastic, Berlin, Germany；Elastic, San Francisco, USA；Elastic, Amsterdam, Netherlands；Elastic, Toronto, Canada；Elastic, Copenhagen, Denmark；Iraklis Psaroudakis、Pooya Salehi、Jason Bryan、Francisco Fernández Castaño、Brendan Cully、Ankita Kumar、Henning Andersen、Thomas Repantis
  - Serverless Elasticsearch 把原本每节点持有本地 shard 的有状态架构改为计算—存储分离：索引文件、transaction log 和 cluster state 进入高可用 object store，indexing 与 search 两个 compute tier 可独立扩缩。系统用批量提交格式和日志聚合分别把对象上传费用降低最多 100 倍和 30 倍，同时保持原 API 与 read-after-write 语义。
  - 相较通过 hot/warm/cold 节点类型耦合计算、容量和副本，核心创新是围绕对象存储重新设计提交、日志和删除协议，使 Elasticsearch 真正无状态扩缩而非只做托管封装。
  - Serverless Search、Elasticsearch、Compute-storage Disaggregation、Object Storage、Read-after-write Consistency

- [Rethinking Tiered Memory Management in Cloud Data Centers](https://doi.org/10.1145/3772052.3772213)
  - The University of Edinburgh, Edinburgh, United Kingdom；Huawei Technologies, Zurich, Switzerland；Tong Xing、Jiaxun Yang、Javier Picorel、Antonio Barbalace

  - 相较 host 全权迁页或固定切分 DRAM/CXL，核心创新是把容量控制与页面优化分属 host/guest，并用轻量 NUMA 重配置形成可快速反馈的协同接口。
  - CXL Memory、Tiered Memory、Host-guest Co-management、Dynamic NUMA、Cloud VM Memory
