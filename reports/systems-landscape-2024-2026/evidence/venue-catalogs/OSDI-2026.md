# OSDI 2026 论文列表

官方 Technical Sessions 共收录 136 篇论文。以下标题均链接至对应的 USENIX 官方论文页；每篇依次列出机构与主要作者、核心工作、相较既有方法的核心创新，以及能直接识别研究对象和技术路径的细粒度方向。

- [Strata: Hierarchical Context Caching for Long Context Language Model Serving](https://www.usenix.org/conference/osdi26/presentation/xie-zhiqiang)
  - Stanford University、NVIDIA、Shanghai Jiao Tong University、University of Colorado Boulder、Carnegie Mellon University、University of Michigan；Zhiqiang Xie、Ziyi Xu、Mark Zhao 等
  - Strata 管理长上下文 LLM 在 GPU HBM、CPU memory、SSD 间的分层 KV cache。GPU-assisted I/O 将适合 attention 的碎片化 GPU layout 与适合存储的大块 host layout 解耦，cache-aware scheduler 则识别同一 context miss 期间到来的 delay hit，以 batch 组合和互补工作隐藏装载；集成 SGLang 并生产部署，吞吐最高比 vLLM-LMCache 高 5 倍。
  - 相较只把 KV block 逐块搬到多级存储，核心创新是同时重做物理 I/O layout 和请求调度，让大传输吃满带宽且 cache loading 不再串行阻塞 prefill。
  - 长上下文 LLM Serving、Hierarchical KV Cache、GPU-Assisted I/O、Cache-Aware Scheduling

- [ECHO: Efficient KV Cache Offloading with Lossless Prefetching for Serving Native Sparse Attention LLMs](https://www.usenix.org/conference/osdi26/presentation/liu-guangda)
  - Shanghai Jiao Tong University、Huawei、Guizhou University；Guangda Liu、Wenhao Chen、Chengwei Li 等
  - ECHO 服务 native sparse-attention LLM：KV 虽只访问稀疏 token，但总 cache 仍随 context 线性增长，因此将其 offload 到 host。graph-friendly manager 在 CUDA Graph 内完成动态 eviction/recall；系统利用 index score 数值可预测性和 query 顺序，在 decode 内及 prefill 请求间无损预取真正会命中的 KV，并用 fused kernel 将 recall 与 indexer 计算流水。长上下文生成吞吐最高提升 2.1 倍。
  - 相较稀疏 attention 仍按需同步取回 KV，核心创新是从稀疏索引器自身的连续分数预测未来访问，在不近似 attention 的情况下提前搬运并完全重叠 recall。
  - Native Sparse Attention、KV Cache Offload、Lossless Prefetch、CUDA Graph/Fused Kernel

- [No Buffer, No Bottleneck: Efficient Zero-Copy KV Cache Offloading for Long-Context LLMs](https://www.usenix.org/conference/osdi26/presentation/luo)
  - University of Virginia；Shutian Luo、Haiying Shen
  - DirectKV 面向 GH200/GB200 等 CPU-GPU 通过 NVLink-C2C 高带宽互连的平台，让 attention kernel 直接读取 CPU-resident KV，不再先拷到 GPU staging buffer。CPU-memory-aware CUDA kernel 融合 KV generation 与 attention，并以 warp pipeline 重叠 fetch、compute、write-back；GH200 上传输量减 50%、GPU memory 减 43%、端到端最高快 1.2 倍。
  - 相较 PCIe offload 默认需要 GPU 临时 buffer 和“双重搬运”，核心创新是把 coherent CPU memory 直接纳入 GPU kernel address space，并专门重排 kernel 以隐藏远端访问。
  - 长上下文推理、Zero-Copy KV Offload、NVLink-C2C、CPU-Memory-Aware Kernel

- [Simple Is Better: Multiplication May Be All You Need for LLM Request Scheduling](https://www.usenix.org/conference/osdi26/presentation/zhang-dingyan)
  - Shanghai Jiao Tong University、Alibaba Group；Dingyan Zhang、Jinbo Han、Kaixi Zhang 等
  - LMetric 为多实例 LLM service 选择单个请求的路由目标，将“若去该实例还需新算多少 prefill token”（KV locality）与“当前 batch size”（负载）直接相乘作为 score。数学分析说明比较时线性组合所需超参数会抵消，并给出极少失效条件的在线检测；在 chatbot/coding-agent trace 上 TTFT、TPOT 均显著降低，已进入生产 canary。
  - 相较对 locality 与 load 手调权重或构建模型/硬件 simulator，核心创新是选取具有 LLM 执行含义的两个指标后用乘法获得 tuning-free trade-off，并明确其理论适用边界。
  - LLM 请求路由、KV Locality、Load Balancing、Tuning-Free Scheduling

- [Prism: Cost-Efficient Multi-LLM Serving via GPU Memory Ballooning](https://www.usenix.org/conference/osdi26/presentation/yu-shan)
  - UCLA、UC Berkeley、Harvard、Carnegie Mellon、Intel、Stanford、ByteDance、Alibaba Cloud 等；Shan Yu、Yifan Qiao、Mingyuan Ma 等
  - Prism 面向服务商必须长期保有大量低流量模型、且生产 trace 呈现成组模型突发活跃的场景。kvcached balloon driver 可按模型实时回收/返还 GPU memory，使多个模型在活跃时空间共享、闲时又可时间复用，而不用在两套机制间切换；已在超过一万 GPU 的生产环境部署。
  - 相较固定切显存或整模型 swap，核心创新是把 GPU memory ballooning 做成跨模型统一弹性层，用同一容量控制原语适应 bursty group 的空间与时间共享。
  - Multi-LLM Serving、GPU Memory Ballooning、模型共置、生产弹性容量管理

- [Break On Through to the Other Side: Pooling Memory Elastically with RamRyder](https://www.usenix.org/conference/osdi26/presentation/zhou-yanbo)
  - UC San Diego、Shanghai Jiao Tong University、Samsung Semiconductor；Yanbo Zhou、Erci Xu、Dongjoo Seo 等
  - RamRyder 让云 VM 的 memory capacity 与 bandwidth 基本独立分配，不再按 vCPU 固定比例。系统控制 guest page 到物理 memory channel 的映射，动态改变某 VM 可用容量/通道数，并隔离不同 VM 的带宽争用；cluster 平均容量利用率提高 28.6%、带宽利用率提高 43.2%，性能接近独占最佳情况。
  - 相较只把 CXL/DRAM 容量做成可池化资源，核心创新是同时虚拟化 page-to-channel mapping，把 memory bandwidth 也变成可计量、可弹性调整的云资源。
  - Elastic Memory Pooling、VM Memory Bandwidth、Page-to-Channel Mapping、性能隔离

- [MAC: Metadata Acceleration for Sustainable Performance in Big-Data Systems with CXL DRAM](https://www.usenix.org/conference/osdi26/presentation/lee)
  - Seoul National University、UIUC；Dusol Lee、Yan Sun、Houxiang Ji 等
  - MAC 关注大容量 CXL DRAM 使 page/对象管理 metadata 本身也放不进本地 DDR 后，host CPU 远程扫描/更新 metadata 导致 reclamation 慢、延迟敏感应用尾部恶化。系统在 CXL memory 侧用 near-memory processing 执行 metadata 的内存密集操作，减少远程流量；相对 OS reclamation 将应用 tail latency 最高降低 98%。
  - 相较只优化应用 data 在 CXL 上的 placement，核心创新是识别容量扩张后“管理数据的数据”成为关键远端工作集，并将 reclamation primitive 下沉到内存侧。
  - CXL DRAM、Memory Reclamation Metadata、Near-Memory Processing、尾延迟

- [Finding NEMO: Nimble and Expressive Memory Observability](https://www.usenix.org/conference/osdi26/presentation/li-shihang)
  - University of Washington、Meta、Microsoft Azure；Shihang Li、Matthew Giordano、Tushar Garg 等
  - NEMO 是放在 server memory controller 的可编程 telemetry engine，OS 可下发规则过滤 memory operation、把访问映射到 counter 并更新小状态，为不同 tiering/THP/隔离 policy 生成专属 view。FPGA CXL expander 原型让 HeMem 更快追踪 hot-set、MEMTIS 更快 split THP，并以低 350 倍 CPU 开销发现 noisy neighbor，最终提升 KV/database 吞吐与延迟。
  - 相较 page-table sampling 覆盖低、scan 开销高或固定硬件 counter 语义僵化，核心创新是在 memory controller 提供小型可编程聚合层，把原始访问就地变成 policy-specific signal。
  - Memory Telemetry、CXL Memory Controller、Policy-Specific Counter、Tiering Observability

- [OBASE: Object-Based Address-Space Engineering to Improve Memory Tiering](https://www.usenix.org/conference/osdi26/presentation/banakar)
  - University of Wisconsin–Madison、Google、xAI；Vinay Banakar、Suli Yang、Kan Wu 等
  - OBASE 解决 allocator 按 size 混排对象导致同一 page 内冷热交织：Google workload 的 active page 最多 97% 字节其实是冷对象。compiler-runtime 通过轻量 pointer instrumentation 追踪对象访问，以 lock-free concurrent migration 将热对象聚到热页、冷对象聚到冷页；无需修改 kswapd、TMO、TPP、Memtis 等 page-level backend 即可把内存 footprint 降最高 70%。
  - 相较继续改进 page hotness estimator，核心创新是在 OS 观察之前主动重塑 virtual address space，让对象语义与页粒度对齐，从源头消除 hotness fragmentation。
  - Object-Aware Memory Tiering、Address-Space Engineering、并发对象迁移、Hotness Fragmentation

- [MDK: Rethinking the Data Center Memory Reclamation Problem](https://www.usenix.org/conference/osdi26/presentation/patel)
  - Google、University of British Columbia、xAI、MongoDB；Shaurya Patel、Suli Yang、Yawen Wang 等
  - MDK 将数据中心 reclamation 重新定义为“在不违反现有 job SLO 时腾出最多内存以再放作业”，而非固定容量下最小 miss。它提供该目标的离线可证明最优策略、展示 performance constraint 与 memory saving 关系的 Memory Performance Curve，以及比 simulation 最快 208 倍的曲线生成方法；据此设计的三种 policy 平均多回收 10%。
  - 相较沿用 OPT/Miss Ratio Curve，核心创新是反转优化自变量和约束，为主动 overcommit/placement 建立新的理论上界、度量与快速评估工具。
  - 数据中心 Memory Reclamation、Memory Performance Curve、SLO-Aware Overcommit、离线最优策略

- [USEC: A User-Requirement-Driven Mandatory Access Control Framework for Operating Systems](https://www.usenix.org/conference/osdi26/presentation/jiang-yu)
  - Tsinghua University、UnionTech、East China Normal University；Yu Jiang、Wenhuan Liu、Fuchen Ma 等
  - USEC 将 Linux MAC policy 改为面向资源的 template 和 semantic class，安全厂商按用户需求声明需保护的进程、文件、socket；kernel 只在 demand-driven path 执行并缓存 decision，binary-compatible LSM interface 可与既有模块共存。相同安全要求下 policy 行数最多少 10 倍、开销比 SELinux 低 3.4%–17.1%，已覆盖 800 万 endpoint。
  - 相较 SELinux 以大量低层 label/rule 描述所有交互，核心创新是把常见资源保护语义提升为模板，并让 enforcement 只物化实际需求，在可配置性、兼容和性能间共同设计。
  - Mandatory Access Control、Resource-Centric Policy、Linux Security Module、生产端点安全

- [Mohabi: Disaggregating and Sandboxing the Firefox JavaScript Engine](https://www.usenix.org/conference/osdi26/presentation/sharma)
  - UT Austin、Stanford University、Mozilla、Google、UC San Diego；Abhishek Sharma、Anand Balaji、Zachary Yedidia 等
  - Mohabi 将 Firefox 的 SpiderMonkey JS engine 从浏览器其余部分解耦，并放入 software fault isolation sandbox，使 engine 漏洞不能破坏 browser。类型系统与 code generation 自动生成跨数万函数、复杂共享结构的安全边界 glue；专用 x86-64 SFI 支持 JS 大地址空间，Speedometer/JetStream 开销约 24%，底层 SFI 在 SPEC 仅 5.9%–6.6%。
  - 相较重写 engine、进程隔离或人工拆解深度 FFI，核心创新是以类型驱动的边界生成把大型遗留 in-process subsystem 实际分离，并为其内存模式定制最快 SFI。
  - Browser Sandboxing、JavaScript Engine Disaggregation、Software Fault Isolation、类型驱动接口生成

- [Ichnaea: A Framework for Precise Tracking of Memory Objects](https://www.usenix.org/conference/osdi26/presentation/haque)
  - George Washington University、RTX BBN Technologies；Samad Haque、Sibin Mohan、Aaron Paulos、Partha Pal
  - Ichnaea 精确记录“谁在何时读写某个 memory object、改了什么”，但平时保持 dormant；利用 memory protection key 将目标对象设为访问触发点，仅在读写发生时截获、记录 caller/context/value change 后恢复执行。相对 Intel Pin 的 tracing overhead 低 10–60 倍，同时保留逐访问信息，可诊断漏洞、热点与并发错误。
  - 相较全程序 binary instrumentation 每条内存访问都付费，核心创新是把 MPK protection fault 变成按对象启用的硬件过滤器，开销只与被关注对象的真实访问成正比。
  - Memory Object Tracing、Memory Protection Keys、按需访问审计、并发/安全诊断

- [Extracting Database Access-Control Policies from Web Applications](https://www.usenix.org/conference/osdi26/presentation/zhang-wen)
  - UC Berkeley、New York University、ICSI；Wen Zhang、Dev Bali、Jamison Kerney 等
  - Ote 从 Ruby on Rails 应用里散落的 access check 和 query filter 反向抽取数据库访问策略。concolic execution 系统探索 application path，记录触发条件与实际 SQL，再合并、简化为“什么用户状态可读写哪些数据”的独立 policy；人工审阅后可由外部 enforcement 持续约束后续代码。三个真实应用中还发现手写策略自身错误。
  - 相较要求开发者先重写显式 policy，核心创新是把 query trace 及 path condition 自动概括为可执行安全规格，使遗留应用的隐含权限可见、可审核、可强制。
  - Web 数据访问控制、Policy Extraction、Concolic Execution、SQL 行为概括

- [iLand: An Instruction-Level Dynamic Binary Instrumentation Framework for iOS](https://www.usenix.org/conference/osdi26/presentation/xie-kaitao)
  - Alibaba Group；Kaitao Xie、Yizhuo Wang、Xiaolong Bai
  - iLand 在未 jailbreak、禁止 JIT 的 iOS 上实现 instruction-level DBI：指令被翻译成预定义 micro-operation，由预编译 atomic execution unit 解释；只模拟 app code、system library 原生运行，以控制手机 CPU/内存。作为普通 sandboxed app 仍支持实时 UI/视频，并用于 60 个热门 App，发现 21% 调私有 API、25% 通过 SVC 直接采集敏感信息。
  - 相较依赖 JIT 的 Android/桌面 DBI，核心创新是以“预编译微操作解释 + application-only emulation”绕过 iOS code-generation 限制，同时保留完整交互应用的可用性能。
  - iOS Dynamic Binary Instrumentation、Micro-Operation Interpreter、App Security Analysis、无越狱执行

- [Tessera: A Holistic Pipeline Parallelism Framework for Trillion-Parameter Heterogeneous MoE Training](https://www.usenix.org/conference/osdi26/presentation/hu-weifang)
  - Huazhong University of Science and Technology、Alibaba Cloud；Weifang Hu、Langshi Chen、Man Yuan 等
  - Tessera 面向 Qwen3/Qwen3-Next 这类 attention 变体与 sparse MoE 混合、运行在 4096–12288 GPU 的万亿参数训练。它为不同 layer combination 合成细粒度 compute-communication overlap，以 overlap 后实测 cost 而非串行 cost 切 pipeline stage，并在 MoE routing 波动产生临时 bubble 时动态搬入可移动 task；生产吞吐提高 20%–33%。
  - 相较按每层独立 profile 静态均分 stage，核心创新是把“能隐藏多少通信”视为 layer 组合属性，并让 partition、静态 overlap schedule、运行时 bubble fill 共同优化。
  - 超大规模 MoE 训练、Pipeline Partition、通信重叠、动态 Bubble Filling

- [Hetu v2: A General and Scalable Deep Learning System with Hierarchical and Heterogeneous Single Program Multiple Data Annotations](https://www.usenix.org/conference/osdi26/presentation/li-haoyang)
  - Peking University、Shanghai Jiao Tong University、Purdue University；Haoyang Li、Fangcheng Fu、Hao Ge 等
  - Hetu v2 的 HSPMD 保留“按单设备写程序”的 declarative annotation，却允许不同设备不对称 shard，并用标准 collective 组合 hierarchical communication。progressive graph specialization 为混合/故障设备生成专属执行逻辑，dynamic graph switching 随变长 sequence 等 temporal heterogeneity 切计划，在异构、波动硬件和混合长度场景达到或超过专用系统。
  - 相较 SPMD 假设所有 rank 对称执行，核心创新是把 asymmetric sharding 与时变 graph 仍表达在单程序抽象中，不迫使用户退回手写 MPMD。
  - 异构分布式训练、HSPMD、Asymmetric Sharding、Dynamic Graph Switching

- [Syncopate: Efficient Multi-GPU AI Kernels via Automatic Chunk-Centric Compute-Communication Overlap](https://www.usenix.org/conference/osdi26/presentation/qiang)
  - UC San Diego、George Mason University、OpenAI、Meta；Xinwei Qiang、Yue Guan、Zhengding Hu 等
  - Syncopate 在单个 fused Triton kernel 内做 multi-GPU compute-communication overlap。communication chunk 抽象独立于 kernel tile 和 NCCL/后端，计划可由既有 compiler 导入、模板生成或手写；source-to-source transform 让对应计算只等待自己的 chunk 到达，而非 whole-kernel 边界同步。多 GPU workload 平均加速 1.3 倍、最高 4.7 倍。
  - 相较 stream-level 重叠整颗 compute/communication kernel，核心创新是将通信可用性对齐到 fused kernel 内的 chunk，消除额外 launch、device-wide barrier 和慢 tile 尾巴。
  - Multi-GPU Kernel、Chunk-Level Overlap、Triton 编译、计算通信融合

- [Teaching the Old Dog New Tricks: Building Efficient Data Pipelines for Large-Scale LLM Pre-Training](https://www.usenix.org/conference/osdi26/presentation/chen-luofan)
  - USTC、ByteDance Seed、ByteDance、Tsinghua University；Luofan Chen、Chenhan Wang、Weidong Zhang 等
  - 该生产研究定位千卡预训练 data pipeline 的三类新瓶颈：训练中评估从异地读 checkpoint、启动时集中 checkpoint I/O、multimodal load 的 CPU transform。系统以 global namespace 预测复制评估 checkpoint、主动复制 hot file，并把数据变换卸到 storage-tier CPU；每次评估浪费 GPU hour 从 16800 降到 4000，启动加载快 40.8%，dataload stall 降 63.2%。
  - 相较更换整个存储系统或只扩带宽，核心创新是根据预训练生命周期把 replication 和 transformation 移到正确地域/资源层，使旧新存储都能低侵入升级。
  - LLM 预训练 Data Pipeline、Checkpoint Replication、Storage-Tier CPU Offload、跨数据中心 I/O

- [Cocoon: A System Architecture for Differentially Private Training with Correlated Noises](https://www.usenix.org/conference/osdi26/presentation/kim-donghwan)
  - Penn State、SK hynix、KAIST；Donghwan Kim、Xin Gu、Jinho Baek 等
  - Cocoon 加速通过跨 iteration correlated noise 相互抵消、提高精度的 DP training。它把随历史增长的 noise state 分层放在 CPU、GPU 和 memory extension，针对大 sparse embedding 只处理被访问部分，并让 near-memory processing 执行带宽密集 noise 运算；在 FPGA NMP 原型上比直接实现快 1.23–10.82 倍。
  - 相较经典 DP-SGD 每轮独立噪声无历史，核心创新是针对“相关噪声算法引入大状态”重构存储/计算路径，使更高精度的 privacy mechanism 能扩展到大模型和 embedding。
  - Differentially Private Training、Correlated Noise、Sparse Embedding、Near-Memory Processing

- [ValScope: Value-Semantics-Aware Metamorphic Testing for Detecting Logical Bugs in DBMSs](https://www.usenix.org/conference/osdi26/presentation/lin-li)
  - Xiamen University；Li Lin、Liehang Chen、Rongxin Wu
  - ValScope 将 SQL metamorphic relation 从 result-set 相等/包含扩展到 value semantics，能描述 aggregation、ordering、numeric value 变化的近似关系。工具用预定义 mutator 生成 query，并做 approximation propagation 分析局部变换对全局输出值的预期影响；六个 DBMS 找到 67 个唯一逻辑 bug，覆盖以往保持集合却算错值的盲区。
  - 相较只把查询结果当集合比较，核心创新是统一 set-level 与 value-level approximation model，为“结果行没丢但值/序错了”建立自动 oracle。
  - DBMS Metamorphic Testing、Value Semantics、Approximation Propagation、SQL 逻辑错误

- [The Abstention Protocol: RCA for Clos Fabrics](https://www.usenix.org/conference/osdi26/presentation/gaikwad)
  - Independent、Microsoft；Madhava Gaikwad、Deepak Pandey
  - CoreSec 为超大规模 Clos network 做 root-cause analysis，不给 noisy、partial、asynchronous telemetry 强行加权打分。多个 telemetry agent 通过 PAM-style control flag 组合：证据充分时给确定判断，冲突/不足时显式 abstain；topology-aware config 表达故障传播面，随证据到达单调收敛，无需跨环境重新调权重。
  - 相较 score fusion 在信号缺失时仍产出不稳定 top cause，核心创新是把“拒绝判断”纳入代数化 agent composition，使自动 RCA 可解释且不会因新证据反复翻转。
  - Network RCA、Abstention Algebra、Telemetry Agent Composition、Clos Fabric 运维

- [When Sampling Lies: Trustworthy Performance Profiling for Flat Workloads with Blink](https://www.usenix.org/conference/osdi26/presentation/devsot)
  - YScope、University of Toronto、Huawei Technologies Canada；Rishikesh Devsot、ChenXing Yang、Yi Fan Yu 等
  - Blink 针对手机 workload 由数千短函数均匀贡献、没有明显 hotspot 的 flat profile；perf sampling 会因 skid、shadow 和覆盖不足产生系统性错误。轻量 function instrumentation 保证短例程覆盖并精确计时，通过插桩选择/实现将开销压到约 1%、accuracy 达 99.999%，已用于 Huawei mobile compiler 优化分析。
  - 相较增加 sampling 频率仍无法消除结构性漏采，核心创新是识别 flat workload 下 sampling 假设失效，转用经过开销控制的近全覆盖 instrumentation。
