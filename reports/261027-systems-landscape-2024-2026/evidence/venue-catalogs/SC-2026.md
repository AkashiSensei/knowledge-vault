## 热门问题与方法

- AI/ML 训练、推理与 Agent 系统以 29 篇成为最大方向，数值算法/高性能算子为 25 篇；LLM serving、AI 训练集群、作业调度和 Agent runtime 已从单个算子优化扩展到端到端资源管理。
- 科学应用与网络/集合通信各 17 篇，量子、空间与专用加速器为 16 篇：一条主线把 PDE、多物理和科学 AI 重构到现代加速器，另一条主线围绕 AI/HPC 的 collective、RDMA、网内计算与新型互连重做数据移动。
- 方法上更强调运行时反馈：上下文/KV cache 感知分配、micro-task 调度、CXL/分层内存、in-network reduction、可信有损压缩，以及对 silent error 和 leadership system 的在线观测。

## 2025–2026 变化

- 主方向从 2025 的数值算子领先（27/134），转为 2026 snapshot 的 AI/ML 训练、推理与 Agent 系统领先（29/149）；但稀疏代数、低精度和矩阵算子合计 25 篇，不是被 AI 取代。
- Agent 四类由 2025 的 1 篇 Agent for Systems + 2 篇 LLM for Systems，变为 2026 snapshot 的 2 篇 Agent System + 3 篇 Agent Infra + 3 篇 Agent for Systems。研究对象从代码助手/文件系统调优，扩展到分布式 Agent runtime、micro-task serving、HPC 作业管理、I/O 遥测、科学模拟监控和异构 kernel 优化。
- 内存中心系统（CXL/分层/共享内存）、量子–HPC 真实工作流、可信有损压缩和运维智能成为更明显的独立议题。由于 SC26 尚未举行，这些变化只表示当前 program，不代表最终 proceedings。

## 论文条目

- [DeepSim: SOL-Based Explainable GPU Performance Projection with Multi-Task Learning](https://sc26.conference-program.com/?post_type=page&p=16&id=pap234&sess=sess208)
  - NVIDIA Corporation；Mengyue Huang、Zhanhui Li、Tim Purcell、Mingqiao Li、Zhengru Wang、Nirmal Saxena
  - DeepSim 面向目标 GPU 尚不可用、只有芯片高层规格的早期设计阶段，用既有 GPU 的 kernel 流量和目标规格构造理想瓶颈，再以多任务学习预测各硬件单元的 speed-of-light 比率，将其校准成实际瓶颈、工作负载类别和执行时间。它在跨 Ampere 至 Blackwell 的 29 万个样本上，对留出的 B200 和未见 kernel 的平均绝对百分比误差分别为 12.29% 和 14.78%。
  - 相比慢且依赖底层硬件细节的模拟器、以及难解释的端到端预测器，核心创新是用可解释的单元级 SOL 比率把瓶颈归因和运行时间预测统一起来。
  - 可靠性、性能观测与运维、GPU 性能预测、多任务学习、瓶颈归因

- [EMO: Energy Efficiency Modeling and Optimization for AI Workloads](https://sc26.conference-program.com/?post_type=page&p=16&id=pap306&sess=sess208)
  - University of Science and Technology of China、Southern University of Science and Technology；Jiyu Luo、Shaoyu Chen、Jingwei Sun、Shengcai Liu、Ke Tang、Guangzhong Sun
  - EMO 针对 CPU–GPU、并发 stream 和多 GPU 异步执行产生的时序空隙，建立低层依赖图并做 what-if 分析，找出可降频的非关键 kernel；随后用依赖感知的 kernel packing 压缩模型规模，并在给定延迟目标下搜索频率策略。实验中能耗降低 15%–28%，性能损失控制在 2%–5%。
  - 核心创新是把异步依赖图上的细粒度 slack 发现、保关键路径的 kernel 打包和受延迟约束的频率组合优化连成低开销在线方案。
  - 可靠性、性能观测与运维、GPU 能耗管理、DVFS、异步依赖图、延迟约束

- [LEO: Tracing GPU Stall Chains via Cross-Vendor Backward Slicing](https://sc26.conference-program.com/?post_type=page&p=16&id=pap534&sess=sess208)
  - Rice University；Yuning Xia、John Mellor-Crummey
  - LEO 面向 profiler 只能指出 GPU stall 位置却难解释根因的问题，从停顿指令反向切片，同时追踪寄存器依赖和 NVIDIA、AMD、Intel 各自的同步机制，将 stall 归因回源指令。21 个 kernel/区域上的人工优化据此获得 1.73–1.82 倍平台几何平均加速；论文中的 LLM 仅用于比较诊断提示是否有助于生成优化建议。
  - 相比只给 stall 计数或局部位置的工具，LEO 首次以跨厂商依赖切片恢复完整 stall 因果链，并把结构化诊断直接对应到源码优化点。
  - 可靠性、性能观测与运维、GPU 性能诊断、跨厂商 profiling、反向切片、LLM 辅助优化

- [Interactive Debugger for Performance Portable Python HPC Kernels](https://sc26.conference-program.com/?post_type=page&p=16&id=pap1059&sess=sess208)
  - The University of Texas at Austin；Ivan Grigorik、Gabriel Kosmacher、George Biros、Milos Gligoric
  - pkdb 为 PyKokkos 一类 Python 嵌入式 HPC kernel 提供断点、单步、继续和变量检查，并保持代码在真实 CPU/GPU 设备上执行且无需改源码；它还支持运行时求值、热替换和两个 kernel 并发比较。跨 Intel/AMD CPU 与 NVIDIA/AMD GPU 的测试表明调试开销有限。
  - 相比离开设备或改写源码的调试方式，核心创新是利用 Python 动态性在实际异构设备执行路径上同时支持传统交互调试和 kernel 热替换/对照。
  - 可靠性、性能观测与运维、Python HPC、交互式调试、性能可移植 kernel、异构设备

- [ORCA: Steerable Observability for Bulk-Synchronous Parallel Applications](https://sc26.conference-program.com/?post_type=page&p=16&id=pap275&sess=sess201)
  - Carnegie Mellon University、Los Alamos National Laboratory (LANL)；Ankush Jain、Sheng Jiang、Charles Cranor、Qing Zheng、Brian Atkinson、George Amvrosiadis、Gary Grider
  - ORCA 为数万进程的 BSP 模拟与训练提供常驻、可操控的在线观测：树形 overlay 协调采集，在原位执行 SQL，并以 timestep 一致的控制让运维人员按需物化视图和干预。4096 rank 的 AMR 程序中等价 trace 开销约 2%，分析最高加速 7275 倍并减少 99.999% 原位数据；LLM 只出现在一项操控性评测中。
  - 相比事后收集海量固定 trace，ORCA 把观测查询和控制下推到运行中的 BSP 应用，以一致 timestep 为边界按问题动态决定采什么、算什么。
  - 可靠性、性能观测与运维、BSP 应用、在线可观测性、原位 SQL、运行时操控

- [Constructing a Job-Centric Frontier Telemetry Dataset to Accelerate HPC Operations, Systems, and Energy Research](https://sc26.conference-program.com/?post_type=page&p=16&id=pap535&sess=sess201)
  - Oak Ridge National Laboratory (ORNL)；Leah Huk、Rachel Palumbo、Woong Shin、Tim Osborne、Ryan Adamson、Michael Sandoval、Corwin Lester
  - 该工作把 Frontier 两年的调度器作业记录与节点级功耗、温度和性能遥测按作业关联，经过收集、归一化和元数据匹配，形成可直接研究工作负载行为、容量规划和异常检测的公开数据集。它解决了两类数据长期分开保存、应用身份需人工追查的问题。
  - 核心创新不是新的诊断模型，而是以作业为统一键把调度元数据和节点遥测整理成可复用、可公开研究的生产级数据资产。
  - 可靠性、性能观测与运维、生产遥测数据集、作业级数据关联、功耗与热力分析、异常检测

- [Understanding Reliability Bottlenecks in LLM Agents for HPC I/O Telemetry Analysis](https://sc26.conference-program.com/?post_type=page&p=16&id=pap908&sess=sess201)
  - University of Delaware、Argonne National Laboratory (ANL)；Chris Egersdoerfer、Orcun Yildiz、Kevin Harms、Robert Latham、Robert Ross、Dong Dai
  - CIODI-Bench 用 Polaris 超算机两年多公开生产 I/O 遥测构造 49 个专家任务，对比会调工具的 LLM Agent 如何取数、分析并生成运维 insight。受限的提取任务中，语义 grounding 将成绩从 73.0% 提到 93.5%；数据分析中，感知过程的 review 提高 13.2%；insight 生成中额外编排无收益且成本近 3 倍。
  - 该工作不是只报一个总准确率，而是用同一生产遥测基准拆出三类任务，定位 grounding、review 和 orchestration 分别在什么结构下有效或反而增加成本。
  - 可靠性、性能观测与运维、Agent System、工具调用 Agent、I/O 遥测分析、grounding 与 review、可靠性评测

- [HieraSparse: Hierarchical Semi-Structured Sparse KV Attention](https://sc26.conference-program.com/?post_type=page&p=16&id=pap262&sess=sess204)
  - Nanyang Technological University, Singapore；Haoxuan Wang、Chen Wang
  - HieraSparse 针对长上下文 LLM 的注意力计算和 KV Cache 容量压力，以分层剪枝把 KV 变成可由 GPU Sparse Tensor Core 执行的半结构化稀疏形式，并为 prefill 与 decode 配套 kernel。相同稀疏度下它比非结构稀疏 decode 方法多 1.2 倍压缩、注意力快 4.57 倍；在无明显质量下降设置下，prefill/decode 分别加速 1.37/1.77 倍。
  - 核心创新是把可调的分层 KV 剪枝约束成硬件原生半结构稀疏，使稀疏率不只节省容量，还能同时转化为 prefill 和 decode 的 Tensor Core 加速。
  - 数值算法与高性能算子、KV Cache 压缩、半结构化稀疏、Tensor Core attention、prefill/decode

- [FastInfer: Breaking the Low-to-Moderate Sparsity Barrier for Efficient LLM Inference](https://sc26.conference-program.com/?post_type=page&p=16&id=pap357&sess=sess204)
  - Beijing University of Posts and Telecommunications；Jinliang Shi、Shigang Li
  - FastInfer 服务 30%–60% 中低稀疏度的剪枝 LLM，以线程寄存器需求为中心设计 TFBE 编码，在运行时低开销重建操作数，并结合亲和性感知搬运和三级流水提升 Tensor Core 利用率。H100 上相对 SpInfer，稀疏 kernel 几何平均加速 1.52 倍，端到端推理加速 1.27 倍。
  - 既有稀疏框架在中低稀疏度常输给稠密计算；其核心创新是从单线程寄存器供数出发重新编码稀疏操作数，而非沿用面向高稀疏度的全局格式。
  - 数值算法与高性能算子、LLM 稀疏推理、非结构化剪枝、Tensor Core、稀疏编码

- [TileFlow: Data-Movement-Centric Optimization for Irregular GEMM on Matrix-Unit CPUs](https://sc26.conference-program.com/?post_type=page&p=16&id=pap724&sess=sess204)
  - NUDT；Weiling Yang、Jianbin Fang、Dezun Dong、Chencheng Deng、Runxi He、Junwen Zhang
  - TileFlow 优化 LLM 推理和向量检索中某些维度很小的 irregular GEMM：它在微内核粒度把按需 packing、访存与计算流水重叠，并依据 NUMA 页分配方式把任务交给更接近数据的线程，减少跨 NUMA 流量。两类 AMX CPU 上，GEMM、Llama3-8B 推理和近邻搜索分别加速 1.36、1.47 和 1.39 倍。
  - 相比为规则矩阵预打包且不感知数据位置的 BLAS，TileFlow 把 packing 时机与 NUMA 放置共同视为 irregular GEMM 的主要瓶颈并在微内核级联合优化。
  - 数值算法与高性能算子、irregular GEMM、CPU 矩阵单元、NUMA 感知、数据搬运

- [Pushing the Envelope of LLM Inference with Ultra-Low-Bit Quantized Models](https://sc26.conference-program.com/?post_type=page&p=16&id=pap858&sess=sess204)
  - Intel Corporation；Evangelos Georganas、Dhiraj Kalamkar、Alexander Heinecke、Pradeep Dubey
  - 该工作从 CPU 的 2-bit 微内核出发，将其接入完整 LLM 推理流水，随后为 Intel Xe2 GPU 实现混合精度 2-bit kernel 并集成到 vLLM。CPU 端相对 bitnet.cpp 快 2.2 倍、相对 16-bit 最高快 7 倍，Xe2 上端到端相对 16-bit 最高快 6.7 倍。
  - 核心创新是从接近 roofline 的 2-bit 底层 kernel 一直贯通到 CPU 与 Xe2 上的实际 serving runtime，验证超低比特模型的理论节省能转成端到端收益。
  - 数值算法与高性能算子、LLM 超低比特推理、2-bit 量化、CPU/GPU 微内核、推理 runtime

- [Loop-Carried Dependence Transformation for Parallel Sparse Solvers on GPUs](https://sc26.conference-program.com/?post_type=page&p=16&id=pap871&sess=sess205)
  - McMaster University、University of Utah；Da Ma、Mohammad Mahdi Salehi Dezfuli、Amir Mohammad Tavakkoli、Samirasadat Jamalidinan、Hossein Albakri、Mary Hall、Kazem Cheshmi
  - LCD 由 Python JIT 编译器识别稀疏求解器中的跨迭代依赖循环，将其映射到 GPU thread block 和 warp，并由中央调度器协调 block/线程管理器及正确同步。它不限定具体数值方法或矩阵类型，生成代码在 H100 的多类操作上比 cuSPARSE 几何平均快 1.60–4.56 倍。
  - 相比只处理完全并行循环或特定稀疏算子的方案，核心创新是自动变换带 loop-carried dependence 的求解器循环并生成可扩展 GPU 同步结构。
  - 数值算法与高性能算子、稀疏求解器、循环依赖变换、GPU JIT 编译、同步机制

- [SPIKe: Generating Practical SpMV Kernels for Sparse Iterative Methods on GPUs](https://sc26.conference-program.com/?post_type=page&p=16&id=pap380&sess=sess205)
  - School of Computer Science, Peking University、Institute of Computing Technology (ICT), Chinese Academy of Sciences (CAS)、Institute for AI Industry Research, Tsinghua University、National University of Defense Technology (NUDT)；Luhan Wang、Haipeng Jia、Kun Li、Zongyuan He、Shengguo Li、Ting Cao、Yunxin Liu、Yunquan Zhang、Yifeng Chen
  - SPIKe 为不同迭代次数的稀疏迭代法生成 SpMV kernel：在线用行跨度代理调线程并行度，以 warp 充当传感器把偏斜 tile 导向不对称路径，离线再结合架构与领域生成代码。2294 个矩阵上预处理近乎可忽略，PageRank 和 GMRES 相对 GraphBLAS/PETSc 平均加速 2.78/4.26 倍。
  - 核心创新是让统一 kernel 同时在线感知均匀与偏斜 tile、离线适配架构，避免为矩阵做昂贵预处理后才能获得负载均衡。
  - 数值算法与高性能算子、SpMV kernel 生成、稀疏迭代法、在线负载均衡、架构感知调优
