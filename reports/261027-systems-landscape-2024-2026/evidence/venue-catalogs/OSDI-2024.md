# OSDI 2024 论文列表

官方 Technical Sessions 共收录 53 篇论文。以下标题均链接至对应的 USENIX 官方论文页；每篇依次列出机构与主要作者、核心工作、相较既有方法的核心创新，以及能直接识别研究对象和技术路径的细粒度方向。

- [Sabre: Hardware-Accelerated Snapshot Compression for Serverless MicroVMs](https://www.usenix.org/conference/osdi24/presentation/lazarev)
  - MIT CSAIL、Intel Labs、Cornell University；Nikita Lazarev、Varun Gohil、James Tsai 等
  - Sabre 面向以 Firecracker microVM 快照恢复来降低函数冷启动的 serverless 平台：系统将内存页无损压缩交给服务器处理器上的近内存分析加速器，并让恢复路径预取压缩快照，使有限 I/O 能覆盖更多 guest 物理内存。快照最多缩小 4.5 倍、解压开销近乎可忽略，内存恢复最高加速 55%。
  - 相较用 CPU 软件压缩后因算力开销抵消预取收益，核心创新是把数据中心已有的近内存硬件纳入 microVM 快照数据通路，使“压缩后多预取”第一次能用于在线冷启动。
  - Serverless 冷启动、MicroVM Snapshot、近内存压缩、内存页预取

- [Nomad: Non-Exclusive Memory Tiering via Transactional Page Migration](https://www.usenix.org/conference/osdi24/presentation/xiang)
  - The University of Texas at Arlington、Intel Labs；Lingfeng Xiang、Zhen Lin、Weishu Deng 等
  - Nomad 管理 DRAM 与 CXL/持久内存等慢速层级：热页被提升到快内存后，慢层仍保留 shadow copy；Linux 中的 transactional page migration 先异步复制、再原子切换映射，若快层压力导致页面很快降级便可复用副本，避免来回搬页和阻塞应用。在内存压力下，相对 Linux TPP 最高提升 6 倍性能。
  - 相较“一个页面只能存在于一个层级”的排他式迁移，核心创新是用页影子和事务式切换实现非排他层级，把迁移移出关键路径并直接抑制冷热页抖动。
  - CXL 分层内存、非排他 Page Tiering、事务式页迁移、Memory Thrashing

- [Managing Memory Tiers with CXL in Virtualized Environments](https://www.usenix.org/conference/osdi24/presentation/zhong-yuhong)
  - Columbia University、Microsoft Azure、Intel、University of Washington、University of Michigan；Yuhong Zhong、Daniel S. Berger、Carl Waldspurger 等
  - 该工作面向云上多 VM 共享本地 DRAM 与较慢 CXL 内存的场景，将 Intel Flat Memory Mode 的硬件 cache-line 级自动放置与软件性能隔离结合。Memstrata 用 page coloring 隔开 VM 的硬件缓存竞争，并以在线 slowdown estimator 识别对远内存敏感的租户、为其增加本地 DRAM；原型中把异常 VM 超过 30% 的退化压到 6% 以下。
  - 相较纯软件页迁移开销高、纯硬件 tiering 又不理解租户 SLO，核心创新是保留硬件细粒度搬运，同时由轻量软件只负责跨 VM 隔离和容量再分配。
  - CXL 虚拟化、Hardware-Managed Tiering、多租户性能隔离、Page Coloring

- [Harvesting Memory-bound CPU Stall Cycles in Software with MSH](https://www.usenix.org/conference/osdi24/presentation/luo)
  - UC Berkeley、ICSI；Zhihong Luo、Sam Son、Sylvia Ratnasamy、Scott Shenker
  - MSH 在延迟敏感服务因 cache miss/内存访问停顿时，将空出的 CPU 周期透明借给后台工作。它联合 profiling、程序分析、二进制插桩和运行时调度识别可安全让出的 stall 区间，并按 SLO 调节并发度；在 SMT 因尾延迟必须关闭的约束下仍可获得其最高 72% 的 harvesting throughput，且可与 SMT 叠加。
  - 相较硬件 SMT 只有固定线程数且难以精细控制延迟，核心创新是在软件层把内存停顿变成可检测、可配置、可扩展并发的资源。
  - 内存停顿利用、Latency-Critical Colocation、二进制插桩、软件线程调度

- [A Tale of Two Paths: Toward a Hybrid Data Plane for Efficient Far-Memory Applications](https://www.usenix.org/conference/osdi24/presentation/chen-lei)
  - University of Chinese Academy of Sciences、UCLA、Tsinghua University、Microsoft Research；Lei Chen、Shi Liu、Chenxi Wang 等
  - Atlas 面向通过高速网络使用 far memory 的应用，在内核 page fault 路径和用户态 object fetch 路径之间动态选择。运行时持续测量页面局部性：局部性好时采用开销低的分页，局部性差时按对象拉取，并把时间上相邻访问的对象重新排成连续本地空间，逐步把工作负载转回更省 CPU 的分页路径；相较 AIFM/Fastswap 提升吞吐并将尾延迟降低一至两个数量级。
  - 相较固定押注“页粒度透明访问”或“对象粒度精确访问”，核心创新是用在线局部性和对象重排让两条数据路径相互转换，在网络流量与 CPU 元数据开销间按工作负载取舍。
  - Far Memory、Page/Object Hybrid Fetch、在线局部性分析、Runtime-Kernel Co-design

- [DRust: Language-Guided Distributed Shared Memory with Fine Granularity, Full Transparency, and Ultra Efficiency](https://www.usenix.org/conference/osdi24/presentation/ma-haoran)
  - UCLA、Alibaba Group、UC San Diego；Haoran Ma、Yifan Qiao、Shi Liu 等
  - DRust 为 Rust 程序提供跨服务器的透明分布式共享内存，把语言的所有权、借用和可变引用规则暴露给运行时：对象所有权已经限制读写次序，系统因此可在对象粒度维护位置和缓存副本，而不必用通用 DSM 的频繁全局一致性协议。其吞吐相对 GAM 和 Grappa 分别最高提升 2.64 倍与 29.16 倍，并随服务器数更好扩展。
  - 相较在运行时重新推断任意并发读写，核心创新是把 Rust 类型系统已有的所有权不变量直接转化为 coherence 约束，以语言语义换掉大量跨机同步。
  - 分布式共享内存、Rust Ownership、对象级一致性、Language-Runtime Co-design

- [Taming Throughput-Latency Tradeoff in LLM Inference with Sarathi-Serve](https://www.usenix.org/conference/osdi24/presentation/agrawal)
  - Georgia Institute of Technology、Microsoft Research India；Amey Agrawal、Nitin Kedia、Ashish Panwar 等
  - Sarathi-Serve 处理在线 LLM 请求中计算密集的 prefill 与逐 token、低利用率 decode 相互干扰的问题。调度器把长 prompt 的 prefill 切成大小接近的 chunk，每轮只插入恰能与既有 decode 组成均匀 batch 的片段，使新请求进入时不暂停正在生成的请求，并减少流水并行 bubble；在尾延迟约束下服务容量相对 vLLM 提高 2.6–5.6 倍。
  - 相较一次执行完整 prefill、令 decode 出现长暂停，核心创新是把 prefill chunking 与 stall-free batch 构造统一为请求级调度原语，同时改善单卡和 pipeline-parallel 推理。
  - LLM Serving、Chunked Prefill、Decode 无停顿调度、吞吐-尾延迟权衡

- [ServerlessLLM: Low-Latency Serverless Inference for Large Language Models](https://www.usenix.org/conference/osdi24/presentation/fu)
  - University of Edinburgh、Nanyang Technological University；Yao Fu、Leyang Xue、Yeqi Huang 等
  - ServerlessLLM 面向模型按需启动和弹性扩缩的 LLM 推理：节点利用 NVMe、主存和 GPU 显存缓存本地 checkpoint，以 loading-optimized 格式并行吃满多级存储带宽；调度器依据各节点权重 locality 选择启动位置，并用请求与 KV 状态的 live migration 将流量迁到已经就绪的实例。不同模型和负载下，启动相关延迟相对既有 serverless 系统降低 10–200 倍。
  - 相较只优化远端权重下载或把模型装载视为固定启动成本，核心创新是联合设计 checkpoint 格式、多层本地缓存、放置决策和在线迁移，围绕“最快可开始推理”调度。
  - LLM Serverless、Checkpoint 多级装载、模型冷启动、推理 Live Migration

- [InfiniGen: Efficient Generative Inference of Large Language Models with Dynamic KV Cache Management](https://www.usenix.org/conference/osdi24/presentation/lee)
  - Seoul National University；Wonbeom Lee、Jungi Lee、Junghwan Seo、Jaewoong Sim
  - InfiniGen 面向长文本生成中 GPU 放不下全部 KV、需从 CPU 内存 offload/prefetch 的场景。系统在当前层用少量 query 权重和下一层部分 key cache 做一次轻量 rehearsal，提前预测下一层真正会获得高 attention 的 token，只把这些 KV 条目搬回 GPU；相对既有 KV 管理方案最高加速 3 倍，并避免激进丢弃造成的明显精度损失。
  - 相较按窗口或历史分数静态选择 KV，核心创新是利用相邻 Transformer 层的运行时输入做前瞻式重要 token 预测，把 host-to-device 搬运从“全量 cache”缩到“下一层实际需要的条目”。
  - 长上下文 LLM 推理、KV Cache Offloading、跨层 Token 预测、选择性预取

- [Llumnix: Dynamic Scheduling for Large Language Model Serving](https://www.usenix.org/conference/osdi24/presentation/sun-biao)
  - Alibaba Group；Biao Sun、Ziming Huang、Hanyu Zhao 等
  - Llumnix 面向输入/输出长度不可预知、优先级与 SLO 各异的在线 LLM 请求，在多个模型实例间运行时重调度。系统像 OS 在 CPU 核间迁移进程一样，连同请求 KV 状态执行低开销 live migration，用统一策略处理负载不均、显存碎片、优先级隔离和 SLO 分化；尾延迟可改善一个数量级，并在相近尾延迟下节省最高 36% 成本。
  - 相较请求一旦进入实例便固定到完成，核心创新是把带状态请求迁移做成可频繁调用的 serving 原语，使全局调度能在实际生成长度暴露后纠正最初放置。
  - LLM Serving、Request Live Migration、跨实例动态调度、SLO/优先级隔离

- [DistServe: Disaggregating Prefill and Decoding for Goodput-optimized Large Language Model Serving](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin)
  - Peking University、UC San Diego、StepFun；Yinmin Zhong、Shengyu Liu、Junda Chen 等
  - DistServe 把每个 LLM 请求的 prefill 和 decode 分配到不同 GPU 池，分别围绕 TTFT 与 TPOT 选择副本数和并行方式，并按集群跨机带宽放置两类实例以控制 KV 状态传输。这样既消除两阶段在同一 batch 内的计算干扰，也解除其资源配置耦合；在 90% 请求同时满足两个延迟 SLO 时，单 GPU 可承载的到达率最高提高 7.4 倍。
  - 相较共置两阶段后只能牺牲 TTFT 或 TPOT，核心创新是把“阶段解耦、独立扩容/并行、拓扑感知放置”共同作为 goodput 优化问题，而非只做 kernel 或 batch 调整。
  - LLM Serving、Prefill-Decode Disaggregation、TTFT/TPOT SLO、拓扑感知资源配置

- [ACCL+: an FPGA-Based Collective Engine for Distributed Applications](https://www.usenix.org/conference/osdi24/presentation/he)
  - ETH Zurich、University of Amsterdam、AMD Research；Zhenhao He、Dario Korolija、Yu Zhu 等
  - ACCL+ 是部署在 SmartNIC/网络附加 FPGA 上的开源 collective communication engine，支持 UDP、TCP 和 RDMA：FPGA 应用可直接执行 FPGA-to-FPGA 集合通信，CPU 应用也能把 collective 卸载到它；新 collective 可通过模块扩展而无需重新综合整个设计。100 Gb/s 集群实验显示其对 FPGA 分布式应用显著优于软件 MPI，并能支撑全 FPGA 推荐推理。
  - 相较把 FPGA 当作由主机 MPI 驱动的被动加速器，核心创新是提供跨平台、可扩展且可由设备直接发起的 collective 数据面，同时兼顾 CPU offload 与纯 FPGA 系统。
  - FPGA 集合通信、SmartNIC Offload、RDMA、分布式推荐推理

- [Beaver: Practical Partial Snapshots for Distributed Cloud Services](https://www.usenix.org/conference/osdi24/presentation/yu)
  - University of Pennsylvania、Shanghai Jiao Tong University、Princeton University、Microsoft/University of Washington；Liangcheng Yu、Xiao Zhang、Haoran Zhang 等
  - Beaver 为只能控制云服务一部分进程、其余外部客户端仍持续发流量的现实环境生成因果一致快照。它利用公有云软件负载均衡器是外部流量统一入口这一规律，在边界记录/编排消息而只改动被快照组件，不阻塞正常通信，因而可用于跨服务调试、复制和状态分析且对用户流量近乎零开销。
  - 相较 Chandy–Lamport 类协议要求纳入并协调所有通信进程，核心创新是把负载均衡器变成 partial snapshot 的可控因果边界，在开放世界流量干扰下仍保持一致性。
  - 分布式 Partial Snapshot、因果一致性、云负载均衡器、非阻塞状态捕获

- [Fast and Scalable In-network Lock Management Using Lock Fission](https://www.usenix.org/conference/osdi24/presentation/zhang-hanze)
  - Shanghai Jiao Tong University、Shanghai AI Laboratory；Hanze Zhang、Ke Cheng、Rong Chen、Haibo Chen
  - FISSLOCK 面向数百万把分布式锁，将同步、延迟敏感的 grant decision 放入可编程交换机，而把 holder/waiter 列表异步留在服务器；交换机还路由按需的细粒度锁迁移。这样避开 CPU 排队又不让交换机 SRAM 保存完整参与者状态，相对 NetLock 最多缩短 79.1% 中位授锁时间，并将 TATP/TPC-C 吞吐提高 1.76/2.28 倍。
  - 相较把整把锁的状态都塞进交换机、容量受限，核心创新是 lock fission：按时延敏感性拆开“决定谁获锁”和“维护全部参与者”，以异构状态分工同时获得低延迟与百万级规模。
  - In-Network Lock、P4 可编程交换机、Lock Fission、事务并发控制

- [Chop Chop: Byzantine Atomic Broadcast to the Network Limit](https://www.usenix.org/conference/osdi24/presentation/camaioni)
  - EPFL；Martina Camaioni、Rachid Guerraoui、Matteo Monti 等
  - Chop Chop 为拜占庭状态机复制提供 atomic broadcast，将大量短消息交给不可信 broker 通过交互协议“蒸馏”为易于统一验签、去重和排序的 batch，再由服务器共识处理。64 台跨地域服务器上可处理每秒 4360 万条 8-byte 消息，在相同延迟下较既有方案高约两个数量级。
  - 相较仅做普通 batching、仍逐消息承担认证和去重，核心创新是 authenticated mempool 与 distillation，使 broker 即使不可信也能预聚合可批量验证的消息，把安全广播推到接近无安全语义的 line rate。
  - Byzantine Atomic Broadcast、Authenticated Mempool、Batch Distillation、状态机复制

- [Enabling Tensor Language Model to Assist in Generating High-Performance Tensor Programs for Deep Learning](https://www.usenix.org/conference/osdi24/presentation/zhai)
  - University of Science and Technology of China、Huawei、ByteDance、Hunan University；Yi Zhai、Sijia Yang、Keyu Pan 等
  - TLM 将深度学习 tensor program 的 schedule 搜索改写为语言生成：专门设计的 tensor language 显式编码 tiling、映射等编译决策，模型结合离线学到的优化知识和当前已选决策，为下一步候选赋概率并采样。它保留 Ansor/MetaSchedule 的大搜索空间，却以少得多的实测完成探索；达到其完全调优性能时编译快 61 倍。
  - 相较随机/进化搜索或用启发式预先裁剪空间，核心创新是让模型学习“决策序列”的条件分布，用生成先验导航完整优化空间，而非直接生成不可验证代码。
  - LLM/Language Model for Systems、Tensor Program Generation、编译自动调优、学习式搜索策略

- [Ladder: Enabling Efficient Low-Precision Deep Learning Computing through Hardware-aware Tensor Transformation](https://www.usenix.org/conference/osdi24/presentation/wang-lei)
  - University of Chinese Academy of Sciences、Microsoft Research、Peking University；Lei Wang、Lingxiao Ma、Shijie Cao 等
  - Ladder 是面向新型低比特/自定义数据类型的 DNN 编译器：tType 类型系统和扩展 tensor expression 把存储格式、访存、类型转换与计算 pipeline 统一表示，再用新的调度原语及硬件感知策略，把硬件不原生支持的精度映射到现有 accelerator 指令和多级内存。模型设计者无需修改硬件即可实测低精度带来的速度收益。
  - 相较为每种量化格式手写 kernel 或只能使用硬件固定类型，核心创新是把 custom datatype 提升为编译 IR 的一等对象，并联合搜索数据布局、转换位置与算子调度。
  - 低精度 DNN 编译、自定义数据类型、Hardware-Aware Tensor Transformation、Kernel Scheduling

- [Caravan: Practical Online Learning of In-Network ML Models with Labeling Agents](https://www.usenix.org/conference/osdi24/presentation/zhang-qizheng)
  - Stanford University、Purdue University、University of Michigan、Sapienza University of Rome；Qizheng Zhang、Ali Imran、Enkeleda Bardhi 等
  - Caravan 让部署在交换机/网络数据面的 ML 模型适应流量漂移：它把既有启发式、ACL、基础模型等封装成多个 labeling agents，为新流量自动产生监督标签；同时以无需持续真值的 accuracy proxy 监测退化，仅在漂移足够明显时触发 GPU 重训练。相对离线模型平均 F1 提升 30.3%，在接近持续学习精度时少用 61.3% GPU 时间。
  - 相较假设离线数据长期有效或持续重训，核心创新是把异构既有系统转成可组合的在线标签源，并用代理精度闭环控制训练频率；这里的 agent 是标签服务，不是规划—行动型 Agent System。
  - ML for Systems、In-Network ML、Labeling Agents、数据漂移与触发式重训练

- [nnScaler: Constraint-Guided Parallelization Plan Generation for Deep Learning Training](https://www.usenix.org/conference/osdi24/presentation/lin-zhiqi)
  - University of Science and Technology of China、Microsoft Research、xAI、BaseBit；Zhiqi Lin、Youshan Miao、Quanlu Zhang 等
  - nnScaler 为大模型/复杂 DNN 训练生成并行执行计划，不把搜索限制在预设的数据、张量或流水组合。领域专家通过 op-trans、op-assign、op-order 三种原语表达模型变换、设备映射和时空次序，再加约束压住组合爆炸；系统由此能覆盖已有空间并构造适合大 embedding、AlphaFold2 等结构的新空间，最高比 DeepSpeed、Megatron-LM、Alpa 快 3.5 倍。
  - 相较在框架内硬编码少量 parallelism template，核心创新是用一组可约束、可组合的通用计划原语开放搜索空间，同时仍让自动生成可计算。
  - 分布式训练、并行计划生成、约束搜索、模型/设备映射

- [ChameleonAPI: Automatic and Efficient Customization of Neural Networks for ML Applications](https://www.usenix.org/conference/osdi24/presentation/liu)
  - University of Chicago、East China Normal University、Microsoft Research；Yuhan Liu、Chengcheng Wan、Kuntai Du 等
  - ChameleonAPI 观察到同一视觉/ML API 的分类错误未必都会改变上层应用决策，于是静态分析应用如何使用 API 输出，抽取 decision process，并自动生成只惩罚“会造成应用失败”的任务损失；随后为每个应用训练轻量定制网络，通过原接口透明部署。相较从商业 API 中选总体准确率最高者，错误应用决策减少 43%。
  - 相较按通用模型 accuracy 优化，核心创新是把下游程序控制流转化为可训练的 application-specific loss，让模型容量花在真正影响软件结果的类别/误差上。
  - ML API 定制、程序分析、Application-Aware Loss、模型专门化
