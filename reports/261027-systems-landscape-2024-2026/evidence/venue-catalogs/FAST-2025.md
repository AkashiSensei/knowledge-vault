# FAST 2025 论文列表

FAST 2025 正式技术议程共收录 36 篇论文。以下标题链接至 USENIX 官方页面；每篇依次列出作者与机构、研究场景和系统机制、相较既有方法的核心创新，以及细粒度方向。36 份官方 PDF 均已保存至 `reference/FAST/2025/`。

- [Fast, Transparent Filesystem Microkernel Recovery with Ananke](https://www.usenix.org/conference/fast25/presentation/liu-jing)
  - Jing Liu, Microsoft Research; Yifan Dai, Andrea C. Arpaci-Dusseau, and Remzi H. Arpaci-Dusseau, University of Wisconsin–Madison Awarded Best Paper!
  - Ananke 将 file system 作为 microkernel userspace service 运行；service process 意外崩溃时，host OS 在其他进程和整机仍存活的窗口里执行一小段可信 recovery code，记录普通 reboot 无法得到的 request/metadata progress，重启并重接应用 FD。3 万余 fault injection 中实现无数据损失，通常数百毫秒透明恢复。
  - 相较整机 crash recovery 只能从磁盘日志推断状态，核心创新是利用 microkernel 的进程级故障边界，在故障瞬间捕获 volatile evidence 并恢复 service/application binding。
  - Filesystem Microkernel、Process-level Recovery、Fault Injection、Transparent Restart、Crash Consistency

- [Boosting File Systems Elegantly: A Transparent NVM Write-ahead Log for Disk File Systems](https://www.usenix.org/conference/fast25/presentation/wang)
  - Guoyu Wang, Xilong Che, Haoyang Wei, Shuo Chen, Puyi He, and Juncheng Hu, Jilin University
  - NVLog 在 legacy disk file system 前放 NVM write-ahead log，只吸收 fsync/synchronous 的小粒度更新，异步写仍走 DRAM/page-cache 快路径；NVM 中记录暂存而非长期迁移数据，并处理 NVM+disk 两种持久介质的顺序、recovery 与 GC。无需改成熟文件系统即可最高加速 15.09 倍。
  - 相较把整个 FS 移到 PM/NVM 或让所有 write 都进新 log，核心创新是 on-demand byte-granular sync absorption，以最小 NVM 占用透明截断慢盘同步路径。
  - NVM Write-ahead Log、Disk File System、Fsync Acceleration、Heterogeneous Persistence、Crash Recovery

- [DJFS : Directory-Granularity Filesystem Journaling for CMM-H SSDs](https://www.usenix.org/conference/fast25/presentation/yoo)
  - Seung Won Yoo, Korea Advanced Institute of Science and Technology (KAIST); Joontaek Oh, University of Wisconsin–Madison; Myeongin Cheon and Bonmoo Koo, Korea Advanced Institute of Science and Technology (KAIST); Wonseb Jeong, Hyunsub Song, Hyeonho Song, and Donghun Lee, Samsung Electronics; Youjip Won, Korea Advanced Institute of Science and Technology (KAIST)
  - DJFS 根据应用更新通常局限在同一 directory 的观察，把 journal transaction 从全局/固定 batch 改成 per-directory。path 决定 transaction 归属，相邻事务可 coalesce；跨目录 rename/link 等由 conflict resolver 保序。互不相关目录可并行 commit，减少 journal lock contention 和 lock-up。
  - 相较 FastCommit 等共享 journal transaction 把无关目录串行化，核心创新是用 namespace directory 作为既有局部性强、又能表达冲突的事务隔离单位。
  - Journaling File System、Per-directory Transaction、Parallel Commit、Lock Contention、CMM-H SSD

- [ScaleLFS: A Log-Structured File System with Scalable Garbage Collection for Commodity SSDs](https://www.usenix.org/conference/fast25/presentation/ha)
  - Jin Yong Ha, Seoul National University; Sangjin Lee, Chung-Ang University; Hyeonsang Eom, Seoul National University; Yongseok Son, Chung-Ang University
  - ScaleLFS 在 F2FS 上让每个 CPU core 有独立 garbage collector 和资源，victim manager 并发选择/更新 segment metadata；victim protector 把冲突保护缩到 page 而非整 file，使多个 GC 可同时搬不同页且不与 foreground overwrite 竞态，commodity SSD 长时间写入吞吐最高高 7 倍。
  - 相较单线程 GC 或仅并行搬运但共享 victim state，核心创新是把 collector、victim selection 和冲突保护三个串行点都改成可扩展 per-core/page-grained 机制。
  - Log-structured File System、Parallel Garbage Collection、F2FS、Page-level Protection、SSD

- [Rethinking the Request-to-IO Transformation Process of File Systems for Full Utilization of High-Bandwidth SSDs](https://www.usenix.org/conference/fast25/presentation/zhan)
  - Yekang Zhan, Haichuan Hu, Xiangrui Yang, and Qiang Cao, Huazhong University of Science and Technology; Hong Jiang, University of Texas at Arlington; Shaohua Wang and Jie Yao, Huazhong University of Science and Technology
  - OrchFS 不把用户 write 全切成同质 page-aligned block I/O。alignment-based partition 把已经/可组成 SSD-page-aligned 的部分经并行 SSD path 发出，剩余 unaligned 小尾部写到小容量 NVM；统一 per-file mapping 组合两处数据，embedded parallel engine 提供足够 outstanding I/O，绕开 page cache/alignment overhead。
  - 相较传统 FS 先按内存页对齐再发 SSD，核心创新是从 request-to-I/O transformation 阶段生成异构粒度和异构介质操作，让每段数据走最合适路径。
  - Hybrid NVM-SSD、Heterogeneous I/O、Write Alignment、File Mapping、Parallel I/O

- [FlacIO: Flat and Collective I/O for Container Image Service](https://www.usenix.org/conference/fast25/presentation/liu-yubo)
  - Yubo Liu, Hongbo Li, Mingrui Liu, Rui Jing, Jian Guo, Bo Zhang, Hanjun Guo, Yuxin Ren, and Ning Jia, Huawei Technologies Co., Ltd.
  - FlacIO 把 container image 从面向存储的全局 layer/tar，改成描述某项 service root-FS 内存状态的 runtime image。节点接收 flat runtime state，runtime page cache 跨同服务实例共享已构造页，减少重复解包、远端读和 network amplification；冷启动比全镜像/懒加载最高快 23/4.6 倍。
  - 相较把镜像优化局限于 layer fetch 顺序，核心创新是改变 image abstraction：直接传输可运行的内存页集合，并以 service-local collective cache 复用。
  - Container Image、Cold Start、Runtime Image、Page Cache、Cloud Storage

- [Cloudscape: A Study of Storage Services in Modern Cloud Architectures](https://www.usenix.org/conference/fast25/presentation/satija)
  - Sambhav Satija, Chenhao Ye, Ranjitha Kosgi, Aditya Jain, Romit Kankaria, Yiwei Chen, Andrea C. Arpaci-Dusseau, and Remzi H. Arpaci-Dusseau, University of Wisconsin–Madison; Kiran Srinivasan, NetApp
  - Cloudscape 从近 400 个真实 AWS architecture 提取 storage-service graph，统计 S3、EBS、DynamoDB、RDS、EFS 等与 Lambda、EC2、ML/analytics service 的组合。结果显示 S3 出现在 68%、文件服务仅 4%，同一架构内异构存储普遍存在，为研究 workload/接口假设提供现实基线。
  - 相较从单服务 trace 推断云存储使用，核心贡献是公开 architecture-level dataset，揭示“哪些存储被怎样组合”而非只测某产品性能。
  - Cloud Architecture Study、AWS Storage、Service Composition、Dataset、Storage Heterogeneity

- [Maat: Analyzing and Optimizing Overcharge on Blockchain Storage](https://www.usenix.org/conference/fast25/presentation/he)
  - Zheyuan He, University of Electronic Science and Technology of China; Zihao Li, The Hong Kong Polytechnic University; Ao Qiao and Jingwei Li, University of Electronic Science and Technology of China; Feng Luo, The Hong Kong Polytechnic University; Sen Yang, University of Electronic Science and Technology of China; Gelei Deng, Nanyang Technological University; Shuwei Song, XiaoSong Zhang, and Ting Chen, University of Electronic Science and Technology of China; Xiapu Luo, The Hong Kong Polytechnic University
  - Maat 在 Ethereum 每条 storage opcode/account-slot 操作粒度对应 gas charge 与实际 CPU/memory/I/O，定位 fee 与 resource workload 不一致的 overcharge。优化依据高层 storage semantic，在所有 node/client 上确定性地产生相同收费/执行，并预先声明分配所需资源；Ethereum/BSC 每周分别可省 560/154 万美元。
  - 相较简单降低 opcode gas 会破坏共识或被不同实现利用，核心创新是把费用优化绑定 consensus-visible storage semantic，并用 resource pre-allocation 消除异构执行差异。
  - Blockchain Storage、Transaction Fee、Resource Accounting、Consensus Determinism、Ethereum

- [Revisiting Network Coding for Warm Blob Storage](https://www.usenix.org/conference/fast25/presentation/gan)
  - Chuang Gan, Huazhong University of Science and Technology; Yuchong Hu, Huazhong University of Science and Technology and Shenzhen Huazhong University of Science and Technology Research Institute; Leyan Zhao, Xin Zhao, Pengyu Gong, and Dan Feng, Huazhong University of Science and Technology
  - NCBlob 为大量 small warm blob 采用 non-systematic MSR code：所有块都是随机线性编码，使故障 repair 可连续读取而非按 systematic MSR 的细碎 sub-block scatter；正常读利用小 blob 的 access locality 控制解码开销。Alibaba Cloud 实验单块/整节点修复快最高 45%/38.4%，正常读仅降 2.1%。
  - 相较默认 systematic code 便于直读却让小块 repair I/O 极度不连续，核心创新是为 warm-blob workload 重新选择 coding form，以顺序 I/O 实现理论带宽优势。
  - Erasure Coding、MSR Code、Warm Blob Storage、Repair I/O、Alibaba Cloud

- [Mooncake: Trading More Storage for Less Computation — A KVCache-centric Architecture for Serving LLM Chatbot](https://www.usenix.org/conference/fast25/presentation/qin)
  - Ruoyu Qin, Moonshot AI and Tsinghua University; Zheming Li, Weiran He, and Jialei Cui, Moonshot AI; Feng Ren, Mingxing Zhang, Yongwei Wu, and Weimin Zheng, Tsinghua University; Xinran Xu, Moonshot AI Awarded Best Paper!
  - Mooncake 是 Kimi 的 KVCache-centric LLM serving：prefill 与 decode GPU pool 分离，GPU 集群闲置的 CPU、DRAM、SSD、NIC 组成全局分布式 KV store；scheduler 根据 prefix 命中、传输代价、各阶段负载和 TTFT/TPOT SLO 放置 request/缓存。千节点每日处理千亿 token，长上下文容量提高 59–498%。
  - 相较仅做 prefill/decode disaggregation、KV 仍绑定单机 GPU/host，核心创新是把 KV cache 升为跨层存储系统和全局调度中心，用更多便宜存储换 GPU 重算。
  - LLM Inference Serving、Disaggregated KV Cache、Prefill-Decode Separation、Global Scheduling、Long Context

- [Towards High-throughput and Low-latency Billion-scale Vector Search via CPU/GPU Collaborative Filtering and Re-ranking](https://www.usenix.org/conference/fast25/presentation/tian-bing)
  - Bing Tian, Haikun Liu, and Yuhang Tang, Huazhong University of Science and Technology; Shihai Xiao, Huawei Technologies Co., Ltd; Zhuohui Duan, Xiaofei Liao, and Hai Jin, Huazhong University of Science and Technology; Xuecang Zhang and Junhua Zhu, Huawei Technologies Co., Ltd; Yu Zhang, Huazhong University of Science and Technology
  - FusionANNS 在十亿向量、SSD+单张入门 GPU 上分层搜索：CPU/GPU multi-tier index 先协同筛选而避免 index 在两端来回 swap，heuristic reranker 只精确读取有机会进入 top-k 的向量，并合并重复 SSD I/O；在保持 recall/latency 时比 SPANN QPS 高 9.4–13.1 倍。
  - 相较 SSD ANNS I/O 多、全 GPU ANNS 成本/容量高，核心创新是围绕跨 CPU–GPU–SSD 数据移动共同设计 filtering、reranking 和 I/O dedup。
  - Vector Search、ANNS、CPU-GPU Collaboration、SSD、RAG Infrastructure

- [IMPRESS: An Importance-Informed Multi-Tier Prefix KV Storage System for Large Language Model Inference](https://www.usenix.org/conference/fast25/presentation/chen-weijian-impress)
  - Weijian Chen, Shuibing He, Haoyang Qu, Ruidong Zhang, Siling Yang, and Ping Chen, Zhejiang University; Yi Zheng and Baoxing Huai, Huawei Cloud; Gang Chen, Zhejiang University
  - IMPRESS 在 CPU memory 放不下长上下文 prefix KV、必须从 disk 加载时，不再读取所有 token/layer/head。它利用不同 attention head 的重要 token index 高相似性，低 I/O 地识别重要 KV，只加载会显著影响输出的部分；multi-tier placement/cache 同样按重要性保留，TTFT 最高降 2.8 倍而精度相近。
  - 相较 prefix cache 命中就全量读盘、I/O 可能比重算更慢，核心创新是把 model attention importance 变成 storage fetch/eviction 单位，实现选择性 KV materialization。
  - LLM KV Storage、Prefix Cache、Importance-aware I/O、Multi-tier Storage、TTFT

- [GPHash: An Efficient Hash Index for GPU with Byte-Granularity Persistent Memory](https://www.usenix.org/conference/fast25/presentation/chen-menglei)
  - Menglei Chen, Yu Hua, Zhangyu Chen, Ming Zhang, and Gen Dong, Wuhan National Laboratory for Optoelectronics, School of Computer, Huazhong University of Science and Technology
  - GPHash 面向 GPU 直接 byte-granular 访问 persistent memory：整 warp 协作执行 probe/update、无需 host CPU，CAS+slot state 以低开销保证 crash/并发一致性；GPU HBM 仅缓存 hot item 并控制 metadata/eviction，缓解 PM 到 GPU bandwidth gap，YCSB 最快高 27.62 倍。
  - 相较 CPU-assisted index 或把 CPU hash table 直接移植 GPU，核心创新是同时按 warp execution、PM consistency 和两级带宽重构 hash operation。
  - GPU Persistent Memory、Hash Index、Warp-cooperative Execution、Lock-free、Hot-item Cache

- [GeminiFS: A Companion File System for GPUs](https://www.usenix.org/conference/fast25/presentation/qiu)
  - Shi Qiu, Weinan Liu, Yifan Hu, Jianqin Yan, and Zhirong Shen, NICE Lab, Xiamen University; Xin Yao, Renhai Chen, and Gong Zhang, Huawei Theory Lab; Yiming Zhang, NICE Lab, Xiamen University and Shanghai Jiao Tong University
  - GeminiFS 给 GPU program 文件接口，却让 GPU 直接在 NVMe queue 发 I/O、绕过 CPU。host FS 仍管 namespace、权限和共享，metadata 嵌入文件以在 host/GPU companion FS 间同步；CPU/GPU 并行建 NVMe control plane，GPU-friendly software page cache 利用 HBM bandwidth，libGemini 屏蔽底层细节。
  - 相较 GPU direct storage 只有裸 block、或传统 FS 每次经 CPU 发请求，核心创新是 companion FS：控制/文件语义留给 host，GPU 获得独立直达 data path。
  - GPU File System、Direct NVMe、Metadata Synchronization、GPU Page Cache、ML Storage

- [3L-Cache: Low Overhead and Precise Learning-based Eviction Policy for Caches](https://www.usenix.org/conference/fast25/presentation/zhou-wenbin)
  - Wenbin Zhou, Beijing University of Technology; Zhixiong Niu and Yongqiang Xiong, Microsoft Research; Juan Fang and Qian Wang, Beijing University of Technology
  - 3L-Cache 保留 learning-based eviction 的 object/byte miss 优势，同时把生产 CPU 开销压低。训练数据收集器过滤不会改变决策的历史 request、按 workload 动态降低 retrain frequency；eviction 用双向 sampling 优先检查 unpopular object而非全 cache 打分，并自动调参数。4855 条 trace 上比 HALP/LRB 少 60.9/94.9% CPU。
  - 相较 learned policy 对每请求更新模型、淘汰时大范围 inference，核心创新是分别减少“学哪些样本、多久学一次、评哪些候选”三类无效计算。
  - Learning-based Cache、Eviction Policy、Online Training、Sampling、CPU Overhead

- [LeapGNN: Accelerating Distributed GNN Training Leveraging Feature-Centric Model Migration](https://www.usenix.org/conference/fast25/presentation/chen-weijian-leap)
  - Weijian Chen, Shuibing He, and Haoyang Qu, Zhejiang University; Xuechen Zhang, Washington State University Vancouver
  - LeapGNN 反转 distributed GNN 的数据移动：vertex feature 远大于 model 时，不把海量 feature 拉到固定 trainer，而让小 model 在持有 feature 的 worker 间迁移。micrograph 提高局部邻域复用，feature pre-gather 合并远端 fetch，动态合并 micrograph 减少 kernel switch/同步，训练最高快 4.2 倍。
  - 相较 model-centric partition 固定模型、跨机搬 feature，核心创新是以 feature locality 决定执行位置，将 model migration 作为更便宜的通信方向。
  - Distributed GNN Training、Model Migration、Feature Locality、Micrograph、Communication Reduction

- [HiDPU: A DPU-Oriented Hybrid Indexing Scheme for Disaggregated Storage Systems](https://www.usenix.org/conference/fast25/presentation/zhu)
  - Wenbin Zhu, Zhaoyan Shen, and Qian Wei, Shandong University; Renhai Chen, Tianjin University and Huawei Technologies Co., Ltd; Xin Yao, Huawei Technologies Co., Ltd; Dongxiao Yu, Shandong University; Zili Shao, The Chinese University of Hong Kong
  - HiDPU 为 disaggregated storage 的 logical→remote address translation 构造 DPU/host hybrid index：连续空间按特点选择 exact、PTHash、LPTHash segment，上层 layered learned index 定位 segment；小顶层和 hot metadata 常驻 DPU，一次交互访问 host 大索引，两阶段异步 update 保持副本一致，内存省 92%、查询快 6.3 倍。
  - 相较全 mapping 塞 DPU 容量不足、每次回 host latency 高，核心创新是利用 address continuity 混合多种压缩表示，并让 learned hierarchy 划分 DPU/host residency。
  - DPU、Disaggregated Storage、Hybrid Index、Learned Index、Address Translation

- [PIMLex: A High-Performance Learned Index with Processing-in-Memory](https://www.usenix.org/conference/fast25/presentation/cui)
  - Lixiao Cui, Kedi Yang, Yusen Li, Gang Wang, and Xiaoguang Liu, College of Computer Science, Nankai University
  - PIMLex 把 learned index 的 prediction/search 移到 UPMEM processing-in-memory module。两层结构让 PIM 保存/处理适合其容量与指令的 model/segment，大数据仍在 conventional DRAM；model 避开 PIM 不擅长运算，hotness-aware replication 将热点 index 分散到多 module，吞吐比 PIM baseline 高 36.5 倍。
  - 相较把完整 learned index 塞进小容量 PIM 或仍由 CPU 受内存墙限制，核心创新是按 PIM capacity/compute 能力解耦两层索引并动态复制热点。
  - Processing-in-Memory、Learned Index、UPMEM、Hotness Replication、Memory Bandwidth

- [HaSiS: A Hardware-assisted Single-index Store for Hybrid Transactional and Analytical Processing](https://www.usenix.org/conference/fast25/presentation/huang)
  - Kecheng Huang, The Chinese University of Hong Kong; Zhaoyan Shen, Shandong University; Zili Shao, The Chinese University of Hong Kong; Feng Chen, Indiana University Bloomington; Tong Zhang, Rensselaer Polytechnic Institute and ScaleFlux Inc.
  - HaSiS 利用可透明压缩的 computational storage drive，使 HTAP B+-tree block 可以稀疏填充却不浪费物理容量：transaction update 原位/低成本维护行式可查结构，analytical scan 同一 index 即可读取新鲜数据，不再在 B+-tree 与 column store 间异步迁移，兼顾 OLTP/OLAP 和近即时 freshness。
  - 相较双/多 index 用复制换两类性能却产生 freshness lag，核心创新是借 CSD compression 消除 sparse single-index 的空间惩罚，从硬件能力重开 HTAP 设计空间。
  - HTAP、Computational Storage、Single Index、Transparent Compression、Data Freshness

- [AegonKV: A High Bandwidth, Low Tail Latency, and Low Storage Cost KV-Separated LSM Store with SmartSSD-based GC Offloading](https://www.usenix.org/conference/fast25/presentation/duan)
  - Zhuohui Duan, Hao Feng, Haikun Liu, Xiaofei Liao, Hai Jin, and Bangyu Li, Huazhong University of Science and Technology
  - AegonKV 将 KV-separated LSM 的 value-log garbage collection 卸载到 SmartSSD：offload-friendly layout 让设备扫描 live value、搬迁并回传紧凑 mapping，host foreground read/write 不与 GC 争 CPU/PCIe bandwidth；软硬件 protocol 异步协调 compaction/回收，吞吐高 1.28–3.3 倍、tail latency 低 37–66%。
  - 相较 host GC 在 CPU 与 I/O 之间做取舍，核心创新是把 value-region 回收闭环放进存储设备，并为 offload 重设 metadata/执行边界。
  - KV Separation、LSM-tree、SmartSSD、Garbage Collection Offload、Tail Latency

- [D2FS: Device-Driven Filesystem Garbage Collection](https://www.usenix.org/conference/fast25/presentation/kim-juwon)
  - Juwon Kim and Seungjae Lee, Korea Advanced Institute of Science and Technology (KAIST); Joontaek Oh, University of Wisconsin–Madison; Dongkun Shin, Sungkyunkwan University; Youjip Won, Korea Advanced Institute of Science and Technology (KAIST)
  - D2FS 让 flash device GC 同时完成 log-structured FS segment cleaning。Coupled GC 在 FTL 搬 valid page 时把其映射到新的 logical FS location，使物理/逻辑都重新聚集；migration upcall 异步通知 host mapping 变化，virtual overprovisioning 让 FTL 总能提前回收，host FS 不再二次搬同一数据。
  - 相较 F2FS GC 与 SSD FTL GC 两层独立造成双重写放大，核心创新是由 device relocation 反向更新 filesystem layout，将两次 GC 合并为一次。
  - Device-driven GC、Log-structured File System、FTL、Migration Upcall、Write Amplification

- [ShiftLock: Mitigate One-sided RDMA Lock Contention via Handover](https://www.usenix.org/conference/fast25/presentation/gao)
  - Jian Gao, Qing Wang, and Jiwu Shu, Tsinghua University Distinguished Artifact Award Winner
  - ShiftLock 在 one-sided RDMA lock 高争用时不让所有 client 反复 CAS server memory。当前 holder 用直接 client-to-client 协议把 lock handover 给本地排队 successor，waiter 本地等待；协议支持 reader-writer、任意 client、故障恢复与 starvation freedom，低争用仍保留 one-sided 快路径。
  - 相较 retry/spin 消耗 lock server inbound IOPS，核心创新是用 RDMA 直接协调构造去中心 MCS 式 wait queue，让锁所有权在 client 间移交。
  - RDMA Lock、Client-to-client Handover、Reader-Writer Lock、Contention、Distributed Storage

- [Selective On-Device Execution of Data-Dependent Read I/Os](https://www.usenix.org/conference/fast25/presentation/park)
  - Chanyoung Park, Minu Chung, and Hyungon Moon, UNIST (Ulsan National Institute of Science and Technology)
  - 该工作把遍历 B+-tree/LSM 等 read-only on-disk structure 的 data-dependent read chain 部分下沉 storage device：设备读取 node 后立即解析 next pointer 并继续 I/O，减少 host round trip；大量并发时与 in-kernel function 分工，设备快速推进依赖链、内核聚合/管理 request。WiredTiger P99 最多降 3.85%。
  - 相较 on-device function 只做过滤预处理、in-kernel traversal 每一层仍跨 PCIe，核心创新是选择性把 pointer-chasing control flow放入设备并与内核协作。
  - Computational Storage、Data-dependent I/O、B+-tree、WiredTiger、On-device Execution

- [On Scalable Integrity Checking for Secure Cloud Disks](https://www.usenix.org/conference/fast25/presentation/burke)
