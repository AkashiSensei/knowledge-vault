# SoCC 2026 论文列表（当前第一轮，非最终完整名单）

截至 2026 年 9 月 20 日，SoCC 2026 官方仅公布 Round 1 的 19 篇录用论文；第二轮通知日期为 9 月 26 日，因此本页不是 SoCC 2026 最终完整论文列表，也不能视为最终 proceedings。官方同时说明 shepherding 期间标题和作者名单仍可能变化。已找到并校验的 10 份合法公开 PDF 保存在 `reference/SoCC/2026/`；FCP、FlowWise 和 TRAM 的公开全文仍使用早期题名，条目中已标明对应关系。

- [Spanner-RSS+: Diagnosing and Reducing Safe-Time Waiting of Read-only Transactions in Spanner-RSS](https://acmsocc.org/2026/accepted-papers.html)
  - Sejong Kim、Hena Cho、Yon Dohn Chung；Korea University。
  - 该工作面向 Spanner-RSS 中只读事务的 safe-time waiting：当副本尚不能证明自己已推进到请求读取时间戳时，只读事务仍会等待。现有公开资料只有官方标题和作者名单，尚未披露 RSS+ 用什么附加状态、判定条件或协议改动缩短这段等待，也没有公开实验数字。
  - 相比原始 Spanner-RSS 已经通过放宽实时顺序、减少与并发读写事务冲突造成的阻塞，RSS+ 把剩余的 safe-time 等待单独识别为瓶颈并进一步处理；具体机制仍需等正式论文，不能由题名推断。
  - Geo-distributed Database, Read-only Transactions, Consistency Protocol, Safe-time Waiting, Storage Systems

- [FCP: Fast User-space RDMA Control Plane Setup for Elastic Computing](https://snowzjx.me/assets/swift-paper.pdf)
  - Junxue Zhang、Han Tian、Xinyang Huang、Wenxue Li、Kaiqiang Xu、Dian Shen、Kai Chen；University of Science and Technology of China、Hong Kong University of Science and Technology、Southeast University、Google。
  - 该工作面向 serverless 等弹性计算任务的冷启动和 fork/warm 启动，解决用户态 RDMA 在打开设备、注册内存和建立连接时控制面启动过慢的问题。公开全文使用早期题名 Swift：它缓存 `libibverbs` 中可跨启动复用的设备检查结果，并利用 fork 继承共享 RDMA 资源，使控制面建立约降至 2.5 ms，同时保留用户态 RDMA 数据路径。
  - 相比 KRCORE 一类为微秒级启动引入内核态抽象的方案，核心创新是重新测量并推翻“用户态 RDMA 控制面必然很慢且难共享”的前提，用缓存与进程继承得到更简单的用户态路径，而不是把复杂度移入内核。
  - Elastic Computing, Serverless, RDMA Control Plane, User-space Networking, Cold/Warm Start

- [FlowWise: Fast–Slow Model Orchestration for Line-Rate Network Traffic Intelligence](https://arxiv.org/abs/2402.03694)
  - Shinan Liu、Ted Shaowang、Gerry Wan、Jeewon Chae、Jonatas Marques、Sanjay Krishnan、Nick Feamster；University of Hong Kong、University of Chicago、Stanford University、Federal University of Rio Grande do Sul。
  - 该工作面向高到达率的逐流网络流量分类，在每条 flow 的包到达过程中先用少量包和快速模型推断，只有置信度不足时才继续等待更多包并升级到慢而准确的模型。公开预印本使用早期题名 ServeFlow；其 CPU 原型让 76.3% 的流在 16 ms 内完成推断，中位端到端时延降低 40.5 倍，并达到每秒 48.5K 条新流的服务率。
  - 相比对所有流固定收集相同数量的包并运行同一个复杂模型，核心创新是把“收集到第几个包”和“调用哪一级模型”合成逐流的级联决策，并利用网络包间等待时间隐藏慢模型成本。
  - ML for Systems, Network Traffic Intelligence, Per-flow Cascaded Inference, Fast–Slow Models, Streaming Serving

- [FedRD: Towards Memory-efficient Federated Learning via Adaptive Recomputation and Defragmentation](https://acmsocc.org/2026/accepted-papers.html)
  - Kahou Tam、Ziyu Gong、Li Li、ChengZhong Xu；University of Macau。
  - 官方题名可确认该工作解决联邦学习客户端训练的内存压力，并把自适应重计算与内存碎片整理作为两个主要手段：前者用额外计算换取激活驻留空间，后者回收“总空闲量足够但缺少连续空间”的不可用内存。论文正文或摘要尚未公开，因此无法确认它针对何种模型、在哪个张量粒度决策，以及依据峰值内存、运行时间还是设备异构状态进行自适应。
  - 相比固定 activation checkpoint/recomputation 计划或独立的分配器整理，题名表明其创新在于联邦训练期间联合处理重计算与碎片问题；两者如何协调以及相对既有系统的量化优势仍待正式论文核实。
  - Federated Learning Systems, Training Memory, Adaptive Recomputation, Memory Defragmentation, Edge Training

- [PEACE: Power and Performance Aware Colocation for Efficient GPU Spatial Partitioning](https://www3.cs.stonybrook.edu/~anshul/socc26_peace.pdf)
  - Bing-Shiun Han、Chaitanya Sundeep Subhedar、Kunaal Parekh、Wan-Chu Lin、Zhenhua Liu、Anshul Gandhi；Stony Brook University。
  - PEACE 在有功率上限的单 GPU 上为并置的训练、推理或科学 CUDA workload 选择 MPS 的 SM 空间切分。它离线只剖析单个 workload 在 10% 粒度 SM 份额和低/中/高三个代表频率下的 GPU 指标与吞吐敏感度，用 Extra Trees 预测候选并置方案的总功率和吞吐；在线过滤超出 power cap 的方案、选择预测吞吐最高的 SM 切分，再由 DVFS 控制器执行功率约束。
  - 相比只做功率封顶、平均切分，或依据 SM activity/吞吐 knee 调份额的方案，核心创新是显式建模“power cap 改变频率、频率又改变最优 SM 切分”的耦合关系，而且不需要理解应用语义或穷举每组并置 workload。它在 V100/A6000、16 个 DL/CUDA workload 上达到离线最优吞吐的 93%–97%，较基线提高 20%–94%。
  - ML for Systems, GPU Colocation, MPS Spatial Partitioning, Power Capping, Throughput Prediction

- [Spandana: Reconciling Strict SLOs with Low Cost under Fine-Grained Load Fluctuations](https://arxiv.org/abs/2606.30533)
  - Dilina Dehigama、Shyam Jesalpura、Zeyu Xu、Marton Nemeth、Shengda Zhu、Marios Kogias、Boris Grot；University of Edinburgh、Imperial College London。
  - Spandana 面向存在亚秒级 microburst 的在线云服务，以每个请求为粒度在常驻 VM 和按需 FaaS 之间分流：VM 旁的轻量控制器估计本地服务时间，能在 SLO 内完成的请求留在 VM，可能违约的请求送往 AWS Lambda 一类 serverless 后端；全局资源分配器再结合 VM 成本、FaaS 成本和负载波动决定 VM 数量。
  - 相比单独依赖反应式/预测式 autoscaling，或用固定规则混合 VM 与 FaaS，核心创新是把快速的逐请求 SLO 保护与慢速的全局成本优化解耦。实验中 CPU 利用率为 76%–86%，相较三个基线降低 5%–44% 成本并保持严格 SLO。
  - Cloud Autoscaling, Request-level Routing, VM–FaaS Hybrid, SLO Enforcement, Cost Optimization

- [TRAM: Tree-based Atomic Multicast on RDMA](https://arxiv.org/abs/2509.07781)
  - Lorenzo Martignetti、Eliã Batista、Gianpaolo Cugola、Fernando Pedone；Università della Svizzera italiana、Politecnico di Milano。
  - TRAM 为跨多个副本组/分片的请求提供一致的 atomic multicast 顺序。公开预印本使用早期题名 Scaling Atomic Ordering in Shared Memory：目的组按静态 overlay tree 协调，组内 leader 用 RDMA one-sided write 直接写 follower 日志并利用写权限切换处理 leader 变更，从而减少消息传递和全组协调。
  - 相比使用完整 DAG 的 genuine multicast 或让所有目的组直接协调，核心创新是以 partially-genuine 的树形结构换取更低通信与同步成本，再用 RDMA 访问权限维持安全复制。公开版本报告相对共享内存协议吞吐提高 3 倍以上、时延降低 2.3 倍以上。
  - Distributed Systems, Atomic Multicast, RDMA, Replication, Overlay Tree

- [Tessera: Contract-Driven Cost–SLO Optimization for Multi-tenant GPU Clouds](https://acmsocc.org/2026/accepted-papers.html)
  - Rui Li、Shuang Cao；Hill Research。
  - 官方题名可确认 Tessera 面向多租户 GPU 云，把租户 contract 中的成本与 SLO 作为资源优化约束，而不是只追求设备利用率。当前没有公开摘要或正文，尚不能确认它优化的是实例购买、模型放置、GPU 切分、请求调度还是这些决策的组合，也不能确认 contract 中包含哪些性能/价格条款。
  - 相比先做资源分配、再被动检查 SLO 的思路，题名所体现的核心变化是让合同约束直接驱动成本–SLO 联合优化；具体求解器、在线状态和实验收益仍待正式论文。
  - Multi-tenant GPU Cloud, Contract-aware Resource Management, Cost–SLO Trade-off, GPU Scheduling

- [ExclaveFL: Verifiable Claims for Federated Learning using Exclaves](https://arxiv.org/abs/2412.10537)
  - Jinnan Guo、Kapil Vaswani、Andrew Paverd、Peter Pietzuch；Imperial College London、Microsoft Azure Research、Microsoft Security Response Center。
  - ExclaveFL 在互不信任的数据提供方共同训练模型时，不把重点放在隐藏训练内容，而是让每个本地训练、差分隐私处理和聚合任务在 integrity-only 的 exclave 中运行；每次任务把代码、输入和输出的度量写入硬件签名的 runtime attestation，并登记到透明日志，审计者据此重建 attested dataflow graph，检查数据/模型投毒、漏聚合或中途更换数据等违规行为。
  - 相比传统 TEE 主要保护机密性且只提供粗粒度启动证明，核心创新是用不保存任意应用秘密的 exclave 降低侧信道攻击面，并为联邦训练的每个数据变换生成可组合的细粒度执行证据。原型在 VGG9、BERT、GPT-2 等训练上开销低于约 9%。
  - Federated Learning Security, Exclave/TEE, Runtime Attestation, Verifiable Training, Provenance Audit

- [Cadence: Taming Coupled Contention in Disaggregated Agent Clouds](https://acmsocc.org/2026/accepted-papers.html)
  - Rui Li、Shuang Cao；Hill Research。
  - Cadence 的研究对象是 disaggregated agent cloud 中相互耦合的资源竞争，即 agent workflow 的不同执行/状态组件分离部署后，一个组件的拥塞会沿调用链影响其他组件及端到端服务。官方尚未公开摘要或正文，因此不能确认其具体拆分对象是模型、工具、memory、sandbox 还是存储，也不能确认它用何种遥测信号和控制算法治理竞争。
  - 它应归为 Agent Infra：目标是优化承载 agent 规划—工具调用—反馈链的云资源，而不是改进 agent 自身的规划、记忆或反思算法。相较把各资源池独立扩缩容或调度，题名所指的核心创新是显式处理跨池 contention coupling；具体机制仍待论文公开。
  - Agent Infra, Disaggregated Agent Cloud, Coupled Resource Contention, Cross-component Scheduling, SLO Isolation

- [The Kernel Always Knows: Understanding Isolation via Kernel Objects](https://anjali05.github.io/papers/socc26.pdf)
  - Anjali、Michael M. Swift；University of Wisconsin–Madison。
  - 该工作把容器和 microVM 的隔离从“用了哪种虚拟化抽象”细化为“两个 workload 实际共享哪些 host-kernel object”。LIMA 用 eBPF 动态跟踪锁获取，再以 Linux 源码静态分析把 lock 映射回 inode、journal、page allocator 等结构，从而比较 LXC、gVisor 和 Firecracker 在不同 workload 下的共享对象足迹和竞争强度。
  - 相比 perf/ftrace 只显示时间花在哪里，或仅按容器/VM 类型给出定性安全判断，核心创新是把同步事件作为共享状态的可测代理并定位到具体 kernel object。测量发现文件系统 journal 与内核页分配器是最常见共享来源，也说明隔离是随平台和 workload 改变的连续谱。
  - Cloud Isolation, Kernel Objects, eBPF Tracing, Containers/MicroVMs, Interference Analysis

- [Memory-Decoupled Layer-Wise Fine-Tuning for Efficient On-Device LLM Adaptation](https://jingguangli.com/publications/)
  - Yebo Wu、Jingguang Li、Chunlin Tian、Kahou Tam、Zhijiang Guo、Li Li；University of Macau、Hong Kong University of Science and Technology (Guangzhou)。
  - EdgeLLM 面向边缘设备参与 LLM 联邦微调时“模型静态参数本身已超过设备内存”的训练瓶颈，把端到端更新改造成逐层训练管线：设备只保留最小活跃层集合并卸载非活跃层，Resource Scheduler 按实时可用内存映射工作，Training Coordinator 用虚拟化上下文维持跨层语义，Execution Planner 裁掉冗余计算并优先适配关键层，I/O Manager 用异步预取和驱逐隐藏换层开销。
  - 相比要求整张计算图和完整模型常驻设备，核心创新是把模型容量与设备峰值内存解耦，同时处理逐层训练造成的语义断裂和 I/O 成本。作者公开摘要报告最高 11.86% 性能提升、2.08 倍收敛加速和 1.78 倍通信开销下降；这是 LLM 训练/适配系统，不是推理系统，也不是 Agent 系统。
  - Federated LLM Fine-tuning, On-device Training, Layer-wise Adaptation, Memory Offloading, Cloud–Edge Systems

- [BoxD: Managing GPU Managed Memory](https://acmsocc.org/2026/accepted-papers.html)
  - Utkarsh Tiwari、Purushottam Kulkarni；Indian Institute of Technology Bombay。
  - 官方题名只足以确认 BoxD 研究 CUDA/GPU managed memory 的系统管理问题；这类内存由驱动在 CPU 与 GPU 间迁移页面，容易受缺页、迁移和 thrashing 影响。当前没有公开摘要或正文，不能据此断言 BoxD 的 “Box” 是哪种隔离/分组抽象，也不能确认它控制页面放置、预取、回收还是多进程配额。
  - 相比把 Unified/Managed Memory 的驱动默认策略当成黑盒，题名显示其贡献应是把 managed memory 变为显式管理对象；具体状态、动作和优于既有预取/迁移策略之处尚待正式论文。
  - GPU Memory Management, CUDA Managed Memory, CPU–GPU Page Migration, Memory Oversubscription

- [Robust and Efficient Replication with CAV Data Structures](https://acmsocc.org/2026/accepted-papers.html)
  - Eliã Batista、Eduardo Alchieri、Paulo Coelho、Fernando Dotti、Fernando Pedone；Università della Svizzera italiana、University of Brasília、Federal University of Uberlândia、Pontifícia Universidade Católica do Rio Grande do Sul。
  - 官方题名可确认该工作以一种 CAV data structure 构建兼顾鲁棒性与效率的复制机制，但目前公开会议页和作者出版物页都没有展开 CAV 的全称、操作语义、故障模型或复制粒度。为避免把同名缩写误套到论文上，本条不推测其内部算法。
  - 相比通用复制协议，题名体现的创新方向是让专用数据结构承担复制中的一致性/恢复工作；它如何减少协调、支持并发或容忍故障，必须等摘要或全文后才能可靠判断。
  - Replication, Fault Tolerance, Distributed Data Structures, CAV, Distributed Systems

- [SlimeMold: Scaling Distributed Hardware Load Balancers via a Unified Giant Connection Table](https://www.microsoft.com/en-us/research/publication/slimemold-scaling-distributed-hardware-load-balancers-via-a-unified-giant-connection-table/)
  - Ziyuan Liu、Zhixiong Niu、Ran Shu、Jianqin Zhang、Guohong Lai、Liang Gao、Na Wang、Zongying He、Jacob Nelson、Dan R. K. Ports、Lihua Yuan、Peng Cheng、Yongqiang Xiong；Beihang University、Microsoft Research、Ruijie Networks、Broadcom、Microsoft。
  - SlimeMold 把多台异构可编程交换机的 CPS 与连接表容量汇成一个逻辑 Giant Connection Table；它将 flow-hash key space 划为细粒度 segment，按节点连接表大小和 CPS 能力分配，每个入口交换机先查 segment owner，再把包送到持有连接状态的节点。软件慢路径保存全量状态并处理新连接，硬件快路径处理已缓存 flow，同时支持少迁移重平衡与 segment 级备份/故障接管。
  - 相比按 VIP 粗粒度切分并依赖 ECMP 的 scale-out，核心创新是按连接表 segment 统一池化异构 HLB 资源，既维持 per-connection consistency，又不因 VIP 热度变化频繁整体迁移。Broadcom BCM56788 SmartToR 原型扩到四个逻辑节点接近线性，仿真在异构动态流量下资源利用率超过 98%。
  - Datacenter Networking, Hardware Load Balancer, Programmable Switch, Connection-state Sharding, Fault Tolerance

- [MosaicKV: SLO-Aware KV-Cache Virtualization for Multi-Tenant LLM Serving in the Cloud](https://acmsocc.org/2026/accepted-papers.html)
  - Rui Li、Shuang Cao；Hill Research。
  - 官方题名可确认该工作在多租户 LLM 云服务中把 KV cache 虚拟化，并以请求/租户 SLO 约束来管理缓存资源；尚未公开它是否做 GPU/CPU/SSD 分层、跨实例池化、逐请求配额、驱逐或迁移，也没有公开评价模型与指标。它与 Sheng Qiang 等人的同名预印本《MosaicKV: Serving Long-Context LLM with Dynamic Two-D KV Cache Compression》（arXiv:2607.00760）作者和题名均不同，不能混为一篇。
  - 相比每个模型实例固定占有 KV cache，题名所体现的创新是为多租户服务提供带 SLO 语义的 KV-cache 虚拟化；具体虚拟化边界与策略仍待正式论文。它是通用 LLM Infra，不因 agent 可能使用长上下文就归为 Agent Infra。
  - LLM Infra, Multi-tenant LLM Serving, KV-cache Virtualization, SLO-aware Memory Management, Cloud AI

- [Evaluating Agentic Systems Across the Lifecycle: A Taxonomy of Drifts and Success Criteria](https://acmsocc.org/2026/accepted-papers.html)
  - Gaurav Saxena、Ildar Iskhakov、Innokentii Konstantinov、Matvey Kukuy；Independent Researcher、Archestra.AI。
  - 官方题名表明该工作不只在静态 benchmark 上测最终答案，而是沿 agentic system 生命周期整理会使行为或能力发生偏移的 drift，并为不同阶段定义 success criteria。摘要和正文尚未公开，因此不能确认 taxonomy 的具体阶段、drift 类别、指标以及是否包含实证 benchmark。
  - 相比只以单次 task success/answer accuracy 评估模型，核心方向是把长期运行、工具与环境变化下的 agent 系统评测组织成生命周期框架。它属于 Agent System Evaluation，而不是 Agent Infra；当前证据也不足以说它直接改进规划、记忆或行动—反馈算法。
  - Agent System Evaluation, Agent Lifecycle, Drift Taxonomy, Success Criteria, Evaluation Methodology

- [No Request Left Behind: Tackling Heterogeneity in Long-Context LLM Inference with Medha](https://arxiv.org/abs/2409.17264)
  - Amey Agrawal、Haoran Qiu、Junda Chen、Íñigo Goiri、Chaojie Zhang、Rayyan Shahid、Ramachandran Ramjee、Alexey Tumanov、Esha Choukse；Georgia Institute of Technology、Microsoft、University of California San Diego。
  - Medha 面向同一 LLM 实例混合短交互请求与百万 token 长请求时，长 prefill 挡住短请求的 convoy effect。它把长 prefill 切成可抢占 chunk，以 Adaptive Chunking 随注意力/MLP 瓶颈变化调块大小，用 Stream Pipeline Parallelism 跨 stage 流水 chunk、KV-Cache Parallelism 分散 decode attention，再由 Length-Aware Relative Slack 调度器结合请求长度、deadline 与剩余 slack 插入短请求并避免长请求饥饿。
  - 相比 LoongServe、vLLM、Sarathi 等 non-preemptive serving，核心创新不是仅按长度增加 context parallelism，而是协同设计可抢占执行、两种并行和 deadline-aware 调度，使百万 token prefill 也能细粒度让出 GPU。混合负载下吞吐提高 5.7 倍，中位与 P99 时延分别降低 30 倍和 174 倍。它是通用 LLM Infra，不是 Agent Infra。
  - LLM Infra, Long-context Inference, Preemptive Scheduling, Adaptive Chunked Prefill, KV-cache Parallelism

- [On Evaluating Performance of LLM Inference Serving Systems](https://arxiv.org/abs/2507.09019)
  - Amey Agrawal、Nitin Kedia、Anmol Agarwal、Jayashree Mohan、Nipun Kwatra、Souvik Kundu、Ramachandran Ramjee、Alexey Tumanov；Georgia Institute of Technology、University of Texas at Austin、Apple、Microsoft Research、Intel Research。
  - 该工作系统检查 LLM serving 论文如何做性能实验，把误导性做法分为 baseline fairness、evaluation setup 和 metric design 三类，例如把工程优化差异误算成算法收益、使用不代表生产长度/到达模式的 workload，或用平均/归一化指标掩盖 generation stall。作者给出评测 checklist，并用 bursty、非均匀产出 token 的 speculative decoding 作为案例展示错误指标如何改变结论。
  - 相比再提出一个 serving runtime 或单一新指标，核心创新是把 LLM 推理的 prefill/decode 双阶段、请求异构与交互式时间约束纳入一套可复查的反模式框架，让不同系统的结果更公平、可复现且贴近用户体验；它研究评测方法，不直接优化在线执行路径。
  - LLM Serving Evaluation, Benchmark Methodology, Baseline Fairness, Workload Design, Metric Anti-patterns
