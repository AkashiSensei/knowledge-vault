# SoCC 2024 论文列表

ACM 正式 proceedings（父 DOI `10.1145/3698038`）中以 `10.1145/3698038.*` 标识的 63 篇正式论文。以下标题均链接至论文 DOI；已找到的 10 份合法公开 PDF 保存在 `reference/SoCC/2024/`。

- [Hops: Fine-grained heterogeneous sensing, efficient and fair Deep Learning cluster scheduling system](https://doi.org/10.1145/3698038.3698515)
  - Qinghe Wang、Futian Wang、Xinwei Zheng；School of Artificial Intelligence, Anhui University, Hefei, Anhui, China、Anhui University, Hefei, Anhui, China、Institute of Artificial Intelligence, Hefei Comprehensive National, Science Center, Hefei, Anhui, China。
  - Hops 面向含不同代际和型号 GPU 的深度学习训练集群，在较细粒度上感知作业在各设备上的实际训练效率与资源异构，再据此联合决定作业放置和 GPU 分配；调度目标同时考虑集群效率与作业间公平，而不是用 GPU 数量把异构设备视为等价资源。
  - 相较依赖离线画像或按 GPU 张数分配的异构调度器，核心创新是把细粒度硬件感知得到的有效训练能力直接纳入公平调度决策。
  - 异构 GPU 集群、DL 训练调度、细粒度性能感知、公平性、Goodput

- [Queue Management for SLO-Oriented Large Language Model Serving](https://doi.org/10.1145/3698038.3698523)
  - Archit Patke、Dhemath Reddy、Saurabh Jha、Haoran Qiu、Christian Pinto、Chandra Narayanaswami、Zbigniew Kalbarczyk、Ravishankar Iyer；University of Illinois at Urbana-Champaign, Urbana, Illinois, USA、IBM Research, Yorktown Heights, New York, USA、IBM Research, Dublin, Ireland。
  - QLM 面向同一异构 GPU 集群中混合交互式与 batch LLM 推理、多个模型和不同 SLO 的请求，以 request group 为粒度维护全局队列；RWT estimator 预测等待时间，global scheduler 据此排序各实例的 virtual queue，并触发 request pulling/eviction、KV cache 异步迁移、load balancing 和 model swapping。
  - 相较只在单模型内部做 continuous batching 或按请求抢占，核心创新是把 SLO 感知的队列顺序变成统一控制面，同时编排四类会改变 GPU/CPU/KV 状态的 serving operation。
  - LLM Serving、交互式与批量请求、SLO 队列、KV Cache Eviction、Model Swapping

- [Kale: Elastic GPU Scheduling for Online DL Model Training](https://doi.org/10.1145/3698038.3698532)
  - Ziyang Liu、Renyu Yang、Jin Ouyang、Weihan Jiang、Tianyu Ye、Menghao Zhang、Sui Huang、Jiaming Huang、Chengru Song、Di Zhang、Tianyu Wo、Chunming Hu；Beihang University, Beijing, China、Kuaishou Inc., Beijing, China。
  - KALE 面向推荐/广告模型持续接收新样本的在线训练，根据样本到达速率和训练积压自动决定 GPU 数量；扩缩容后，它重分片和 shuffle 尚未处理的数据，使各 worker 的剩余样本更均衡，避免某个 worker 形成长尾并拖慢同步迭代，已部署在快手生产集群。
  - 相较在 backlog 出现后才按阈值增减 GPU，核心创新是联合预测所需 GPU 与扩缩容后的数据再均衡，让资源弹性真正转化为在线模型新鲜度。
  - 在线 DL 训练、弹性 GPU 调度、样本到达波动、数据重平衡、生产推荐系统

- [FedCaSe: Enhancing Federated Learning with Heterogeneity-aware Caching and Scheduling](https://doi.org/10.1145/3698038.3698559)
  - Redwan Ibne Seraj Khan、Arnab K. Paul、Yue Cheng、Xun Steve Jian、Ali R. Butt；Virginia Tech, Virginia, USA、BITS Pilani, KK Birla Goa Campus, Goa, India、University of Virginia, Virginia, USA、Virgina Tech, Virginia, USA。
  - FedCaSe 面向客户端本地样本量、内存缓存空间和计算速度都高度异构的 FL，在客户端缓存“更有训练价值”的样本，采样时考虑各自可容纳的 working set，并按历史样本经验与设备能力选择客户端/安排轮次；三者共同提高 read hit ratio、减少远端数据读取并缩短训练轮次。
  - 相较把客户端缓存当统一大小的 LRU/LFU，核心创新是联合优化样本缓存、数据采样和客户端调度，使缓存命中与模型学习价值在异构设备上协同。
  - 联邦学习系统、客户端缓存、异构设备、Experience-aware Sampling、客户端调度

- [SQLStateGuard: Statement-Level SQL Injection Defense Based on Learning-Driven Middleware](https://doi.org/10.1145/3698038.3698569)
  - Xin Liu、Yuanyuan Huang、Tianyi Wang、Song Li、Weina Niu、Jun Shen、Qingguo Zhou、Xiaokang Zhou；School of Information Science & Engineering, Lanzhou University, Lanzhou, Gansu, China、The State Key Laboratory of Blockchain and Data Security, Zhejiang University, Hangzhou, Zhejiang, China、School of Computer Science and Engineering, University of Electronic Science and Technology of China, Chengdu, Sichuan, China、School of Computing and Information Technology, University of Wollongong, Wollongong, New South Wales, Australia、Kansai University, Suita, Osaka, Japan。
  - SQLStateGuard 在数据库中间件即将执行 SQL statement 时截获语句，而不是从 HTTP 流量或源码猜测攻击；SQLSG-Net 先做 SQL 语义解析，再用带 gated linear unit 的数据库专用模型比较正常/恶意语句差异，分类并直接阻断注入，二分类准确率超过 99.9%。
  - 相较规则 WAF、流量 payload 检测或静态 taint analysis，核心创新是把 RASP 下沉到 statement execution 边界，并用语义模型减少不会真正形成恶意 SQL 的误报。
  - SQL 注入防御、RASP Middleware、Statement-Level Detection、NLP 安全模型、数据库安全

- [Vista: Machine Learning based Database Performance Troubleshooting Framework in Amazon RDS](https://doi.org/10.1145/3698038.3698519)
  - Vikramank Singh、Zhao Song、Balakrishnan Murali Narayanaswamy、Kapil Eknath Vaidya、Tim Kraska；Amazon Web Services、Narayanaswamy Amazon Web Services、Amazon Web Services, MIT。
  - Vista 在数十万 Amazon RDS 实例上自动执行异常检测和根因分析：自监督深度 autoregressive model 用周期对齐与 skip connection 适应噪声、非平稳和不同周期的负载，再从每分钟数百万 SQL 中筛出支配查询，以 robust causal inference 关联异常 query statistics 与 wait event。
  - 相较静态阈值、要求用户给正常基线或在长尾数据上直接比较均值，核心创新是利用大规模 fleet 数据训练可跨数据库泛化的检测器，并用稳健长尾统计把 RCA 缩到少量可疑 SQL。
  - ML for Systems、数据库性能诊断、Amazon RDS、自监督异常检测、因果根因分析

- [Building AI Agents for Autonomous Clouds: Challenges and Design Principles](https://doi.org/10.1145/3698038.3698525)
  - Manish Shetty、Yinfang Chen、Gagan Somashekar、Minghua Ma、Yogesh Simmhan、Xuchao Zhang、Jonathan Mace、Dax Vandevoorde、Pedro Las-Casas、Shachee Mishra Gupta、Suman Nath、Chetan Bansal、Saravan Rajmohan；University of California, Berkeley、University of Illinois Urbana-Champaign、Microsoft、Indian Institue of Science、Microsoft Research、Agnes Scott College。
  - 这篇 vision paper 讨论让 AI Agent 承担云服务故障定位、根因分析和修复的需求，并给出 AIOpsLab 原型：平台部署微服务、生成负载、用 chaos engineering 注入故障，向 Agent 提供日志/指标/trace 与操作 API，再根据 Agent 的连续观测—诊断—行动—环境反馈评估恢复效果。
  - 相较用静态离线数据集评测一次性 AIOps 模型，核心创新是建立可复现的交互式 Agent-Cloud Interface，让运维 Agent 在真实状态会被行动改变的闭环环境中开发和比较。
  - Agent for Systems、AIOps Agent、故障定位与修复、Agent-Cloud Interface、交互式评测

- [Zero-SAD: Zero-Shot Learning Using Synthetic Abnormal Data for Abnormal Behavior Detection on Private Cloud](https://doi.org/10.1145/3698038.3698533)
  - Jae-Seok Kim、Joonho Seo、Seon-Jin Hwang、Jinmyeong Shin、Yoon-Ho Choi；Pusan National University, Busan, South Korea。
  - Zero-SAD 面向私有云中真实异常样本稀缺、攻击/故障类型不断变化的问题，用正常运行数据与合成异常构造训练对，使检测器在没有目标异常标注的情况下学习正常—异常边界，并对未见过的异常行为做 zero-shot 判别。
  - 相较依赖每类故障/攻击的历史标签，核心创新是用可控的 synthetic abnormal data 替代难以收集的私有云异常样本，训练能迁移到未知异常的检测模型。
  - 私有云安全、异常行为检测、Zero-Shot Learning、合成异常数据、未知威胁

- [Forecasting Algorithms for Intelligent Resource Scaling: An Experimental Analysis](https://doi.org/10.1145/3698038.3698564)
  - Yanlei Diao、Dominik Horn、Andreas Kipf、Oleksandr Shchur、Ines Benito、Wenjian Dong、Davide Pagano、Pascal Pfeil、Vikram Nathan、Balakrishnan Narayanaswamy、Tim Kraska；Amazon Web Services、UTN。
  - 该研究以 Amazon Redshift Serverless 的大规模真实查询序列为对象，对多类时间序列预测算法在负载规模、周期性、突发性和资源消耗预测上的表现做系统比较，分析哪些数据特征会使通用预测器失效，以指导后续自动扩缩容选择模型与特征。
  - 相较在合成或单一业务序列上报告一个新模型，核心创新是建立面向真实云查询负载的实验性诊断框架，揭示算法优劣随工作负载特征变化的边界。
  - Serverless 数据仓库、工作负载预测、资源扩缩容、时间序列、生产测量

- [Snapipeline: Accelerating Snapshot Startup for FaaS Containers](https://doi.org/10.1145/3698038.3698513)
  - Yuqiao Lan、Xiaohui Peng、Yifan Wang；Institute of Computing Technology, Chinese Academy of Sciences, Beijing, China University of Chinese Academy of Sciences, Beijing, China。
  - Snapipeline 面向用 snapshot 恢复 FaaS 容器的冷启动，压缩阶段把去重范围扩展到 file-mapped pages；恢复阶段根据内存页冷热先恢复执行必需页，并将 snapshot 解压、页面恢复和函数执行流水化，使解压退出启动关键路径，平均端到端延迟降低 53%。
  - 相较先完整解压 snapshot 再串行 restore，核心创新是以页热度建立跨解压—恢复—执行的 pipeline，同时消除 file-backed 页面冗余。
  - FaaS 冷启动、容器 Snapshot、页面冷热、流水线恢复、内存去重

- [En4S: Enabling SLOs in Serverless Storage Systems](https://doi.org/10.1145/3698038.3698529)
  - Minghao Xie、Chen Qian、Heiner Litz；UC Santa Cruz, USA。
  - En4S 是面向数据密集型 serverless 函数的解耦闪存临时对象存储，按请求 SLO 对共享设备做可扩展调度，并以自适应 burst control、token reclaim 和减少网络到存储数据拷贝等机制抑制严格/宽松租户间干扰；目标是在大量不同 SLO 并存时仍给出可预测尾延迟。
  - 相较 Redis/S3 或只能处理少量服务等级的 disaggregated store，核心创新是为短生命周期 serverless I/O 设计可扩展的多 SLO token 调度与突发回收机制。
  - Serverless 存储、解耦闪存、SLO 调度、QoS 隔离、Ephemeral Object Store

- [Pre-Warming is Not Enough: Accelerating Serverless Inference With Opportunistic Pre-Loading](https://doi.org/10.1145/3698038.3698509)
  - Yifan Sui、Hanfei Yu、Yitao Hu、Jianxun Li、Hao Wang；Shanghai Jiao Tong University, Shanghai, China、Stevens Institute of Technology, Hoboken, USA、Tianjin University, Tianjin, China。
  - InstaInfer 面向 serverless ML inference 的 cold start，指出容器已 warm 后加载框架库与模型仍是主要延迟；系统只利用现有 warm container/GPU 的空闲内存机会性预载 artifact，并随负载动态 load/offload，不额外改变 provider 的 keep-alive/pre-warm 策略，模型加载延迟最高降低 93%。
  - 相较只提前创建容器或永久预留模型副本，核心创新是把“容器 warm”与“ML artifact ready”分开，并在不新增常驻实例的前提下用集群空闲内存做机会性预载。
  - Serverless ML 推理、模型预加载、Cold Start、Warm Container、GPU 内存复用

- [Faascale: Scaling MicroVM Vertically for Serverless Computing with Memory Elasticity](https://doi.org/10.1145/3698038.3698512)
  - Xinmin Zhang、Qiang He、Hao Fan、Song Wu；CGCL/SCTS/BDTS, Huazhong University of Science and Technology, Wuhan, Hubei, China、CGCL/SCTS/BDTS, Huazhong University of Science and Technology, Jinyinhu Laboratory, Wuhan, Hubei, China, Jinyinhu Laboratory, China。
  - Faascale 面向 Firecracker microVM 承载的 serverless functions，不再通过新建更多 microVM 横向扩容，而是按与 function instance 绑定的内存 block 快速纵向增减容量，并预填充物理页避免 lazy population 延迟；内存 scaling 加快 2–3 个数量级，平均冷启动下降 89.01%。
  - 相较 memory balloon 以通用页为粒度或 snapshot 横向启动新实例，核心创新是为函数实例设计 block-bound memory elasticity 与预填充路径。
  - Serverless MicroVM、纵向扩缩容、Firecracker、内存弹性、冷启动

- [Rethinking the Networking Stack for Serverless Environments: A Sidecar Approach](https://doi.org/10.1145/3698038.3698561)
  - Vishwanath Seshagiri、Abhinav Gupta、Vahab Jabrayilov、Avani Wildani、Kostis Kaffes；Emory University, Atlanta, USA、Columbia University, NYC, USA、Cloudflare and Emory University, Atlanta, USA。
  - 这篇 vision paper 测量 Firecracker 等高度整合 serverless 环境中传统 guest 网络栈的路径开销，并提出把低开销数据面移到 sidecar 的新网络架构；sidecar 需要在控制面完成连接、策略与隔离管理，在数据面绕开重复的虚拟化/内核处理，同时维持现有安全边界。
  - 相较继续微调每个 microVM 内的传统网络栈，核心创新是把 serverless 网络栈重划分为共享 sidecar 数据面与隔离控制面，并明确实现该架构前需解决的问题。
  - Serverless 网络、Firecracker、Sidecar 数据面、虚拟化开销、隔离

- [Process-as-a-Service: Unifying Elastic and Stateful Clouds with Serverless Processes](https://doi.org/10.1145/3698038.3698567)
  - Marcin Copik、Alexandru Calotoiu、Gyorgy Rethy、Roman Böhringer、Rodrigo Bruno、Torsten Hoefler；ETH Zurich, Zurich, Switzerland、Oracle Labs, Zurich, Switzerland and ETH Zurich、OpenCore GmbH, Schindellegi, Switzerland、INESC-ID, Instituto Superior, Técnico, University of Lisbon, Lisbon, Portugal。
  - PraaS 把 OS process 抽象移植到 serverless：同一 cloud process 内的函数像线程一样共享近计算端的持久状态，并以 send/recv 通过共享内存、TCP 或 RDMA 通信；计算实例仍可由平台弹性回收，状态则被换出并在下次调用时惰性恢复，远程调用最高加速 17 倍。
  - 相较无状态 FaaS 每次经控制面并访问远端存储，核心创新是把计算生命周期与状态生命周期分离，让“可换出的有状态进程”同时保留 serverless 弹性和本地性。
  - Process-as-a-Service、Stateful Serverless、Cloud Process、直接调用通道、状态换入换出

- [AutoBurst: Autoscaling Burstable Instances for Cost-effective Latency SLOs](https://doi.org/10.1145/3698038.3698530)
  - Rubaba Hasan、Timothy Zhu、Bhuvan Urgaonkar；The Pennsylvania State University。
  - AutoBurst 面向有延迟 SLO 的在线服务，把低价但受 CPU credit/速率限制的 burstable 实例与常规实例组合使用；控制器联合决定两类实例数量以及何时使用 burst capacity，在负载变化下用短时全速能力吸收峰值，同时保证延迟并降低成本，实验最高节省 25%。
  - 相较只把 burstable 实例用于缓存备份或一次性 flash crowd，核心创新是将 credit/burst 状态纳入通用 autoscaling 控制，并同时调整 burstable 与 regular 容量。
  - 云自动扩缩容、Burstable Instance、延迟 SLO、CPU Credit、成本优化

- [Is It Time To Put Cold Starts In The Deep Freeze?](https://doi.org/10.1145/3698038.3698527)
  - Carlos Segarra、Ivan Durev、Peter Pietzuch；Imperial College London。
  - 这篇 vision paper 调查 35 篇 serverless 研究所用 workload，发现超过 80% 的函数语义上不要求低延迟，据此提出 DFaaS：用户标注 delay tolerance，平台可在 deadline 前延迟、中断、迁移和融合函数，以提高 CPU/加速器利用率而不执着于消除每次 cold start。
  - 相较把冷启动时延作为所有 FaaS workload 的首要指标，核心创新是将 delay tolerance 暴露为一等语义，用 deadline slack 换取资源整合空间。
  - Delay-Tolerant FaaS、批处理 Serverless、Deadline、函数融合、资源利用率

- [Towards Swap-Free, Continuous Ballooning for Fast, Cloud-Based Virtual Machine Migrations](https://doi.org/10.1145/3698038.3698543)
  - Kevin Alarcón Negy、Tycho Nightingale、Hakim Weatherspoon、Zhiming Shen；Exostellar, Inc.。
  - 该生产方案为不超卖的云 VM 修改 Linux balloon driver，并用用户态 continuous ballooning 在迁移前持续回收可释放页、在应用内存突增时及时归还，从而避免 swap 和 OOM；对接近 600 GB 的巨型 VM，额外开销不超过 8% 而迁移至少加快 52%。
  - 相较在迁移高风险期禁用 balloon 或依赖 swap，核心创新是让 balloon 回收与内存请求持续反馈，在巨幅 memory spike 和反复迁移下仍保证无交换、无 OOM。
  - VM 热迁移、Continuous Ballooning、内存回收、Swap-Free、OOM 安全

- [PCLive: Pipelined Restoration of Application Containers for Reduced Service Downtime](https://doi.org/10.1145/3698038.3698545)
  - Shiv Bhushan Tripathi、Debadatta Mishra；Department of Computer Science and Engineering, Indian Institute of Technology Kanpur, India。
  - PCLive 面向有大内存工作集的应用容器迁移：源端停止容器后，不再等待完整 checkpoint 被串行恢复，而是在目的端把恢复步骤流水化，让可用状态、内存页和后续恢复并行推进；相对 CRIU pre-copy，Redis 容器恢复阶段最高缩短约 38.8 倍、服务停机最高降低约 2.7 倍。
  - 相较只优化迁移前的预拷贝，核心创新是把目的端恢复本身拆成可重叠流水线，直接移除停机窗口中的串行恢复瓶颈。
  - 容器热迁移、Checkpoint/Restore、流水线恢复、CRIU、服务停机时间

- [Scheduling for Reduced Tail Task Latencies in Highly Utilized Datacenters](https://doi.org/10.1145/3698038.3698522)
  - Smita Vijayakumar、Anil Madhavapeddy、Evangelia Kalyvianaki；University of Cambridge, Cambridge, UK。
  - Murmuration 面向高利用率集群中一个 data-parallel job 的尾任务因排队过久拖慢整项作业的问题，让多个分布式 scheduler 交换 placement state，并尽量把同一 job 的任务安排在相近时间启动；队列重排还可按剩余作业规模调整调度/执行顺序。
  - 相较 Kubernetes 的集中放置或 Sparrow 只追求单任务快速决策，核心创新是把同一 job 各任务启动时间的 temporal proximity 作为分布式调度目标。
  - 数据中心调度、Tail Task Latency、分布式 Scheduler、Job-Aware Placement、高利用率集群

- [Krios: Scheduling Abstractions and Mechanisms for Enabling a LEO Compute Cloud](https://doi.org/10.1145/3698038.3698566)
  - Vaibhav Bhosale、Ada Gavrilovska、Ketan Bhardwaj；Georgia Institute of Technology, Atlanta, Georgia, USA。

  - 相较把地面 Kubernetes 调度直接搬到卫星或在所有卫星复制服务，核心创新是以虚拟地理 zone 隐藏轨道移动，并用预测式 handover 维持区域可用性。
  - LEO 云、卫星边缘计算、预测式 Handover、地理可用区、应用编排
