# FAST 2024 论文列表

FAST 2024 正式技术议程共收录 22 篇论文。以下标题链接至 USENIX 官方页面；每篇依次列出作者与机构、研究场景和系统机制、相较既有方法的核心创新，以及细粒度方向。22 份官方 PDF 均已保存至 `reference/FAST/2024/`。

- [TeRM: Extending RDMA-Attached Memory with SSD](https://www.usenix.org/conference/fast24/presentation/yang-zhe)
  - Zhe Yang, Qing Wang, Xiaojian Liao, and Youyou Lu, Tsinghua University; Keji Huang, Huawei Technologies Co., Ltd; Jiwu Shu, Tsinghua University
  - TeRM 让未经修改的 RDMA in-memory file/KV system 把容量扩展到 SSD，但 remote RNIC 仍像访问已 pin memory 一样读写。它在 memory node 预先管理 SSD↔DRAM page placement/transfer，使 RDMA miss 不触发 RNIC page fault、也不让 CPU 进入 request critical path，并控制网络/CPU 后台开销，性能接近全内存上界。
  - 相较 remote paging miss 后由 CPU fault handler 拉盘，核心创新是把 SSD extension 的地址解析和搬运移出一次 RDMA 访问路径，同时保持原有 one-sided interface。
  - RDMA Storage、SSD-extended Memory、One-sided Access、Page-fault Elimination、Memory Tiering

- [Combining Buffered I/O and Direct I/O in Distributed File Systems](https://www.usenix.org/conference/fast24/presentation/qian)
  - Yingjin Qian, Data Direct Networks; Marc-André Vef, Johannes Gutenberg University Mainz; Patrick Farrell and Andreas Dilger, Whamcloud Inc.; Xi Li and Shuichi Ihara, Data Direct Networks; Yinjin Fu, Sun Yat-Sen University; Wei Xue, Tsinghua University and Qinghai University; André Brinkmann, Johannes Gutenberg University Mainz
  - 该工作在 Lustre client/server 内对每段 I/O 透明选择 buffered I/O 或 direct I/O，而不让应用提前决定。decision 同时看 request size、file-lock contention 和可用内存：小/可复用访问利用 page cache，大顺序或内存紧张/锁竞争时 bypass；再配 delayed allocation 等机制，吞吐最高比原 Lustre 高 3 倍。
  - 相较全文件/全作业固定一种 I/O mode 或仅按大小切换，核心创新是将 cache、锁和内存压力纳入分布式文件系统内部的动态 per-I/O policy。
  - Distributed File System、Buffered/Direct I/O、Lustre、Lock Contention、Adaptive I/O Path

- [OmniCache: Collaborative Caching for Near-storage Accelerators](https://www.usenix.org/conference/fast24/presentation/zhang-jian)
  - Jian Zhang and Yujie Ren, Rutgers University; Marie Nguyen, Samsung; Changwoo Min, Igalia; Sudarsun Kannan, Rutgers University
  - OmniCache 为 near-storage accelerator 协同使用设备侧 cache 与 host DRAM：I/O/compute 尽量访问离执行器最近的副本，两级 cache 对并发读和计算保持协调；model-driven offloader 持续读取 CPU/device、queue、cache 和数据移动指标，决定算子在 host 还是 device 执行，并探索以 CXL 扩展共享内存。
  - 相较近盘计算只用容量有限的 device cache、或总回 host memory，核心创新是把两处 cache 与处理器 placement 放入同一动态模型，联合选择 data/compute locality。
  - Near-storage Computing、Collaborative Cache、Dynamic Offloading、CXL、Host-Device Locality

- [Symbiosis: The Art of Application and Kernel Cache Cooperation](https://www.usenix.org/conference/fast24/presentation/dai)
  - Yifan Dai, Jing Liu, Andrea Arpaci-Dusseau, and Remzi Arpaci-Dusseau, University of Wisconsin—Madison
  - Symbiosis 解决 LevelDB、WiredTiger、RocksDB 同时有 application block cache 和 kernel page cache、静态划分会重复或挤占内存的问题。runtime 依据 workload hit/IO 行为动态调两层 cache 容量，让应用 cache 保存高价值对象、内核仍承担文件页复用；跨读密集 workload 平均快 1.5 倍、最高 5 倍。
  - 相较管理员手工固定两个 cache 上限，核心创新是把原本互不知情的 application/kernel eviction domain 作为一个共享内存预算在线协调。
  - Key-Value Store、Application/Kernel Cache、Dynamic Memory Partition、RocksDB、Page Cache

- [Optimizing File Systems on Heterogeneous Memory by Integrating DRAM Cache with Virtual Memory Management](https://www.usenix.org/conference/fast24/presentation/liu-yubo)
  - Yubo Liu, Yuxin Ren, Mingrui Liu, Hongbo Li, Hanjun Guo, Xie Miao, and Xinwei Hu, Huawei Technologies Co., Ltd.; Haibo Chen, Huawei Technologies Co., Ltd. and Shanghai Jiao Tong University
  - FLAC 为 DRAM+persistent-memory file system 把 DRAM cache 与 virtual-memory mapping 合并管理。zero-copy caching 让 application 直接映射 cache page，避免 file-system buffer 再拷贝；parallel cache manager 并发同步/迁移 DRAM 与 PM，并由 FlacFS 暴露文件语义，真实应用比 DAX/cache-based FS 最高快约 10 倍。
  - 相较 DAX 绕 cache 频繁触碰慢 PM、传统 cache 又在应用/文件系统间搬数据，核心创新是让 VM page mapping 成为 cache ownership 与零拷贝接口。
  - Heterogeneous Memory、Persistent Memory、File-system Cache、Zero Copy、Virtual Memory

- [Kosmo: Efficient Online Miss Ratio Curve Generation for Eviction Policy Evaluation](https://www.usenix.org/conference/fast24/presentation/shakiba)
  - Kia Shakiba, Sari Sultan, and Michael Stumm, University of Toronto
  - Kosmo 在线生成 cache size→miss ratio curve，且同一次 access stream 可评估 LFU、FIFO、2Q、LRFU 等不满足 inclusion property 的 eviction policy。它用紧凑统计结构代替并行维护大量 miniature cache，在 1260 亿访问上平均少 3.6 倍、最高少 36 倍内存并更高吞吐。
  - 相较 Miniature Simulations 为每个容量/策略维护模拟 cache，核心创新是用可共享的在线状态直接推导多种非栈式策略 MRC，使 runtime tuning 可承受。
  - Cache Analysis、Miss Ratio Curve、Eviction Policy、Online Algorithm、Memory Efficiency

- [I/O Passthru: Upstreaming a flexible and efficient I/O Path in Linux](https://www.usenix.org/conference/fast24/presentation/joshi)
  - Kanchan Joshi, Anuj Gupta, Javier González, Ankit Kumar, Krishna Kanth Reddy, Arun George, and Simon Lund, Samsung Semiconductor; Jens Axboe, Meta Platforms Inc.
  - I/O Passthru 是已进入 mainline Linux 的新 NVMe path：NVMe character interface 暴露非传统 block command，io_uring command 以异步、低拷贝方式提交，因而 zoned/data-placement 等新接口可由 userspace 使用而无需每次改 block layer。FIO IOPS 比 io_uring block path 高 16–40%，并接入 Cachelib data placement。
  - 相较所有 NVMe innovation 都先翻译成 block I/O、等待内核专用 API，核心创新是通用 char+io_uring passthrough 窄腰，兼得扩展性与内核级异步执行。
  - Linux Storage、NVMe Passthrough、io_uring、Kernel Interface、Data Placement

- [Metis: File System Model Checking via Versatile Input and State Exploration](https://www.usenix.org/conference/fast24/presentation/liu-yifei)
  - Yifei Liu and Manish Adkar, Stony Brook University; Gerard Holzmann, Nimble Research; Geoff Kuenning, Harvey Mudd College; Pei Liu, Scott A. Smolka, Wei Su, and Erez Zadok, Stony Brook University
  - Metis 用 nondeterministic loop 选择 file-system syscall、argument 和 crash/state transition，权重可调以改变探索重点；抽象文件系统 state 去除无关细节、支持多节点近线性并行。每步将被测 FS 与专为快速 oracle/reproduction 写的 RefFS 对比，发现差异后保存最小可重放路径，共找出多系统 bug。
  - 相较 syscall fuzzing 只追代码覆盖、传统 model checking 状态表示过重，核心创新是把 input generation 与抽象 FS-state exploration 统一，并配一个可控 reference implementation 作语义 oracle。
  - File-system Testing、Model Checking、State Exploration、Differential Oracle、Bug Reproduction

- [RFUSE: Modernizing Userspace Filesystem Framework through Scalable Kernel-Userspace Communication](https://www.usenix.org/conference/fast24/presentation/cho)
  - Kyu-Jin Cho, Jaewon Choi, Hyungjoon Kwon, and Jin-Soo Kim, Seoul National University
  - RFUSE 保持现有 FUSE filesystem 完全不改，但重做 kernel↔userspace request channel：每 CPU core 独立 ring buffer，减少全局锁、context switch 和 request/data copy；请求在产生 core 附近入队并由 userspace worker 并行消费，使高核数、快 NVMe 下数据与 metadata throughput 接近 in-kernel FS。
  - 相较优化某个 userspace FS 实现，核心创新是替换 FUSE 公共通信底座，以 per-core shared ring 消除所有 FUSE workload 的结构性串行化。
  - Userspace File System、FUSE、Per-core Ring Buffer、Kernel-Userspace Communication、Scalability

- [The Design and Implementation of a Capacity-Variant Storage System](https://www.usenix.org/conference/fast24/presentation/jiao)
  - Ziyang Jiao and Xiangqun Zhang, Syracuse University; Hojin Shin and Jongmoo Choi, Dankook University; Bryan S. Kim, Syracuse University
  - CVSS 接受 SSD 随磨损逐步减少对外容量，以换取始终较低 write amplification 和稳定 latency。CV-SSD 按健康状态缩容，CV-FS 用可弹性 logical partition 的 log-structured layout 适配变化，user-level manager 根据设备状态协调数据/容量；避免固定容量 SSD 晚年 fail-slow，寿命延长 268–327%。
  - 相较把额定容量终身不变、靠更强 GC 硬撑，核心创新是将 capacity 变成可随寿命调整的系统契约，并让 SSD、FS、manager 三层协同。
  - Flash Storage、Capacity-Variant SSD、Fail-slow、Log-structured File System、Lifetime Management

- [I/O in a Flash: Evolution of ONTAP to Low-Latency SSDs](https://www.usenix.org/conference/fast24/presentation/curtis-maury)
  - Matthew Curtis-Maury, Ram Kesavan, Bharadwaj V R, Nikhil Mattankot, Vania Fang, Yash Trivedi, Kesari Mishra, and Qin Li, NetApp, Inc Deployed-Systems Paper
  - 该经验论文按时间梳理 NetApp ONTAP 从面向 HDD 到全闪存的 read path 演进，逐项定位原架构中为旋转盘合理、在 sub-ms SSD 上反而主导延迟的软件等待、排队和层间处理，并给出每次生产改造的性能证据与取舍。
  - 相较提出一套 clean-slate flash system，核心贡献是展示成熟企业存储如何分阶段移除 legacy software latency，并量化哪些改动真正让介质性能到达应用。
  - Enterprise Storage、All-flash Array、Read Path、Software Latency、ONTAP Experience

- [We Ain't Afraid of No File Fragmentation: Causes and Prevention of Its Performance Impact on Modern Flash SSDs](https://www.usenix.org/conference/fast24/presentation/jun)
  - Yuhun Jun, Sungkyunkwan University and Samsung Electronics Co., Ltd.; Shinhyun Park, Sungkyunkwan University; Jeong-Uk Kang, Samsung Electronics Co., Ltd.; Sang-Hoon Kim, Ajou University; Euiseong Seo, Sungkyunkwan University Awarded Best Paper!
  - 该工作跨 Linux I/O path、NVMe interface 与 SSD flash die 追踪文件碎片化，发现主要损失不是 host request split，而是相邻 logical block 的写入被其他写打断后随机落到同一 die，读取发生 die-level collision；overwrite 也会触发。新 NVMe hint+page-to-die allocator 强制连续块跨连续 die，无需 defrag。
  - 相较在文件系统合并 request 或事后碎片整理，核心创新是定位到 SSD 内物理并行度才是根因，并让 host 传递布局意图控制 flash placement。
  - Flash SSD、File Fragmentation、Die-level Collision、NVMe Extension、Physical Placement

- [In-Memory Key-Value Store Live Migration with NetMigrate](https://www.usenix.org/conference/fast24/presentation/zhu)
  - Zeying Zhu, University of Maryland; Yibo Zhao, Boston University; Zaoxing Liu, University of Maryland
  - NetMigrate 在 Redis shard 从 source 搬到 destination 时，由 programmable switch 逐 key/range 记录迁移进度并实时将 client query 导向持有最新值的 server；data copy 仍在后台进行，switch 避免请求经 source 转发或停服，迁移期 throughput 提高 6.5–416%。
  - 相较 stop-and-copy 或 source-side proxy/pulling data path，核心创新是让网络数据平面成为细粒度 migration directory，查询路由随复制进度即时变化。
  - Key-Value Store、Live Migration、Programmable Switch、Redis、Shard Routing

- [IONIA: High-Performance Replication for Modern Disk-based KV Stores](https://www.usenix.org/conference/fast24/presentation/xu)
  - Yi Xu, University of California, Berkeley; Henry Zhu, University of Illinois Urbana-Champaign; Prashant Pandey, University of Utah; Alex Conway, Cornell Tech and VMware Research; Rob Johnson, VMware Research; Aishwarya Ganesan and Ramnatthan Alagappan, University of Illinois Urbana-Champaign and VMware Research
  - IONIA 针对 SSD write-optimized KV 的接口/性能设计 replication：foreground write 一次 RTT 获得足够副本确认，耗时的本地结构更新可在后台并行；read 可从任意 replica 大多一次 RTT 返回，不要求所有 replica 同步完成 write，又不因部分慢副本降低写可用性。
  - 相较通用 consensus/primary-backup 按内存 KV 假设执行，核心创新是利用 SSD WO-KV 的 append/update 与后台 compaction 特性重新划分 durability、execution 和 read visibility。
  - Key-Value Replication、SSD、Write-optimized Store、One-RTT Write、Replica Read

- [Physical vs. Logical Indexing with IDEA: Inverted Deduplication-Aware Index](https://www.usenix.org/conference/fast24/presentation/levi)
  - Asaf Levi, Technion - Israel Institute of Technology; Philip Shilane, Dell Technologies; Sarai Sheinvald, Braude College of Engineering; Gala Yadgar, Technion - Israel Institute of Technology
  - IDEA 为已去重存储建立 term index 时，不按 logical file 重复索引相同 chunk。倒排层先将 term 映射到包含它的唯一 physical chunk，再用第二层把 chunk 映射到所有 logical file；查询时组合两层并支持 ranking/proximity，Lucene prototype 让 index size/creation time 最多降 73%/94%。
  - 相较 Elasticsearch/Lucene 对每个逻辑副本重复建 posting，核心创新是让索引结构与 dedup 的 physical/logical indirection 对齐，复用内容和索引两种重复。
  - Deduplicated Storage、Inverted Index、Physical Chunk、Lucene、Information Retrieval

- [MIDAS: Minimizing Write Amplification in Log-Structured Systems through Adaptive Group Number and Size Configuration](https://www.usenix.org/conference/fast24/presentation/oh)
  - Seonggyun Oh, Jeeyun Kim, and Soyoung Han, DGIST; Jaeho Kim, Gyeongsang National University; Sungjin Lee, DGIST; Sam H. Noh, Virginia Tech
  - MiDAS 为 log-structured SSD 把 block 按 age/update interval 自动分入链式 group，并用 UID 与 Markov analytical model 根据 workload 动态决定 group 数量和各组容量；另建大小可变的 HOT group 隔离高频更新，减少 GC 时搬运仍存活的冷块，WAF 低 25%、吞吐高 54%。
  - 相较固定 hot/cold class 或经验式多 stream，核心创新是用可解析模型同时调 group count、size 与 hot region，系统化最小化预期数据移动。
  - Log-structured Storage、Write Amplification、Garbage Collection、Markov Model、Hot/Cold Separation

- [What's the Story in EBS Glory: Evolutions and Lessons in Building Cloud Block Store](https://www.usenix.org/conference/fast24/presentation/zhang-weidong)
  - Weidong Zhang, Erci Xu, Qiuping Wang, Xiaolu Zhang, Yuesheng Gu, Zhenwei Lu, Tao Ouyang, Guanqun Dai, Wenwen Peng, Zhe Xu, Shuo Zhang, Dong Wu, Yilei Peng, Tianyun Wang, Haoran Zhang, Jiasheng Wang, Wenyuan Yan, Yuanyuan Dong, Wenhui Yao, Zhongjie Wu, Lingjun Zhu, Chao Shi, Yinhu Wang, Rong Liu, Junping Wu, Jiaji Zhu, and Jiesheng Wu, Alibaba Group Awarded Best Paper! Deployed-Systems Paper
  - 该论文复盘 Alibaba Cloud EBS 十年三代架构：EBS1 优先简单性，EBS2 转向性能/空间效率，EBS3 重点压低 network traffic amplification；并用生产数据解释如何同时提供 latency/throughput/IOPS/capacity elasticity、缩小多级故障 blast radius，以及硬件 offload 何时值得采用。
  - 相较只报告当前架构峰值，核心贡献是把三代取舍、失败方案和需求变化放在同一演进链中，给出云块存储规模化的因果经验。
  - Cloud Block Storage、Architecture Evolution、Elasticity、Failure Blast Radius、Hardware Offload

- [ELECT: Enabling Erasure Coding Tiering for LSM-tree-based Storage](https://www.usenix.org/conference/fast24/presentation/ren)
  - Yanjing Ren and Yuanming Ren, The Chinese University of Hong Kong; Xiaolu Li and Yuchong Hu, Huazhong University of Science and Technology; Jingwei Li, University of Electronic Science and Technology of China; Patrick P. C. Lee, The Chinese University of Hong Kong
  - ELECT 在 Cassandra/LSM hot tier 内同时使用 replication 与 erasure coding：依据 SSTable/key hotness 将仍常读的数据从多副本逐步转 EC，冷却后再 offload 到 cold tier；用户一个参数控制省容量与访问/重建开销，保持 availability 的同时降低 hot-tier redundancy。
  - 相较 hot tier 全 replication 成本高、直接 EC 又让每次热读解码，核心创新是让 redundancy scheme 与 LSM layout/hotness 生命周期共同变化。
  - Distributed KV、Erasure Coding、LSM-tree、Hot/Cold Tiering、Cassandra

- [MinFlow: High-performance and Cost-efficient Data Passing for I/O-intensive Stateful Serverless Analytics](https://www.usenix.org/conference/fast24/presentation/li)
  - Tao Li, Yongkun Li, and Wenzhe Zhu, University of Science and Technology of China; Yinlong Xu, Anhui Province Key Laboratory of High Performance Computing, University of Science and Technology of China; John C. S. Lui, The Chinese University of Hong Kong
  - MinFlow 为 serverless analytics shuffle 联合选择数据传递 topology 与 function placement。它快速生成减少 object-store PUT/GET 的多级 topology，再把 DAG 交错切成小 bipartite subgraph，使 producer/consumer function 尽量同处、超过一半数据不落 remote storage；cost model 在实际 FaaS 限制下选并行度/配置。
  - 相较只优化 shuffle storage、网络或 function scheduling 的单点方案，核心创新是以 data-passing DAG 为共同表示，联合改变拓扑、partition 与部署。
  - Serverless Analytics、Shuffle、Data-passing Topology、Function Scheduling、Object Storage Cost

- [COLE: A Column-based Learned Storage for Blockchain Systems](https://www.usenix.org/conference/fast24/presentation/zhang-ce)
  - Ce Zhang and Cheng Xu, Hong Kong Baptist University; Haibo Hu, Hong Kong Polytechnic University; Jianliang Xu, Hong Kong Baptist University
  - COLE 为 Ethereum 历史 state/provenance query 不再持久化庞大的 Merkle Patricia Trie node。它按 state key 将历次 value 连续列式存放，用 learned model 定位时间/值区间，并以 write-optimized disk layout 合并更新；在保留 provenance 查询的同时 index/storage 少最高 94%、吞吐高 1.4–5.4 倍。
  - 相较把通用 learned index 直接替 MPT 仍需持久化大 model node，核心创新是先把区块链多版本状态重排为可学习的列式序列，再设计盘上更新路径。
  - Blockchain Storage、Learned Index、Columnar Layout、Provenance Query、Write Optimization

- [Baleen: ML Admission & Prefetching for Flash Caches](https://www.usenix.org/conference/fast24/presentation/wong)
  - Daniel Lin-Kit Wong, Carnegie Mellon University; Hao Wu, Meta; Carson Molder, UT Austin; Sathya Gunasekar, Jimmy Lu, Snehal Khandkar, and Abhinav Sharma, Meta; Daniel S. Berger, Microsoft and University of Washington; Nathan Beckmann and Gregory R. Ganger, Carnegie Mellon University
  - Baleen 为 Meta bulk-storage 前的 flash cache 联合学习 admission 与 prefetch。episode model 将一个 object 从首次访问到 residency 结束的整段复用行为作为训练样本；目标不是 miss ratio，而是后端 HDD seek/service 时间 Disk-head Time，并受 flash 长期写入率/寿命约束，固定写率下 peak load 再降 12%。
  - 相较分别训练 admission/prefetch、以 byte/IO miss 当代理目标，核心创新是 episode-level 协同决策并直接优化决定后端服务器数的物理负载指标。
  - ML for Storage、Flash Cache、Admission、Prefetching、Disk-head Time

- [Seraph: Towards Scalable and Efficient Fully-external Graph Computation via On-demand Processing](https://www.usenix.org/conference/fast24/presentation/yang-tsun-yu)
  - Tsun-Yu Yang, Yizou Chen, Yuhong Liang, and Ming-Chang Yang, The Chinese University of Hong Kong
  - Seraph 在单机 constant-memory 处理 billion-scale graph 时，不再为顺序带宽整段扫描大量无关 edge。它按算法当前 active vertex on-demand 随机取必要数据；hybrid graph format 平衡定位与 locality，vertex passing 高效传播更新，selective precomputation 复用已加载数据，现代 SSD 上比既有 fully-external 系统快最高两个数量级。
  - 相较默认 sequential I/O 永远优于 random I/O 的外存图系统，核心创新是利用现代存储随机/顺序差距缩小，转而最小化总读取量并补齐 locality。
  - External Graph Processing、On-demand I/O、Hybrid Graph Format、SSD、Billion-scale Graph
