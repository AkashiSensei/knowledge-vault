# 训练与显存

## I. 训练流程与显存组成

### 训练和推理有什么区别？

训练通过前向计算、损失计算、反向传播和优化器更新来学习参数；常规推理使用已有参数执行前向计算，不计算参数梯度、不更新参数。因此训练还需要保存反向所需的激活、参数梯度和优化器状态。自回归大模型推理会反复生成 token，并可能维护 KV Cache，不能理解为只执行一次前向或只存储权重。[参考：PyTorch 训练教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)。

### 训练显存主要被哪些数据占用？为什么权重放得下，不代表就能训练？

主要包括模型权重、参数梯度、优化器状态、为反向保存的激活，以及算子临时工作空间、通信缓冲区和运行开销。权重只是其中一部分，能否训练要看实际执行中的显存峰值，不能只按权重文件大小判断；临时空间和通信缓冲区也不一定很小。具体定义和带精度假设的计算示例见 [[knowledge/ai-infra/training#I. Training State and Memory|训练状态与显存]]。

## II. 反向传播与数据生命周期

### 反向传播为什么需要前向的激活？

因为计算梯度需要用到前向时的输入或中间结果。例如标量计算 `y = w * x`，收到输出梯度 `g_y = ∂L/∂y` 后，权重梯度为 `g_w = g_y * x`，必须拿到当时的 `x`；在多层网络里，`x` 往往是上一层的激活。框架保存的是反向计算所需的张量，并非所有中间结果。[参考：PyTorch 自动求导](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)。

### 已经有梯度了，为什么还需要保留激活？

要区分“损失对当前层输出的梯度”和“损失对当前层参数的梯度”。收到输出梯度不代表参数梯度已经算完；例如 `y = w * x` 仍需用保存的 `x` 计算 `g_w = g_y * x`。所有依赖该激活的反向计算结束后，通常就可以释放它，不必为了本次反向继续保留。[参考：PyTorch 自动求导机制](https://docs.pytorch.org/docs/stable/notes/autograd.html)。

### 梯度是怎样逐层向前计算的？

从损失开始，按链式法则沿计算图反向传播。每层收到输出梯度，结合本层运算的导数，计算参数梯度，并把输入梯度传给前一层。例如 `y = w * x`，有 `g_w = g_y * x`、`g_x = g_y * w`；需要的前向数据可能是激活、权重或其他保存的张量。分支汇合时，还要累加不同路径的梯度贡献。[参考：PyTorch 自动求导](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)。

### 算完的激活和梯度可以丢掉吗？为什么显存仍然可能不够？

可以，但要区分数据用途：前向保存的激活在所有相关反向计算完成后通常可释放；中间激活的梯度用完通常也不长期保留；参数梯度通常留给优化器更新，梯度累积时还要继续保留和累加。前向结束时许多待反向使用的激活仍同时存在，反向中剩余激活、已产生的参数梯度和临时空间也会重叠，因此应关注峰值。这里说的是普通一阶反向；显式保留计算图或其他引用可能延长生命周期，框架的缓存分配器也可能继续保留已释放张量对应的显存以便复用。[参考：PyTorch 自动求导机制](https://docs.pytorch.org/docs/stable/notes/autograd.html)。梯度累积见 [[knowledge/ai-infra/training#4. Gradient Accumulation|已有笔记]]。

## III. 梯度累积

### 什么是梯度累积？它如何在显存有限时实现更大的有效 batch size？

把一次参数更新对应的 batch 拆成多个 microbatch，每个都执行前向和反向，将参数梯度累加到同一组梯度缓冲区；期间保持参数不变、不清空梯度，达到累积步数后再做一次优化器更新并清理梯度。例如单卡每次处理 8 个样本，累积 4 次，对应一次更新使用 32 个样本；等大小 microbatch 的同步数据并行下，有效全局 batch 为“每卡 microbatch 大小 × 累积步数 × DP 副本数”。每个 microbatch 反向后可释放不再需要的激活，因此降低相对于一次处理整个 batch 的激活峰值，但不会直接减少权重和优化器状态。

易错点：推迟的是优化器更新，不是反向传播；只运行前向不会产生训练所需的参数梯度。等大小 microbatch、各自 loss 取均值时，通常将 loss 除以累积步数，使累加梯度对应整个 batch 的平均梯度；样本数或有效 token 数不等时需按实际目标加权。梯度累积与直接大 batch 的等价还取决于损失、随机性和跨样本运算，不能无条件认定完全一致。详见 [[knowledge/ai-infra/training#4. Gradient Accumulation|梯度累积原理与条件]]。

### 梯度累积期间累积的是哪些梯度，什么时候更新参数？

累积的是本次参与训练并产生梯度的参数的梯度；冻结参数不在其中。每个 microbatch 使用相同的参数执行前向和反向，把梯度加到已有缓冲区；累积窗口内不更新参数，结束后通常做一次优化器更新。Adam 的一阶、二阶矩等优化器状态也通常在这次更新时推进，而不是每个 microbatch 更新一次。详见 [[knowledge/ai-infra/training#4. Gradient Accumulation|梯度累积]]。

### 梯度累积主要是为了省显存，还是减少优化器更新成本？

主要用于在显存有限时保持目标有效 batch：分批前向和反向，使激活不必覆盖整个 batch 同时保留。与相同有效 batch 的直接大 batch 训练相比，两者都只更新一次参数，梯度累积没有额外减少更新次数。若与每个小 batch 都更新相比，虽然优化器调用更少，但有效 batch 和更新轨迹也变了，不能当作无条件等价的加速。Adam 更新要读写权重、梯度和矩估计，成本取决于参数量、精度、融合实现和硬件，可能受显存带宽限制；梯度累积也可能因小矩阵效率和更多调度开销而更慢，多卡时是否减少梯度通信还取决于同步策略。[参考：PyTorch Adam](https://docs.pytorch.org/docs/stable/generated/torch.optim.Adam.html)、[性能调优指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html)。

### 为什么使用较大的有效 batch？它一定更好吗？

较大的有效 batch 让一次更新汇总更多样本的梯度；在样本近似独立等条件下，平均梯度的方差通常更小，受单个样本影响更少。这是有效 batch 增大的统计收益，不代表必然更快收敛或更好泛化。[参考：梯度噪声尺度研究](https://arxiv.org/abs/1812.06162)。

要区分有效 batch 与实际同时计算的 microbatch：只增加梯度累积步数不会直接提高同时计算的并行度。多卡数据并行的吞吐收益来自硬件并行和足够的每卡工作量，不是有效 batch 这个数值变大的直接结果；固定每卡 microbatch 和累积步数时，增加 DP 副本数会使全局有效 batch 随之增大，这是配置上的伴随变化。梯度累积则用于在显存有限时实现选定的有效 batch，并非保证比直接小 batch 更快。[参考：大 batch 与分布式训练实践](https://arxiv.org/abs/1706.02677)。

batch 并非越大越好：同样处理一遍数据时，batch 越大，参数更新次数越少；超过一定规模后，梯度降噪的边际收益下降，可能降低样本效率或影响泛化，还要匹配学习率和 warmup。优化目标是以合理资源成本更快达到目标效果，而不是单纯追求 batch 最大。[参考：大 batch 的收益边界与梯度噪声尺度](https://arxiv.org/abs/1812.06162)。

## IV. 激活重计算

### 什么是激活重计算？它如何节省显存，代价是什么？

激活重计算（Activation Checkpointing）是在前向时只保留选定的边界张量，不长期保存某些计算段内部反向所需的激活；反向进入该段时，从保存的边界输入重新执行必要的前向计算，恢复激活后再计算梯度。例如 `x → A → B → C → y`，可保存某段的输入，反向需要 A、B 的中间结果时再重算。它降低保存激活的显存占用，代价是额外前向计算，通常会增加单步耗时；不直接减少参数、参数梯度和优化器状态。这里的 checkpoint 是计算边界，不是保存到磁盘的模型检查点；包含 dropout 等随机运算时还需保证重算行为一致。[参考：PyTorch Activation Checkpointing](https://docs.pytorch.org/docs/stable/checkpoint.html)。

### 很深的网络可以在中间保存几个激活检查点吗？

可以。把网络划分为若干段，保存段边界的激活，省去部分内部激活的长期保存。例如 12 层网络保存输入 a0、第 4 层输出 a4、第 8 层输出 a8；反向处理第 9～12 层时从 a8 重算该段，接着从 a4 重算第 5～8 层，最后从 a0 重算第 1～4 层。每段只恢复所需数据，不必每次从网络开头重算。检查点更多会增加边界激活的保存量，但不能只凭检查点数量断定重算次数更少；段太大则重算阶段的临时激活峰值也可能较高。划分应权衡边界保存量、段内重算峰值与重算开销，结合实际激活大小和执行策略，而不只是层数均分。[参考：PyTorch Activation Checkpointing](https://docs.pytorch.org/docs/stable/checkpoint.html)。

## V. 数值精度

### FP16 和 BF16 都占 16 位，有什么区别？为什么大模型训练经常使用 BF16？

二者都占 2 字节，但位分配不同：FP16 是 1 位符号、5 位指数、10 位小数；BF16 是 1 位符号、8 位指数、7 位小数。指数决定数值范围，小数位影响有效精度，因此 BF16 的指数范围与 FP32 相当，更不易因 FP16 的范围限制而上溢或下溢，但同一量级的表示比 FP16 更粗糙。支持 BF16 的硬件上，训练常用它兼顾低存储成本与较宽数值范围，通常无需 FP16 常见的梯度 loss scaling；它不是比 FP16 更精确，也不保证完全避免数值问题。实际混合精度训练仍会按实现对部分运算、累加或更新状态使用 FP32，不能认为全部训练状态都变成 16 位。[参考：BF16 研究](https://arxiv.org/abs/1905.12322)、[NVIDIA 混合精度指南](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)、[PyTorch AMP](https://docs.pytorch.org/docs/stable/amp.html)。

### 大模型需要更宽的表示范围，还是希望保留接近 FP32 的数值范围？

这里的“更宽”主要是相对 FP16 而言，不是需要超过 FP32；BF16 保留与 FP32 相同的指数位数，让低精度训练更容易沿用 FP32 的数值尺度。也不意味着每个张量都会用满这个范围，而是减少因范围收窄引入的问题，尤其是模型原本按 FP32/BF16 训练时。问题不限于转换已有权重：前向激活、反向梯度和运算中间值的尺度会变化，也可能遇到上溢或下溢。FP16 仍可配合适当的数值处理训练，不能说大模型必然要求 BF16。

要区分范围和精度：范围不足时，大数可能上溢为 Inf，过小的数可能下溢或舍入为零，并不一定被自动裁剪到边界；即使数值在可表示范围内，FP32 转成 BF16/FP16 也会因有效位数减少而舍入。BF16 主要缓解前一种范围问题，仍存在精度损失，因此部分累加、敏感运算或更新状态仍可能使用 FP32。[参考：NVIDIA 混合精度指南](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)、[BF16 范围与转换说明](https://docs.cloud.google.com/tpu/docs/bfloat16)、[PyTorch AMP](https://docs.pytorch.org/docs/stable/amp.html)。

### 上溢和下溢就是精度转换时超出表示范围吗？

基本如此，但不只发生在精度转换时，算术运算的结果也可能遇到。上溢指绝对值超过最大有限值，按常见浮点处理可能变成正负 Inf；下溢涉及非零结果太接近零，进入次正规数范围时相对精度可能降低，过小时会舍入为零。“太小”指绝对值太小，不是负得太多；范围内因有效位数有限而产生的普通舍入误差，也不等于上溢或下溢。[参考：NVIDIA 混合精度格式说明](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)。
